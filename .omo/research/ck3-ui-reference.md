# CK3 UI 문법과 전술 RPG의 결합: 잔선: 서울 POC 결정안

- 조사일: 2026-09-06 / 작업: st_01a07596
- 대상: 붕괴 이후 서울 지하철, 영등포·신도림·구로 3역, 탐사자·의무관·순찰자 3인, 격자 전투.
- 산출물 범위: 이 보고서와 `sources.json` 추가 항목만 작성. 게임 코드·기존 `REPORT.md` 수정, 게임 실행, 커밋 없음.
- 근거 구분: **확인**은 조회한 원문/공개 스크린샷의 사실, **원리**는 그 사실의 설계 해석, **POC 결정**은 적용 제안이다. 현재 구현 여부는 검사하지 않았다. 기존 보고서의 미제공 항목도 코드에서 부재가 확인된 것으로 취급하지 않는다.
- 버전: 화면 배치는 2020년 PC 출시 리뷰 이미지 기준. 현재 Paradox 호스팅 위키의 규칙과 출시 전 개발일지는 별도 표시한다. 콘솔판·모든 DLC·2026년 최신 화면이 동일하다는 주장이 아니다.

## 1. 결론과 선행 정정

**CK3에서 가져올 것은 ‘사람이 선택의 주체이고, 선택의 이유와 손실을 같은 자리에서 읽는다’는 원리다. 격자 위 명령은 FE/FFT, 인물과 대화의 연결은 파랜드/창세기전, 선택의 인과 설명은 CK3로 나눈다.** CK3의 지도·정치·계승 시스템을 축소 복제하는 방향은 권하지 않는다.

POC 첫 구현은 **3인 상시 식별 → 목적지와 조우 상대 파악 → 비용·효과 비교 → 수동 전술 명령 → 인물별 결과 확인**의 한 바퀴다. 아트 완성을 기다리지 않고 이름·역할·초상 대체표식으로 시작한다.

### 의뢰의 표현을 그대로 원작 사실로 쓰면 안 되는 세 가지

1. **‘인물 중심 상단 바에 초상·특성·스트레스·건강·명예·신앙·금이 전부 상시 표시’는 정확한 CK3 배치 설명이 아니다.** 확인한 기본 지도 화면은 플레이어 초상과 스트레스가 좌하단, 금·명예·신앙 등 자원은 상단, 상세 특성·기량·건강 표식은 인물창에 분산된다. 다른 인물을 조회할 때 그 인물의 자원과 플레이어 자원도 서로 다르다. 가져올 것은 상단 위치가 아니라 **화면을 바꿔도 잃지 않는 주체·핵심 상태의 기준점**이다.[S31-I1][S31-I2]
2. **‘이벤트마다 2–4개 선택, 모든 비용·효과·확률 공개’도 보편 규칙이 아니다.** 위키는 옵션 수에 고정 제한을 두지 않고, `hidden_effect`로 효과 설명을 숨길 수 있다고 명시한다. 실제 리뷰 이미지에는 확인 선택 하나뿐인 결과 이벤트도 있다. `ai_chance`는 AI의 옵션 선택 가중치이지 플레이어 행동 성공률이 아니다. **세 조우 카드를 비교 가능하게 만들고, 알려진 즉시 비용·결과를 확정 전에 공개**하는 것은 POC의 더 엄격한 정책으로 채택한다.[S25 §Options][S31-I3]
3. **공식 CK3 PDF 플레이 매뉴얼은 이번 조회에서 확보하지 못했다.** Steam의 `/manual/1158310`은 상점 홈으로 이동했고 검색은 유효한 공식 PDF를 제공하지 않았다. Paradox 호스팅의 커뮤니티 편집 위키는 공식 저술 매뉴얼로 격상하지 않는다. CK3의 조작 안내 근거는 위키 입문 가이드·개발일지 공식 공지·출시 리뷰로 보완하고, 격자 조작의 매뉴얼 근거는 기존 보고서가 검증한 Nintendo FE 전자 매뉴얼과 SQUARE FFT 매뉴얼을 사용한다.[S19][S22][S01][S02]

## 2. 일곱 화면/패턴의 원리와 적용

### 2.1 인물 중심 전역 HUD: ‘내가 누구이며 무엇을 잃을 수 있는가’

**확인.** 출시 화면은 좌하단 플레이어 초상, 그 옆의 가느다란 스트레스 표시, 상단 자원 및 현안 표시로 주체와 세계 상태를 계속 참조하게 한다. 인물창에는 특성 아이콘, 능력, 건강 표식, 가족 등의 상세가 있다. RPS 리뷰어는 스트레스를 한동안 찾지 못했다가 본문을 정정했다. 존재하는 지표도 시선에 들어오지 않으면 실질적으로 숨겨진 정보다.[S31][S31-I1][S31-I2] CK3의 건강은 사망 위험과 관련된 속성이지 전술 전투 HP가 아니다.[S21 §Health]

**원리.** 지속되는 얼굴은 사건과 자원 손실을 ‘내 사람에게 일어나는 일’로 묶는다. 값이 항상 같은 위치에 있으면 기억으로 화면 간 값을 비교하지 않아도 된다. 반대로 작은 의미 불명의 아이콘을 계속 노출하는 것만으로는 충분하지 않다.

**POC 결정 — P0.** 전역 헤더에는 현재 역·임무·실제 원정 자원, 파티 스트립에는 **탐사자/의무관/순찰자 각각의 이름·역할·HP·현재 상태**를 둔다. 선택 인물은 지속 테두리와 이름으로 표시한다. 전투에서는 선택자 AP를 가까이 두고 전원 HP 요약은 유지한다. 피로/스트레스가 실제 상태로 존재하면 이름·수치/단계·위험 임계값을 함께 표시한다. 없다면 장식 게이지를 만들지 않는다. 초상 클릭/키보드 포커스로 동일 인물 상세를 연다.

**복제 금지.** 명예→평판, 신앙→사기 같은 자동 치환; 신앙·왕조 명성 등 불필요한 자원 추가; 건강을 HP처럼 설명하기; 모든 능력/특성을 상단 한 줄에 밀어 넣기; 3인 파티를 군주 한 명의 시점으로 축소하기. 3D 유전·노화 초상은 P2 이후에도 필수가 아니다.[S30]

### 2.2 인물창: ‘프로필’이 아니라 다음 행동의 이유

**확인.** 조회한 인물창은 큰 초상과 이름·나이·성격 요약, 특성 아이콘, 기량, 소속/작위, 배우자·후계자, 가족/관계/궁정/봉신 탭을 묶는다. 인물별 관계 수치가 함께 보인다.[S31-I1] 위키는 상대에 대한 의견이 행동과 특정 상호작용 성공에 영향을 주며, 외교·전투·관리·계책·학습 및 개인 무용을 구분한다고 설명한다.[S20][S21] 특성 이름은 툴팁 연결을 지원하고 대상 인물에 따라 조건부 설명을 낼 수 있다.[S26] 비밀과 구실은 다른 인물에게 영향력을 행사하는 체계다.[S28][S30]

**원리.** ‘누구인가 → 무엇을 잘하는가 → 누구와 어떤 사이인가 → 무엇을 할 수 있는가’가 한 인물에 결속된다. 의견은 방향이 있는 값이므로 두 사람의 호감이 같다고 가정하지 않는다. 성격은 설명문에 그치지 않고 선택의 부담과 연결될 때 역할극이 된다. IGN은 성격에 어긋나는 선택의 스트레스 비용이 이 역할을 한다고 평가한다.[S30]

**POC 결정 — P0 최소, P1 상세.**
- P0: 파티 목록에서 인물 선택 → 이름·역할·HP/AP·장비 요약·현재 부상 확인. 탐사자/의무관/순찰자를 어디에서 선택해도 동일한 사람을 조회한다.
- P1: `능력·장비 / 관계·기록` 정도로 구획. 특성에는 짧은 성격 설명과 **실제 효과**를 분리해 적는다. 관계는 `의무관 → 탐사자: 신뢰`처럼 주체/대상·최근 변화 원인을 명시한다. 최근 원인 기록이 없다면 원인을 창작하지 않는다.
- 비밀은 `알아낸 정보`가 실제 존재할 때만 노출한다. 인물 페이지는 관련 사건/정보로 가는 입구, 정보 목록은 원문·확인 여부·사용 가능한 행동을 보여주는 공간으로 구별한다. CK3의 모든 비밀이 공개 인물창에 나열된다는 뜻이 아니다.

**복제 금지.** 거대 가계도·왕조/봉신 탭·결혼 후보 검색·수십 기량·전 인물 비밀 노출. 공개된 정보가 없는 것과 비밀 자체가 없는 것을 혼동하지 않는다. POC 역할 명칭만으로 숨겨진 성공 보너스를 발명하지 않는다.

### 2.3 이벤트 팝업: 이야기와 실행 계약을 분리하되 함께 제시

**확인.** 출시 이미지에는 사건 제목·상황 글·큰 관련 인물·하단 선택이 함께 있고, 선택 툴팁이 `Will Happen`과 `Has Happened`를 구분한다. 해당 결과 이벤트는 이미 발생한 죽음과 음모 종료를 설명하고 다음 선택에는 즉시 효과가 없다고 알린다.[S31-I3] 이벤트 정의는 좌/우 및 보조 초상, 이름 붙은 옵션, 조건부 옵션, 비활성 옵션 노출, 숨긴 효과를 지원한다.[S25] PC Gamer는 짧은 사건 글이 인물의 생애와 연결되는 점을 긍정 평가한다.[S29] 개발일지 #10 공식 공지는 수치 보너스뿐 아니라 생활방식이 인물 이야기에서 무엇을 뜻하는지 묻는다.[S32]

**원리.** 초상은 결과를 떠안을 사람을 고정하고, 본문은 상황의 의미를, 효과 설명은 실행 계약을 맡는다. 선택 전에 비교할 수 있어야 불이익이 납득 가능한 대가가 된다. 미래 효과와 이미 적용된 결과를 구별해야 확인 버튼이 또 자원을 소모한다고 오해하지 않는다.

**POC 결정 — P0.** 장소·상대 이름/세력·태도·우리 목표 → 우리 대표/상대 식별 → 핵심 대사 → **교섭/우회/전투 3카드**. 각 카드는 아래 구조를 공유한다.

| 필드 | 표시 규칙 |
|---|---|
| 실행 주체와 대상 | ‘탐사자가 누구와 교섭하는가’, ‘누구를 치료하는가’를 명시. 고정 담당이면 선택기처럼 꾸미지 않는다. |
| 확정 비용 | 실제 자원명·소모량·현재 보유·확정 후 잔량. 무료이면 ‘소모 없음’. |
| 조건/실행 가능 여부 | 필요한 역할·물품·위치 등 실제 조건. 불가이면 부족 수량/조건을 카드에서 읽는다. |
| 알려진 즉시 결과 | 관계·부상·위치·전투 진입의 실제 결과. 확정과 확률 분기를 다른 구획으로. |
| 확률/위험 | 실제 확률을 공개하는 규칙일 때만 성공률과 성공/실패 결과를 병기. 확정 규칙은 ‘확정’, 미상은 ‘미확인’. 임의의 70%를 넣지 않는다. |
| ‘왜?’ | 현재 계산에 쓰인 역할·특성·장비·상태의 기여분만 펼쳐 본다. 설명용 임의 공식 금지. |

선택/호버는 미리보기, 명시적인 `교섭 확정` 등에서만 한 번 커밋한다. 긴 비용/위험 설명을 읽기 위해 카드를 확정해야 해서는 안 된다. 호버와 키보드 포커스/상세 열기가 같은 정보를 제공한다.

**복제 금지.** 매 조우에 4선택 강제, CK3식 긴 사건 연쇄, 중요한 즉시 비용을 `숨은 결과`로 감추기, 모든 장기 서사를 스포일러로 공개하기, 이벤트 선택 확률과 전투 명중률 또는 AI 선택 가중치를 혼동하기. 결과 확인 팝업과 아직 결정하지 않은 조우를 동일한 버튼 문구로 처리하지 않는다.

### 2.4 지도: 장식 배경이 아니라 대상을 고르는 판단 표면

**확인.** 출시 이미지에서 지도 호버는 영역/통치자/영지를 설명하고, 지도 모드에는 `Political Map · Selecting: Realms` 또는 `Details Map · Selecting: Holdings`처럼 현재 선택 단위가 표시된다.[S31-I1][S31-I2] 개발일지 #25 공식 공지는 지도 기능·지도 모드와 지도 상호작용을 다룬다고 명시한다.[S23] IGN은 줌에 따라 양피지에서 상세 지형으로 이어지는 표현과 별도 지도 모드를 설명하며, 지형을 읽기 쉬워 이동 판단이 빨라진다고 평가한다.[S30]

**원리.** 위치·대상·정보가 같은 표면에 있으면 목록의 지명과 지도의 위치를 머릿속에서 다시 연결할 필요가 없다. 지도 모드는 다른 세계로 이동하는 기능이 아니라 **같은 장소에 대해 다른 질문을 하는 필터**다. 선택 대상의 단위를 알려 주어야 클릭 결과를 예측할 수 있다.

**POC 결정 — P0 기본, P1 정보 필터.** 3역을 실제 원정 연결 규칙으로 그린다. 현재 파티 위치, 호버/포커스 역, 선택 목적지, 갈 수 없는 역을 구별한다. 선택 패널에 역 이름·알려진 인물/사건·이동 비용·위험·주 행동 `신도림으로 이동`을 묶는다. 호버/클릭은 정보를 고를 뿐 즉시 이동하지 않는다. P1에 필요할 때만 `경로 / 위험·사건` 정보 필터를 추가하고 같은 역의 선택과 범례를 유지한다.

**복제 금지.** 3역을 위해 중세식 줌 계층·백작령/남작령·수십 지도 모드 만들기; 세금/개발도/건물 투자/봉신 수입을 원정 지도에 이식하기. **전장 격자는 별도 판단 단위**다. 전투의 이동 가능 칸·적 위협·고저차/엄폐는 FE/FFT/Triangle의 전투 문법으로 표현한다.[S01][S02][S07]

### 2.5 자문회·궁정·계책: 사람 목록을 행동 가능한 업무 목록으로

**확인.** 위키 입문 가이드는 자문회에서 인물의 과업을 지정하고, 후보 목록을 기량 등으로 정렬/필터링하는 조작을 설명한다.[S19] 자문회 위키는 담당 기량에 따른 과업 효과와 임명 불가 조건을 구분한다.[S27] 계책은 대상·요구조건·성공 효과·발각 관련 변수를 갖는다.[S28] #6 및 #5 공식 공지는 각각 자문회/배우자와 비밀/구실의 설계 주제를 확인해 준다.[S24][S33] 다만 **모든 불가 사유가 원작의 모든 화면에서 완벽하게 설명된다는 보장은 없다.** RPS는 결혼 불가 원인이 명확하지 않아 헤맸던 사례를 지적한다.[S31]

**원리.** 목록의 목적은 인원 수를 세는 것이 아니라 ‘이 일을 누구에게 맡길 수 있는가’를 비교하는 것이다. 후보·담당 역할·현재 상태·기대 효과·제약이 붙으면 기억에 의존한 메뉴 왕복을 줄인다. 불가 이유는 오류 메시지가 아니라 **다음에 충족할 수 있는 조건**이다.

**POC 결정 — P0 불가 설명, P1 업무 상세.** 자문회/궁정/계책 3개 메뉴 대신 준비 화면의 **파티 3행 + 현재 조우의 행동 목록**으로 축소한다. 행에는 이름/역할·상태·현재 장비·실행 가능한 행동을 둔다. 실제 치료 기능이 있고 약품이 부족하다면 `치료 불가: 약품 필요 N / 보유 M`을 표시하고 장비/물품 화면으로 연결한다. 담당 변경/정찰/정보 활용은 현재 규칙에 있을 때만 실행 가능 UI를 제공한다. 진행도가 없는 기능에 작업 진행 막대를 만들지 않는다.

**복제 금지.** 가짜 자문회 직책, 월 단위 파견, 거대한 궁정, 이중 스파이 운영, 비밀 발각과 성공의 두 확률을 단순 POC에 신규 도입. 비활성 버튼에서 포인터 이벤트를 차단해 이유까지 볼 수 없게 만드는 구현도 금지한다.

### 2.6 중첩 툴팁과 ‘왜?’: 숨은 계산으로 들어가는 국소적 설명

**확인.** PC Gamer는 ‘툴팁 안에도 툴팁’이 있고 튜토리얼 메뉴에 계속 접근할 수 있어 복잡한 시스템의 연결을 이해하기 쉬워졌다고 평가한다.[S29] #16 공식 공지는 인터페이스를 명확하게 하고 관련 정보를 보여 주는 것을 설계 목표로 든다.[S22] 위키는 인물/특성/작위 이름을 대상에 맞는 툴팁과 연결하는 방식을 설명한다.[S26] 단, RPS의 계승 사례는 여러 설명이 있어도 최종 인과가 사실상 숨겨질 수 있음을 보여 준다.[S31]

**원리.** 요약을 먼저 제공하고 궁금한 용어/계산에만 세부를 여는 **점진적 공개**다. 원래 판단 대상을 잃지 않은 채 설명→설명의 근거로 내려갈 수 있어야 한다. 모든 정보를 작은 글자로 한 번에 보여 주는 방식과 반대다. 단순 용어 사전으로는 ‘왜 지금 이 값인가’를 설명하지 못한다.

**POC 결정 — P0 직접 이유, P1 고정 가능한 2단계 상세, P2 전역 용어집.**
1. 표면: 비용/예상 결과/불가 사유는 툴팁 없이 읽힌다.
2. 첫 상세: 정의 한 줄 + 현재 계산에 참여한 기초값/보정값/최종값. 가산·곱셈·상한·반올림은 실제 계산 순서대로 표시한다. 수치가 아니라 조건 판정이면 충족/미충족 조건으로 설명한다.
3. 두 번째 상세: `부상`, `엄폐` 등 원인 용어의 실제 효과/지속 조건. 첫 상세를 클릭/키보드로 고정하고 안의 링크에 포커스를 옮길 수 있다. Esc로 한 층씩 닫고 원래 선택으로 돌아온다. 이 2단계 제한과 입력 방식은 POC 제안이며 CK3의 정확한 기본 잠금 키나 시간 설정을 실증한 것은 아니다.

**수용 핵심.** 설명을 여는 동작은 비용·턴·RNG를 소비하지 않는다. 계산식의 최종값이 미리보기와 같고 확정 시 동일한 상태/조건이면 실제 효과도 일치한다. 미리보기 이후 상태가 바뀌었다면 바뀐 조건을 갱신해 다시 확정하게 한다. 숨은 정보를 공개하지 않으면서도 알려진 정보로 무엇을 계산했는지 설명한다.

**복제 금지.** 무한 툴팁 탑, 필수 비용을 3번째 팝업에 숨기기, 호버 타이머만으로 조작 가능하게 만들기, 계산 원인을 기록하지 않았는데 그럴듯한 사유를 생성하기. 작은 POC는 우선 고정 상세 패널 하나로도 원리를 충족할 수 있다.

### 2.7 경고/현안 바: 기록과 ‘지금 처리할 일’을 분리

**확인.** 입문 가이드는 상단 다이아몬드 경고와 덜 중요한 항목을 숫자 있는 묶음으로 구분한다.[S19 §Before unpausing] 출시 이미지에서도 개별 아이콘·현안 개수·별도 우측 메시지 목록이 보인다.[S31-I1] 그러나 RPS는 사소한 알림 배너가 조작 중인 창을 가리고 닫기 어렵다는 점을 비판한다.[S31]

**원리.** 플레이어가 모든 화면을 순회하며 상태 변화를 감시하지 않아도 되게 한다. 중요한 것은 ‘알림 개수’가 아니라 **심각도 → 대상 → 해결 행동**이다. 이미 일어난 일의 로그와 아직 해결할 조건의 현안을 같은 큐로 만들면 집중력이 낭비된다.

**POC 결정 — P0 진행 차단, P1 비차단 현안, P2 사용자 정리.**
- P0: 출격/치료/이동을 실제로 막는 조건을 관련 버튼 옆에 지속 표시한다.
- P1: 헤더 `주의 N`에서 실제 규칙이 제공하는 부상·미정산·준비 누락·새 사건만 묶는다. 항목 선택은 해당 인물/역/조건으로 포커스를 옮기고 자동 실행하지 않는다. 해결하면 항목과 개수를 즉시 갱신한다.
- P2: 비차단 항목 접기/확인 처리. 차단 사유는 닫았다는 이유로 사라지지 않는다. 색 외에 `진행 불가 / 주의 / 새 정보` 문자를 쓴다.

**복제 금지.** 3역에 수십 경고, 매 원정마다 전체 화면 튜토리얼, 자동 사라지는 토스트만으로 부상/정산 전달, 주 행동 위를 가리는 배너. 로그는 보조 기록으로 남긴다.

### 이 10개 뒤의 P1/P2 경계

- **P1:** 실제 장비 변경이 있으면 변경 전후 비교, 실제 관계 변화가 있으면 방향·최근 원인, 실제 정보 활용이 있으면 확인된 정보 목록과 연결된 선택. 고정 상세/키보드 포커스 보존, 필요한 경우 위험·사건 지도 필터.
- **P2:** 표정/부상 초상 변화, 짧은 선택 피드백 연출, 비차단 알림 개인화, 찾아볼 내용이 충분해진 뒤 용어집. 3D 초상·거대한 관계 그래프·지도 경제는 우선순위 밖.
- 한글 버튼/상태/불가 사유의 가독성, 색 외 식별, 마우스 없는 접근은 폴리시를 기다리지 않는 기본 조건이다. 기존 보고서의 1280×720/1920×1080 검수와 CJK 원칙은 유지한다.[S14]

## 5. 한 바퀴 검수 시나리오

**영등포에서 3인 확인 → 신도림 정보만 조회 후 취소 → 목적지 확정 → 상대가 있는 조우 → 카드별 비용/효과 열람 → 전투 선택 → 출격 상태 확인 → 수동 이동/공격/대기 → 정산 → 거점 복귀.**
- 정상 진행 외에 실제 규칙의 불가 조건 한 개, 선택 취소 한 개, 불확실한 선택 한 개가 있다면 그 경우를 포함한다. 없는 규칙을 검수용으로 새로 만들지 않는다.
- 설명을 읽는 동안 게임 상태·난수 결과를 바꾸지 않는다. 확률 선택을 취소/재열람해 성공 결과를 다시 뽑게 만들지 않는다.
- 전투 결과의 부상/전투불능/사망은 실제 규칙대로 구분한다. CK3 건강/죽음 표현을 전술 HP에 덮어쓰지 않는다.
- 결과 적용이 끝난 후 같은 인물 카드에서 실제 변화를 다시 읽을 수 있어야 한다. 내보인 알림과 값도 함께 갱신한다.

### 검증에서 제외한 자료

- Paradox 사이트로 이동하는 개발일지 단축 링크는 현재 404였다. 포럼 직접 요청 및 Reader 요청은 Client Challenge/Validating browser였으므로 **개발일지 본문을 읽었다고 쓰지 않았다**. 대신 공식 Steam 공지에서 확인 가능한 설계 의도만 인용한다. Steam 공지의 표지 이미지도 조회했지만 실제 UI 화면이 아니어서 배치 근거에서 제외했다.
- 위키 직접 요청은 클라이언트 챌린지였고 본문은 `https://r.jina.ai/https://ck3.paradoxwikis.com/...`로 조회했다. `Interface`는 플레이어 사용법이 아닌 모딩 문서여서 일반 화면 배치 근거로 쓰지 않았다. 404인 `User_interface`/`Developer_diary_16`도 제외했다.
- Naver/Bing/Google/DuckDuckGo 검색을 원문 발견용으로 시도했다. 무관한 검색 결과, AI 요약, JS 껍데기, 캡차는 근거로 사용하지 않았다. 공식 CK3 PDF 매뉴얼 확보 실패를 제3자 문서나 CK2 매뉴얼로 숨기지 않았다.
- 직접 실행/동영상 프레임 검증은 하지 않았다. CK3 모든 이벤트의 사전 확률 공개, 모든 메뉴의 완전한 불가 사유, 정확한 툴팁 잠금 키/시간 설정은 미검증이다. 보고서의 엄격한 수용 기준을 원작의 무결점 보증으로 읽지 않아야 한다.
