# Content consumers and normalized-store migration boundaries

## Evidence baseline

Investigation: 2026-09-13, working tree at HEAD `09863cf39209467c56c5459e8b4a552e58db2b3e`. Measurements below cover only top-level `docs/game-logic/*.md`, the parsed atlas object, and top-level `docs-site/rules/*.md`, unless specified. They describe checkout state, not production deployment. Initial `git status --short` showed unrelated tracked edits, including `SERVICES.md`, `vercel.json`, root service HTML and docs-site mirrors, plus untracked regional/backfill work; these were not changed by this investigation. File citations refer to that working tree.

Measured: 202 source Markdown pages; atlas 5,072,804 UTF-8 bytes; 422 humans, 32 houses, 5 theaters, 48 synthetics, 47 story manifests/45 story bodies, 27 hostile groups, 42 monster manifests/41 monster bodies, 67 arcs, 43 relations, 14 change-ledger entries, 3 diagrams. `parseCastIndex` returned 422 rows with zero positional ID/name mismatches. `projectionsFromAtlas` produced 125 files; all existing monster batch pages were represented. Seven `Rules-*.md` compendium pages plus `rules/index.md` exist only in docs-site, not top-level game-logic.

Recommendation: normalize authoring records and publication decisions, retain lossless document envelopes, and export deterministic compatibility files. Do not turn the design store into a live gameplay dependency.

## Concrete conflicts and migration invariants

1. **Freeze legacy IDs and order.** Preserve the measured 422 K-ID/name bindings and distinguish K/H/F/V/HC/HP namespaces. Sorting Cast-Index changes the parser-assigned IDs despite prose promising no renumbering; prose still says 412 humans, while validator requires 422 (`tools/wiki/world-atlas-parse.mjs:24-47`; `docs/game-logic/World-Narrative-Atlas.md:36-38,54`; `tools/wiki/world-atlas-verify.mjs:94-105`). Keep row-order metadata and explicit migration mappings; retain directed/name-based cast relation semantics until callers change.

2. **Import source envelopes, not projections.** Preserve prose, every JSON field, unknown extensions, provenance, revision, ledger, relationships and ordered arrays. House rendering omits charter/membership/succession and hardcodes exclusive-state display; the schema requires those fields (`tools/wiki/world-atlas-render.mjs:18-37`; `tools/wiki/world-atlas-schema.mjs:111-116`). Story section order and monster row-major IDs are enforced (`tools/wiki/world-atlas-verify-rest.mjs:181-189,228-235,268-275`). Atlas prose says r11 while JSON says r14: record this conflict rather than silently choosing a merged revision (`docs/game-logic/World-Narrative-Atlas.md:14,86`).

3. **Separate authored, integrated, publishable and runtime-promoted states.** Measurement at the baseline above: 113 fragment files exist; `publishedFragmentPages` allows 25 (B001 and G01-G24), excludes 88. Mount maps the fragment prefixes without that filter (`tools/wiki/build-wiki.mjs:250-278`; `docs-site/scripts/mount.mjs:29-39,157-198`). The whole atlas is also a non-fragment page, so fragment filtering is not field-level secrecy. A normalized exporter must explicitly decide surface-specific eligibility, not infer approval from file existence, `active`, or an approved integration SHA. Preserve the incomplete manifest state (`tools/wiki/confirmed-integration-manifest.json:2-5`).

4. **Keep export ownership explicit.** Source edits belong in the owning atlas/cast/root documents or site-authored compendium; mirrors are regenerated. Mount overwrites mapped destinations but never deletes stale pages, while VitePress enumerates all section Markdown; stale files can remain searchable (`docs-site/scripts/mount.mjs:192-198`; `docs-site/.vitepress/config.mts:8-18`). A future cleanup must use an output manifest, protecting the eight site-only rules files. Materializer's unexpected-file check exempts confirmed monster pages, so do not assume all nonprojected files are disposable (`tools/wiki/materialize-world-atlas.mjs:10-12,42-52`).

5. **Preserve public-text policy at the actual export surface.** Wiki rejects Kenshi/Underrail/Gunner/clone/복제 after entity decoding, NFKC/case normalization and invisible-codepoint removal; code fences, labels, alt/title and visible HTML attributes count, URL destinations do not (`tools/wiki/build-wiki.mjs:10,38-59,318-404`). Site gate strips HTML with regex and lowercases, so it is not equivalent (`docs-site/scripts/gate.mjs:44-61`). Do not apply a URL substring ban or assume passing the weaker site gate proves Wiki eligibility.

6. **Preserve routes and root service composition.** Keep document slugs/anchors and distinguish basename-based site rewriting from Wiki `.md` removal and SVG-specific relative paths (`docs-site/scripts/mount.mjs:130-138`; `tools/wiki/build-wiki.mjs:513-520`; `tools/wiki/world-atlas-isometric.mjs:59-70`). Root `/` is the service hub, not the VitePress home; composite staging must retain moodboard and proxied Next routes. `/assets/*` has a static/proxy namespace collision boundary (`SERVICES.md:3-14,28,34-45`; `vercel.json:2-29`). `system-design/` remains pending in the dirty service contract; do not silently register it. Gate resolves paths after discarding fragments, so anchor continuity needs separate export checks (`docs-site/scripts/gate.mjs:74-93`).

7. **Keep asset identity and evidence intact.** Binary formats are LFS-managed; store canonical path, digest, media metadata and provenance references rather than pointer-stub contents (`.gitattributes:12-37`; `tools/check-lfs-hydration.mjs:6-26`). Unity catalog YAML uses GUID/fileID references; runtime promotion also validates source/runtime bindings and retarget lineage (`Game/Assets/Janseon/Data/Assets/Area1GameDataCatalog.asset:12-34`; `tools/art/runtime-asset-provenance.mjs:135-180`). Recreating files without reference preservation can break scene/art wiring even when document links still work.

8. **Export approved static runtime snapshots, not live design records.** Runtime content contracts expose read-only catalogs and versioned fingerprints, not narrative documents (`Game/Assets/Janseon/Core/Data/ContentCatalogContracts.cs:8-12,59-85`). Preserve NFC UTF-8 length-prefixed canonical hashing, ordinal ordering and schema/content/fingerprint versions (`Game/Assets/Janseon/Data/Fingerprints/CanonicalContentFingerprint.cs:2`). Area-1 validator still locks 6 cards/3 roles/1 formation/3 stations despite the larger live route graph. Coordinate any future runtime export with compiled rule/catalog changes; changing design prose or graph JSON is insufficient. `EnsureCompatible` exists, but scoped search of `Game/Assets/Janseon` at this HEAD found no caller beyond its declaration; do not claim replay enforcement is integrated.

## Verification and remaining uncertainty

Read-only `materializeWorldAtlas({check:true})` passed all 125 expected outputs, including atlas SVGs. This establishes current projection equality, not publication approval or full narrative validity. Measurements invoked the actual parser/renderer/publication-filter functions in memory; no content was generated into product directories. LSP definition lookup timed out with Roslyn project-reference warnings; runtime contracts were read directly. No Unity, browser, build, deployment, installation or migration was run. The legacy Seoul graph generator and deployed artifact inventory were not established; preserve both graph representations and the service contract until a future migration explicitly resolves their ownership.
