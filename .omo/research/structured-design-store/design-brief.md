# 전환 설계 공통 입력

이 문서는 설계 제안의 공통 기준이다. 제품 코드·데이터·서비스는 바꾸지 않는다. 최종 계획은 한국어로 쓴다.

## 권안과 미응답
- 제안: 단일 SQLite DB를 가진 HTTP 저작 API. SQL은 공통 ID·관계·승인·출처에, JSON은 타입별 본문과 교환에 사용. MD는 긴 서술 블록의 표현법 및 문서 내보내기로 남긴다. JSON 파일 자체를 NoSQL 서버로 부르지 않는다.
- 사용자는 편집 기준을 답하지 않았다. 중앙 API를 승인된 선택으로 쓰지 않는다. 승인이 없으면 현재 Git 원본 지위 유지; 같은 내용을 Git와 DB에서 동시에 직접 편집하는 안은 제외한다.
- MongoDB를 포함한 서버형 저장소는 비교 대안이지 설치 지시가 아니다. 단일 writer 제약을 넘어선다고 추정해 DB를 먼저 늘리지 않는다.

## 형식에 반드시 담을 것
- domain planning/world/rules와 kind, 다중 category/tag는 서로 다르다. 파일명 prefix가 데이터 분류의 권한이 되지 않는다.
- 안정 ID·별칭·원본 locator·원본 bytes/hash·수집 branch/commit·내용 revision·검토·공개 범위를 분리한다. 기존 K ID는 이름 순서에서 재계산하지 않는다.
- 긴 한국어 서술은 본문 블록으로 보존. 공유 엔티티를 여러 문서에 복사하지 않고 ID로 연결. 검색용 투영은 재생성 가능해야 한다.
- source_kind(검증된 자료/추론/창작), review 상태, 공개 대상, 구현 상태, 실제 기준일과 세계관 시점을 서로 독립시킨다. unknown을 허위 default로 채우지 않는다.
- 실제 출처와 내부 영감의 공개권한이 다르다. 내부 source 참조/이름/에셋은 HTML·MD·JSON 공개 패키지·검색 인덱스에 유출하지 않는다.
