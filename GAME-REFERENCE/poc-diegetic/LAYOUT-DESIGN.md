# UI 레이아웃 설계 — 목표와 POC 역사

상태: 2026-09-19 개정. 현재 기준은 [Intent.md](../../Intent.md) 결정 11, [Design.md](../../Design.md) 0절, [목표 와이어프레임](../../GDD/system-design/total-war-ui/wireframes.json)과 [UX 흐름](../../GDD/system-design/total-war-ui/ux-flow.json)이다. 아래 목표는 데스크톱 문서 청사진이며 새 전투 구현이나 승인된 최종 HUD가 아니다.

## 현재 목표 레이아웃

[전투 콘솔](battle-hud/index.html)은 목표 청사진을 먼저 보여 주고 이전 콘솔은 접힌 역사 영역에 둔다. 대표 데스크톱에서 읽는 고정 폭 문서이며 기존 캡처를 목표 렌더로 재사용하지 않는다.

| 구역 | 목표 내용 |
|---|---|
| 상단 | 목표 설계 표기, 닫힌 전투의 시간 상태, 3D 자유 지휘 카메라 설명 |
| 좌측 | 이름 있는 영웅과 병졸 분대의 별도 명단. 병졸만 현재 인원 / 20 |
| 중앙 | 팬·오빗·줌을 전제로 한 공간 청사진. 고정 타일·셀·각도·FOV 없음 |
| 우측 | 선택 부대, 현재 지시, 이동·공격·진형 방향·정지, 미리보기·확인·취소 |
| 하단 | 철수·항복 확인과 결과·다음 행선의 설계 설명 |

선택이 없으면 명령을 비활성화하는 목표다. 미리보기 취소는 기존 지시를 보존하고 확인만 수락 기록에 남는다. 같은 부대의 새 확정 지시는 이전 지시를 교체한다. 목록은 카드 덱이 아니며 드로우·자원·재충전·명령 큐·웨이포인트 연쇄를 넣지 않는다. 영웅 직접 조작과 전체 군단 상한도 추가하지 않는다.

일시정지는 이 파티의 닫힌 전투에만 적용한다. 정지 중에도 선택·미리보기·취소·확인이 가능하다. 확인은 결정론적 수락 순서로 기록하며 재개 뒤 다음 시뮬레이션 단계에 적용한다. 공유 캠페인과 다른 파티는 계속되고 감속·배속은 없다. 카메라와 시간 제어는 질문 시간 초과 뒤 채택한 설계 기본안이지 소유자 명시 결정이 아니다.

질서 철수는 `LegalFallback` 확인이 필요한 명령, 패주는 사기 붕괴에 따른 비자발 이탈이다. 항복 제안은 자발적이며 퇴로가 막혀도 선택을 지우지 않는다. 적이 수락해야 종료된다. 포획은 종료 상태와 분리한 인물 신병 결과다. `ResultId` 결과 반영은 한 번만 하며 원정 계속과 귀환·정착·정복·방랑·교역을 분리한다.

## 검토와 식별자 경계

HTML의 목표 영역은 정적 배치 예시다. 동작 검토는 [목표 UI 템플릿](../../GDD/system-design/total-war-ui/index.html)에 연결한다. 인물 미술은 애니메이션풍 정비율을 목표로 하며, 이 도식은 완성 아트가 아니다. 이 문서의 HTML 식별자를 Unity `UiElementNames`의 구현 사실로 간주하지 않는다. 기존 Unity 이름은 Design.md 11절 POC 기록에 그대로 둔다.

## 2026-09-13 POC 역사 — 아래 상세와 수치는 현재 요구가 아님

아래는 당시 레이아웃·다이제틱 전환 주장을 보존한 기록이다. 원안의 확정·승인·검증 완료 표현은 현재 목표 승인이나 이번 검증 증거가 아니다. 카드 수치, 고정 카메라, 격자, SD, 재충전, 6분대와 4방향 슬롯은 현 목표로 이월하지 않는다. 좌우 사이드스크롤도 POC 표현이다. `anchor-capture.png`는 역사 캡처이며 바꾸지 않는다.

이 문서는 지금까지 확정한 레이아웃 설계를 한 장으로 정리한다. 근거는 루트 Design.md 계약, 무드보드(`../ui-layout-moodboard/`), 다이제틱 전환 문서(`./DIRECTION.md`)다. 화면을 유니티부터 짜지 않는다 — HTML 시안으로 검증한 값을 계약으로 잠그고 uGUI로 옮긴다.

## 전체 화면 구조

- 씬 순서는 Bootstrap(0) → MainTitle → Foundation(1)이고 씬 교체는 앱 FSM만 승인한다.
- 화면은 활성 lease당 Canvas 하나이고 모달 없이 같은 문서 안 패널 전환으로 단계를 표시한다.
- 대상 해상도는 1280×720과 1920×1080(16:9). 1080p에서 같은 비율 스케일을 유지한다.
- 키보드만으로 1차 액션 전부에 닿는다. 포커스는 신호 황 링으로 표시한다.

## 안정 요소 이름 체계

화면 요소는 `UiElementNames`가 단일 출처다. 목업 컨트롤과 유니티 이름이 일대일로 대응한다 — `main-title-root`·`main-title-start`, `stage-rail`·`route-rail`·`station-*`, `encounter-choices`·`choice-*`, `battle-hud`·`battle-grid`·`battle-cell-{x}-{y}`·`battle-play-pause`, `formation-edit-*`(슬롯·정면·확정·취소), `settlement-panel`·`return-action`. 스냅샷·테스트·캡처가 같은 이름 집합을 공유한다.

## 무드보드와 검증 자산

- `../ui-layout-moodboard/` — 11개 영역(시각 언어·앱 흐름·타이틀·캠페인·조우·전투·진형·지휘관 카드·정산·공간 문법·구현 파이프라인)의 자립형 무드보드. 동결 캡처·구현 캡처·위키 다이어그램만으로 구성했다.
- 이 문서의 수치는 무드보드 검증 당시 게이트(patina·금지어·경로 무결성·브라우저 렌더)를 통과한 값이다.

## 다이제틱 전환

2026-09-13 소유자 판정으로 표현층은 다이제틱 방향으로 갈아탄다 — 웹 카드·칩·스크롤 목록 문법을 폐기하고 UI를 세계 안 사물(관제 콘솔 계기·반발광 지도판·티커 프린터·클립 카드 랙)로 만든다. 구조 계약은 이 문서의 수치 그대로 산다. 앵커 시안은 `./battle-hud/index.html`(캡처 `./battle-hud/anchor-capture.png`), 방향 원칙은 `./DIRECTION.md`에 있다. 승인된 앵커를 기준으로 나머지 표면을 같은 언어로 펼친 뒤 동결 바를 교체한다.
