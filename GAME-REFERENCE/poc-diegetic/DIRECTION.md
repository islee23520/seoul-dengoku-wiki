# 다이제틱 UI 방향 — 목표 지휘 화면 후보

상태: 2026-09-19 개정. [Intent.md](../../Intent.md) 결정 11과 [Design.md](../../Design.md) 0절을 따르는 데스크톱 설계 후보다. 새 전투 구현이나 다이제틱 표현 승인 기록이 아니다.

## 현재 목표

관제 콘솔·노선도·종이 장부의 재질은 후보로 유지하되, 정보와 조작은 부대 지휘에 맞춘다. 가독성이 사물 흉내보다 우선한다. 목록은 카드 덱이 아니며 드로우·자원·재충전은 없다.

- 전장은 3D 자유 지휘 카메라의 팬·오빗·줌으로 읽는다. 아래 HTML의 상단 도식은 문서용 청사진이지 실제 렌더가 아니다. 카메라와 닫힌 전투 일시정지는 질문 무응답 뒤 채택한 기본안이며 소유자 직접 결정이 아니다. 각도·FOV는 잠그지 않는다.
- 영웅은 별도 지휘 인물로 표시하고 병졸 수에서 제외한다. 병졸 분대는 현재 인원 / 20으로 표시한다. 전체 분대·영웅·군단 상한은 정하지 않는다. 인물 미술 목표는 애니메이션풍 정비율이며 영웅 직접 액션은 없다.
- 부대 선택 뒤 이동·공격·진형 방향·정지 명령을 검토한다. 미리보기 취소는 기존 지시를 보존하고, 확인만 수락 기록에 남는다. 같은 부대의 새 확정 지시는 현재 지시를 교체한다. 명령 큐·웨이포인트 연쇄는 없다.
- 일시정지는 이 파티의 닫힌 전투만 멈춘다. 정지 중 선택·미리보기·확인·취소를 허용하고, 확인된 지시는 결정론적 수락 순서로 기록해 재개 뒤 다음 시뮬레이션 단계에 적용한다. 공유 캠페인·다른 파티를 멈추거나 감속·배속을 추가하지 않는다.
- 질서 철수는 `LegalFallback`을 확인하는 명령이다. 패주는 사기 붕괴에 따른 비자발 이탈이다. 자발적 항복 제안은 퇴로 봉쇄만으로 숨기지 않으며 적이 수락해야 종료된다. 포획은 별도 인물 신병 결과다.
- 결과는 `ResultId`로 한 번만 반영한다. 결과 확인은 귀환 명령이 아니며 원정을 계속할 수 있다. 귀환·정착·정복·방랑·교역은 서로 다른 결말이다.

## 현재 표면 매핑

| 영역 | 목표 설계 후보 |
|---|---|
| 전장 | 반발광 지도판 재질의 공간 청사진. 고정 셀·사거리 칸 수 없음 |
| 좌측 명단 | 영웅 상태와 병졸 분대 인원 / 20을 분리 |
| 명령 검토 | 선택 부대·현재 지시·미리보기·확인·취소 |
| 시간 상태 | 이 파티 전투의 진행/일시정지·재개 대기 구분 |
| 종료·장부 | 철수/항복 확인, 종료 유형과 신병 결과 분리, 다음 행선 |

[전투 콘솔 청사진](battle-hud/index.html)은 정적 배치 검토다. 상태 전이 시연은 [목표 UI 템플릿](../../GDD/system-design/total-war-ui/index.html)에서 확인한다. Unity 이름과 런타임은 변경하지 않는다. 기존 캡처와 직접 자산은 역사 자료로 보존한다.

## 2026-09-12~13 POC 역사 — 아래 원안은 현재 요구가 아님

아래는 웹페이지처럼 보인다는 판정에서 출발한 원안이다. 카드·격자·고정 카메라·SD 수치와 승인 절차는 당시 후보의 기록이며 위 목표를 제한하지 않는다. 좌우 사이드스크롤 역시 2026-09-19 이후 목표가 아닌 POC 화면 기록이다.

상태: 후보 — 소유자 앵커 시안 승인 전. 승인 시 Intent.md 결정 및 Design.md 개정으로 승격한다(두 문서는 병렬 세션이 수정 중이라 지금은 건드리지 않는다).

## 계기

2026-09-12 소유자 판정 — "ui layout 이 너무 웹페이지". HTML 목업 출발 파이프라인이 웹 문법을 그대로 배어들게 했다. 패널·카드·칩·스크롤 목록·웹 그리드·박스 테두리는 문서의 문법이지 게임 화면의 문법이 아니다.

## 원칙

1. UI는 세계 안의 사물이다. 화면에 뜨는 정보는 잔선 세계의 잔여 설비가 내는 것이다.
2. 사물의 종류는 세계가 정한다. 꺼진 안내판, 비상 전원 계기, 노선도 부첨물, 관제 콘솔, 종이 장부, 무전기.
3. 웹 문법을 쓰지 않는다. 카드 그리드, 칩, 스크롤 목록, 시스템 웹폰트 박스, 1px 박스 테두리 — 폐기.
4. 수치 계약은 산다. 카드 132×180, 격자 5×5 셀 64, 카메라 45°/35.264°, 1.5m 타일, 2.5등신 — 구조는 유지하고 재질만 바꾼다.
5. 가독성이 사물보다 우선한다. 사물 흉내가 판독을 해치면 사물을 물러난다.

## 표면별 사물 매핑

| 화면 | 세계 안 사물 |
|---|---|
| 메인 타이틀 | 꺼진 역명 안내판에 비상 전원이 들어온 상태 — 점멸 형광 글자, 노선 폴드 배경 |
| 캠페인 | 관제 데스크 위 노선도 부착물(스테이션 원점·구간 굵기)과 걸개식 단계 패 |
| 조우 선택 | 무전기에서 올라오는 세 갈래 응답 — 주파리 다이얼 위 선택 램프 |
| 전투 HUD | 임시 관제 콘솔 — 아날로그 계기(사기 바늘), 수직 모세관(HP), 반발광 지도판(격자), 티커 프린터(기록), 카드 랙(지시 카드) |
| 진형 편집 | 금속 배치판 위 자석 유닛 — 스프레이 방향 마킹 |
| 지휘관 카드 | 집게 클립에 꽂힌 신원 식별표 — 사진 웰, 소속 인장, 재충전 인쇄줄 |
| 정산 | 철재 걸판 장부 — 타자기 풍 수기와 인장 |

## 폐기 목록

- 웹 카드 그리드, 칩 필, 스크롤 리스트
- 시스템 웹폰트 본문 박스, 1px 베젤 패널
- 웹 그리드 여백 문법(space 4·8·16·24·40의 균등 배치)

## 유지 목록

- 해상도 1280×720·1920×1080, uGUI+TMP 전용
- 안정 요소 이름(UiElementNames) — 사물이 바뀌어도 명칭 계약은 잇는다
- 색 토큰의 의미(비상등 청백, 신호 황, 위험 적) — 재질 표현은 달라진다
- Core 규칙 전부(규칙서 참조)

## 절차

1. 앵커 시안(전투 HUD)을 보고 소유자가 방향을 판정한다.
2. 승인 시 나머지 표면 시안을 같은 언어로 펼친 뒤 동결 바를 교체한다.
3. 거부 시 이 문서는 폐기하고 다른 방향(게임 HUD 문법 등)을 다시 시안으로 검증한다.
