기준 원격 SHA: `dd8661d2f2326f4b107071a3e5f310a96a9eb9d9`

이후 사용자의 GitHub 반영 요청으로 수행한 원천 수정·빌드·게시 준비 검증은 [별도 적용 기록](publication-verification.md)에 남긴다. 아래 과거 판정을 소급하여 바꾸지 않는다.

## 범위와 판정 방식

순수 산문 편집이다. 자연어 문장을 고정하는 회귀 테스트는 만들지 않았다. 아래 집계는 **전수 목록의 누락 여부**를 확인하며, 이름의 자연스러움·정본 승인·게임 동작의 자동 검증이 아니다. 코드·런타임·배포 파일은 변경하지 않으므로 빌드·타입 검사·LSP·유닛 테스트·보안 스캔은 해당 없음이다.

## 1차 검증 이력

다음은 1차 산출물의 조회·검증 이력이다. 당시의 ‘신종목 무공 없음 보존’ 판단은 이후 사용자 직접 설정(총검술 사용자)으로 **폐기**됐다. 아래 옛 해시와 승인은 2차 수정본의 승인으로 재사용하지 않는다.

### 실제 조회

```sh
curl -fsSL https://api.github.com/repos/islee23520/seoul-dengoku-wiki/commits/main
curl -fsSL https://raw.githubusercontent.com/islee23520/seoul-dengoku-wiki/dd8661d2f2326f4b107071a3e5f310a96a9eb9d9/lore/culture/Martial-Paths.md
curl -fsSL https://raw.githubusercontent.com/islee23520/seoul-dengoku-wiki/dd8661d2f2326f4b107071a3e5f310a96a9eb9d9/lore/culture/Martial-Paths.json
curl -fsSL https://raw.githubusercontent.com/islee23520/seoul-dengoku-wiki/dd8661d2f2326f4b107071a3e5f310a96a9eb9d9/lore/editorial/Naming-Ledger.json
curl -fsSL 'https://api.github.com/repos/islee23520/seoul-dengoku-wiki/pulls?state=open&per_page=100'
```

확인 결과: 원격 응답 성공, `main`은 기준 SHA, PR 목록은 빈 배열이었다. PR #195 병합 시각 `2026-09-26T11:55:35Z`를 20:55 KST로 바로잡았다. 무공 JSON `status: draft`, 명명 원장의 9개 한자 필드는 모두 null이다.

### 사용자 표면

실행: `cua.createBrowserTab('iab', 'https://seoul-dengoku.linalab.io/wiki/world/Martial-Paths', {visible:false})`.

결과: 페이지 제목 `무공 | 서울:전국 공식 위키`, 아홉 유파 표·별칭·세부 기법이 표시됐다. `매트손·빈탄손·렌즈숨`이 실제 독자 화면에 노출되는 것을 확인했다. 총림의 항룡십팔장·타구봉법은 보이지만 최신 GitHub의 소림 추가 문구는 아직 없었다. 이는 원격 개정안 반영 확인이 아니라 **변경 전 게시 상태의 확인**이다. 이번 산출물인 Markdown은 원문과 나란히 읽는 QA로 검토한다.

### 집계·문서 검사

Node.js에서 JSON의 `아홉-유파-table3`, `손결-table2`, 첫 열이 `기법`인 5개 표를 추출하고 `상륙호위진`을 더했다. 개정안의 S/A/C/T 행 원문명과 집합을 비교했으며 중복과 Markdown 원문 존재도 함께 확인했다.

```text
S 정식명: 원천 9 / 개정안 9 / 누락 0 / 추가 0 / 중복 0
A 별칭: 원천 6 / 개정안 6 / 누락 0 / 추가 0 / 중복 0
C 분류: 원천 6 / 개정안 6 / 누락 0 / 추가 0 / 중복 0
T 세부: 원천 61 / 개정안 61 / 누락 0 / 추가 0 / 중복 0
품계 4개: 누락 0
총림 습속 4개: 누락 0
MD/JSON에서 수문손: 없음
```

`git diff --check` 통과. Node.js로 세 문서의 상대 링크 14건과 Markdown 표 열 수를 확인했으며 오류는 0건이었다. 첫 링크 검사 호출은 일회성 검사 코드의 괄호 오타로 실패했고, 바로잡은 호출 결과만 유효한 증거로 삼는다. 자연스러움은 표의 기능·추천명·주의 열을 원문과 나란히 읽어 확인했다. 최종 의미 대조에서 T03은 주입 간격 세기, T04는 수문 바퀴 밀기, T44는 소형 화기 범위를 보존하도록 다듬고 같은 검사를 다시 통과했다.

정리: 브라우저 QA용 tab 3은 `auditTab.close()`로 종료했다. 별도 서버·패키지·런타임은 만들지 않았다.

### 독립 검토 — 이전 버전에만 유효

검토자 `final_name_revision_review`: **APPROVE**, BLOCK 없음. 원천 대비 목록, 고유명·무공 없음 보존, 의미·분류 경계, 로컬/원격 상태 구분을 독립적으로 확인했다. T08 `수문봉법`과 T52 `봉인절단법`은 새 표시 조합어라는 취향 수준의 NOTE가 있었으나 실제 봉술·절단 내용과 제한이 있어 기준 위반으로 판정하지 않았다. 루트도 해당 근거를 확인해 유지했다.

검토 대상의 SHA-256:

```text
83c5f1d340c5cbe475929a6fa92254a3b1e5cd6b62cd0b2bc183a49119506c18  martial-name-audit-and-revision.md
9db2bae359a4e6c53ee5af00bfd008b6c8518944beaff7427f63e856c840e1d8  mugong-wiki-update-and-development-study.md
```

1차 승인 당시에는 검토 후 본문을 변경하지 않았다. 이후 2차 검토에서 본문을 수정했으므로 위 승인은 현재 본문을 보증하지 않는다. 커밋하지 않은 문서 변경이므로 Git HEAD만으로 검토 버전을 특정하지 않고 각 버전의 내용 해시를 남긴다.

## 2차 고강도 검토 — 최신 사용자 지시 반영

검토 범위는 로컬 편집안 82행과 품계4·습속4, 인접 조사 보고서다. 원격 HEAD를 다시 조회했으며 기준 SHA와 같았다. 사용자 설정 ‘신종목은 총검술 무공 사용자’를 원격의 이전 ‘없음’보다 우선했다.

### 발견한 결함과 수정

- 1차 신종목 보존 지침을 폐기했다. 원천 `Core-Characters.json`의 `신종목-p4`와 대응 Markdown, 생성 후 `sections["무공"]` 및 `biography`까지 검증할 지점을 명시했다.
- 수문심법·연환검법은 꼭 필요한 개명이 아니므로 철회했다. 수문호흡법·죽검연환법을 살리고 총검술 개명은 유지했다.
- 수문봉법·봉인절단법을 독립 무공처럼 제안한 부분을 철회했다. 도구 운용과 실제 무공, 작업명과 설명을 구분했다.
- 간격 유지→간격 고정, 호위 명부→원문의 방패 명부, 필사 중 호흡 조절→서서 한 장 필사하기로 의미를 바로잡았다. 다른 작업명도 짧은 표시명과 조건 설명으로 나눴다.
- S05는 개명 보류, T28·T40·T58은 동작/효과 해석과 개명 보류로 구분했다. 해당 행은 일괄 치환·신규 전투 카드 등록에서 제외한다. 나머지 이름 정리와 기존 기능 보존까지 막지는 않는다.
- 총림 안의 개방과 소림 전수를 분리하고, 소속·동료 관계만으로 타구봉법 카드 자격을 부여하던 제안을 정정했다.

### 독립 발견 검토

`hard_review_korean_names`, `hard_review_semantic_contract`는 82행 전체를 읽고 명칭과 원문 의미를 각각 검토했다. `shin_bayonet_source_review`는 인물 원천·생성 경로를 확인했다. 이들은 1차 안의 결함을 찾은 검토이며 아래 수정본의 최종 승인과는 다르다.

리뷰 의견을 그대로 자동 채택하지 않았다. ‘별칭은 원문에 있으므로 삭제 금지’는 디렉터의 명칭 정리 요구와 충돌해 기각했다. 짧은 표시명에서 빠진 조건이 설명에 보존된 경우 효과 삭제로 보지 않는다. ‘소화기’를 ‘소형 화기’로 푼 것은 소방용 소화기와의 오독을 막는 표기이며 새로운 무기 종류나 중화기를 추가하지 않는다.

### 2차 실행 검증

실행: `node <<'NODE'` 일회성 읽기 전용 검사에서 pinned JSON을 fetch하고 표의 한국어 첫 열과 개정안 S/A/C/T 원문명 집합을 비교했다. 같은 실행에서 로컬 상대 링크와 Markdown 표 열 수를 확인했다. `git diff --check`도 다시 실행했다.

```text
S: source 9 / audit 9 / missing 0 / extra 0 / duplicates 0
A: source 6 / audit 6 / missing 0 / extra 0 / duplicates 0
C: source 6 / audit 6 / missing 0 / extra 0 / duplicates 0
T: source 61 / audit 61 / missing 0 / extra 0 / duplicates 0
품계 4 / 습속 4: 누락 0
상대 링크 14: 깨짐 0
Markdown 표: 열 오류 0
git diff --check: PASS
```

수정본 8절의 인물 카드·소개문·유파 목록·작업 목록·총림 안내 예문을 직접 읽는 방식으로 문맥을 검토했다. 총검술의 보유와 장비 접근, 개봉칼 작업과 독립 무공, 총림 소속과 실제 전수를 분리한다. 이는 **산문 QA-by-read**이며 실제 게임 카드 또는 배포된 UI를 실행한 증거가 아니다. 원격 프로젝트 빌드·전투·생성기는 실행하지 않았다.

최종 검토에 넘긴 본문 SHA-256:

```text
207524e5f4b51804e8486a6bb84ff121cef212c68827b7890d5f2e490b3836f9  martial-name-audit-and-revision.md
339d6e8f51742866d32ba7c5234e94dcccfd8335f91e3bc08c1af67ed0d39016  mugong-wiki-update-and-development-study.md
```

로컬 Git HEAD는 `01db3a9e0ce320395aa2a6779147c0ff3724d2dc`다. 이 문서들은 커밋되지 않은 변경이므로 HEAD만으로는 검토 버전을 특정할 수 없다. 위 본문 해시를 함께 사용한다.

### 최종 독립 판정: INCONCLUSIVE — 게시 승인 아님

별도 읽기 전용 검토를 `codex exec --ephemeral --sandbox read-only`로 실행했다. 검토자는 두 본문을 읽고 위 SHA-256 일치, S9/A6/C6/T61과 ID 중복 없음을 확인했다. 그러나 응답 연결 재시도가 반복됐고, 약 19분간 최종 PASS/FAIL 없이 이미 확인한 문서·파일·공백을 다시 검사했다. 해당 프로세스를 종료했으며 **최종 승인으로 계산하지 않는다**. 세 선행 독립 검토의 발견사항과 루트의 수정·QA 기록은 유효하지만, 그것으로 수정본에 대한 별도 최종 승인을 대체했다고 주장하지 않는다.

이 검토는 다섯 관점의 단일 검토 시도였다. `review-work`의 다섯 독립 lane 통과나 `ultrawork`의 무조건적 최종 승인 확보를 주장하지 않는다. 코드·런타임·보안 스캔은 산문 편집 범위에 해당하지 않는다.

최종 전달 판정은 **1차 안의 일괄 반영 부적합, 결함을 수정한 로컬 2차안 제공, 네 항목 적용 보류, 게시 승인 미확보**다. 승인 또는 원격 반영을 이미 마친 문서로 사용해서는 안 된다.

정리: 검토 세션 34503은 중단 종료(exit 1)됐다. 원격 쓰기·커밋·푸시는 없었으며, 이 작업에서 서버·브라우저·임시 원천 파일은 만들지 않았다.

## 남은 범위

- 원격 Wiki·인물 원장·생성 파일·GitHub 이슈·PR은 쓰지 않았다. 커밋·푸시·배포도 하지 않았다.
- 전수검사는 명시된 버전의 무공 문서와 관련 명명 원장을 기준으로 한다. 원격 전체 이력의 모든 무공 표현을 제거했다고 주장하지 않는다.
- 기록단절법의 새 이름과 세부 세 항목의 의미 충돌은 개정안에 보류로 남겼다. 신종목의 총검술 보유는 사용자가 명시한 설정 변경이며 로컬 반영 지침을 정정했다. 원격 인물 데이터가 이미 바뀌었다고 주장하지 않는다.
