# 무공 관련 위키 업데이트 파악과 발전 방향 연구

조사일: 2026-09-26 (KST)

2026-09-26 현재 반영 상태: 이 문서는 날짜가 붙은 역사적 조사 기록으로 기여 브랜치에 복사되었다. 당시 상태는 원격 Wiki 정본·생성물·게시 사이트에 병합·배포되기 전이었으며, 제안·보류·옛 게시 상태를 현재 승인으로 바꾸지 않는다.

## 결론

현재 정본 원천은 부모 저장소가 아니라 별도 저장소인 [`islee23520/seoul-dengoku-wiki`](https://github.com/islee23520/seoul-dengoku-wiki)다. 확인 시 `main`의 최신 HEAD는 `dd8661d2f2326f4b107071a3e5f310a96a9eb9d9`이고, 2026-09-26 20:55 KST에 병합된 Wiki PR #195가 `lore/culture/Martial-Paths.md`와 JSON을 갱신했다. 무공 JSON이 저작 원천이고 Markdown·사이트는 그 내용을 보여 주는 대응 표면이다. JSON의 `status: draft`와 사이트의 공통 `정본` 배지는 최종 승인·잠금과 구별한다.

디렉터의 최신 요구에 따른 [무공 명칭 전수검사와 개정안](martial-name-audit-and-revision.md)을 2차 재검토했다. **9개 정식명·6개 별칭·6개 분류·61개 세부 항목**을 각각 검토했고 품계·비전투 습속도 포함했다. 방향은 한자어 금지가 아니라 `매트손·빈탄손·렌즈숨` 같은 억지 조어 제거다. `심법·권법·검법·봉법·신공`은 내용에 맞게 쓸 수 있다. 1차의 수문심법·연환검법 개명 권고는 철회하고 원래 정식명을 유지한다. 신종목은 최신 사용자 설정에 따라 총검술 사용자로 정정할 대상이다. 원격 Wiki에는 아직 적용하지 않았다.

`https://seoul-dengoku.linalab.io/wiki/`는 그 정본을 독자에게 보여 주는 공식 게시 표면이다. 사이트 HTML 자체는 앱 셸이고, 문서·인물 데이터는 빌드된 `generated`/`public` 투영물로 읽는다. 따라서 “사이트에 정본을 저장한다”기보다는 **GitHub Wiki 저장소의 `lore/`를 정본으로 저장하고, 사이트가 이를 생성·게시한다**고 표현해야 정확하다. 1차 조회 당시 [`person-1009`](https://seoul-dengoku.linalab.io/wiki/people/person-1009)는 `정본` 배지를 보여 주며, 실제 endpoint [`person-1009.json`](https://seoul-dengoku.linalab.io/wiki/person-details/person-1009.json)는 Wiki 저장소의 [`생성 JSON`](https://github.com/islee23520/seoul-dengoku-wiki/blob/dd8661d2f2326f4b107071a3e5f310a96a9eb9d9/wiki/public/person-details/person-1009.json)과 SHA-256 `d7777bc79b38da1e5641856989b15b0c6dc178e3f2d3ab48fa8437f2ea7ca8cd`로 일치했다. 이 JSON에는 `school`·`martial` 키가 없고 `sections["무공"]`에는 `없음. 생업만.`이 입력돼 있었다. 이는 **변경 전 게시 상태**다. 최신 사용자 지시는 신종목을 총검술 사용자로 확정하므로, 앞으로는 `Core-Characters.json`의 `신종목-p4`를 고치고 재생성해야 한다. 기존 `source: proposal`, `locked: false` 역시 공개 게시와 최종 승인·잠금을 구분하는 근거이지, 새 설정을 거부하는 근거가 아니다.

게시 시차도 확인됐다. 최신 GitHub `main`의 PR #195 문구는 `안국총림 안에서는 개방의 항룡십팔장과 타구봉법을 전한다`와 함께 소림 전수를 명시하지만, 현재 live `/wiki/world/Martial-Paths`에는 개방의 항룡십팔장·타구봉법 문구는 있고 소림 추가 문구는 아직 없다. 따라서 **원천 정본은 최신이고, 사이트는 적어도 무공 문서 자산 기준으로 한 배포분 뒤처져 있다**. 인물 JSON 한 파일의 일치는 사이트 전체가 최신 HEAD라는 증거가 아니다.

대신 무공을 발전시킬 수 있는 설계 기반은 충분히 정리되어 있다.

- `Ref-Taikou-Risshiden`은 스승과의 교유 → 입문 → 대련·비기 전수 → 인가 → 제자·도장 운영이라는 전승 흐름을 참고 메커니즘으로 정리한다.
- `Ref-Mechanism-Index`는 검호의 유파·도장·제자 목표를 군사 통일과 분리하고, 생업 숙련·조직 직위·시설 운영권을 별도 축으로 두자는 적용 제안을 담는다.
- `Characters-Factions-and-Professions`는 사제를 의미 있는 관계로 저장하고, 정비사·물류상·의무원·순찰대·전령·탐사원·기록관의 7개 생업을 정본 계약으로 둔다.
- `Cast-Profile-Contract`는 새 인물에게 생업·소속·직위·징집 이력·무장 접근을 기록하도록 한다. 유파를 새 국가나 새 병과로 넣을 근거는 없다.
- `Realtime-Formation-Card-Battle`은 전투 카드를 인물의 관계·생업·특기와 거점 카드에서 만들고, 실시간 진형·카드 전투 계약을 `rtfc-owner-cards-v2`로 고정한다.

따라서 다음 단계의 무공은 초능력이나 공격력 수치가 아니라 **스승·제자·전승·인가·빚·이탈을 가진 사회적 관계와 생업 숙련**으로 먼저 정의하는 것이 정합성이 높다. 이슈 #102의 세 전승 후보와 상호부조망 제안은 이 방향의 창작 초안이지, 위키 정본이나 구현 완료가 아니다.

## 디렉터 지시로 추가된 정본 방향

이번 검토에서 게임 디렉터가 다음 연결을 강하게 요구했다.

> **교 세력 → 총림 → 개방 계열 → 타구봉법**

이 요구는 `총림` 안에 개방 계열의 전승과 `타구봉법`을 분명히 드러내라는 방향으로 반영한다. 다만 최신 원천은 안국총림 안의 개방 전수와 소림 전수를 구분하고, 환승계를 별도 상호부조망으로 둔다. 따라서 총림 전체를 개방과 동일한 조직으로 합치거나 환승계를 총림의 하부 조직으로 만들지 않는다.

이 연결은 이제 Wiki 정본에 들어갔다. 인물 연결은 원문 또는 새로 승인된 설정을 근거로 한다. **신종목은 이번 사용자 직접 지시로 총검술 사용자로 정정한다.** 무공 보유와 특정 유파 가입은 별개이므로, 그의 스승·계보·품계·장비 접근을 임의로 채우지 않는다. 다른 인물도 세력 소속만으로 무공을 자동 부여하지 않는다.

### 용어를 자연스럽게 보이게 하는 규칙

무협다운 이름과 자연스러운 설명문은 양립할 수 있다. 아래 규칙은 최신 디렉터 요구에 맞춘 편집 기준이다.

- 총림과 개방을 매번 같은 이름으로 쓰지 않는다. `총림에서 개방 무공을 배운 사람`처럼 소속과 전수를 구분한다.
- `타구봉법`은 고유 기술명으로 유지한다. 초식·심법·운기 등의 어휘 자체를 금지하지 않되, 실제로 정의하지 않은 체계나 능력을 이름만으로 추가하지 않는다.
- `총림·개방·타구봉법`과 원천에 있는 `항룡십팔장·소림` 전수를 보존한다. 과거 생활어 후보를 현재 아홉 유파의 대체명으로 쓰지 않는다.
- 정식 무공명에는 `심법·권법·검법·봉법·신공`을 내용에 맞게 쓸 수 있다. 뜻 없는 수식어와 손·숨·줄의 기계적 조합을 걷어 낸다. 화면에서는 정식명과 한 문장 설명을 함께 쓴다.
- 기술 설명은 동작과 실패 조건을 구체적으로 쓴다. 새 동작 예문은 전수된 초식이나 승인된 전투 효과처럼 단정하지 않는다.
- `스승·선배·제자·후배`, `약속·빚·당직·연락망`을 우선 사용하고 `사부·장문인·호법·비급`은 총림 내부 인물의 고유 말투가 필요할 때만 제한적으로 쓴다.
- 타구봉법을 기존 작품의 기술 설명이나 문장을 복사해 재현하지 않는다. 프로젝트의 서울 지하철·골목·호송·상호부조 문제를 해결하는 방식으로 새 장면을 쓴다.

예시 문장:

> 안국총림에서는 개방의 항룡십팔장과 타구봉법을 전한다. 소림 무공도 전하지만, 개방과 소림의 전수는 서로 구분한다.

기존의 손목 밀기·발목 걸기 예문은 장면 후보일 뿐 정본의 확정 초식이 아니다. 환승계의 상호부조망 역할을 총림의 정의로 옮겨 쓰지 않는다.

### 게임 표면에 넣는 최소안

`타구봉법`은 첫 구현에서 별도 공격력 트리로 만들지 않고, **실제 전수가 확인된 인물의 카드 후보**로 검토한다. 총림 소속이나 스승과의 동료 관계만으로 자격을 주지 않는다.

| 카드명 | `타구봉법` | 이름은 고정, 설명은 서울식 동작으로 작성 |
| 카드 조건 | 해당 인물의 타구봉법 전수 기록 + 실제 봉 또는 사용이 허용된 대체 공구의 접근 | 세력 소속·동료 관계만으로 전수·장비·숙련을 자동 부여하지 않음 |
| 전투 적용 | 기존 `Move`·`SetFacing`·후퇴 판단과 연동해 퇴로·간격을 만든다 | 새 명령·새 피해 공식은 만들지 않음 |
| 비전투 적용 | 통행·호송·군중 분리·민간인 대피 장면에서 사용 | 시간·관계 신뢰·봉 상태 중 하나를 소모 |

총림이 교 세력이라면 세력 가치관·정책에는 `개방`, `공동`, `분산`, `자격` 축을 먼저 검토한다. 수치는 기존 `Values-and-Policy-Scales`의 근거와 산문을 맞춘 뒤 결정하며, 이름만 보고 임의 숫자를 넣지 않는다. 총림을 17번째 국가 슬롯으로 만들거나 교 세력의 기존 정통성을 대체하지 않는다.

## 현재 공백

1. 인물별 무공 유무는 인물 원문과 최신 승인 설정을 대조한다. `school`·`martial` 키가 없다고 누락으로 판정하지 않는다. 신종목은 `신종목-p4`에 총검술을 반영한 뒤 생성 JSON의 `sections["무공"]`과 `biography`를 함께 확인해야 한다.
2. 화면용 생활 별칭과 장부용 정식명을 함께 관리할 명명·문체 게이트를 계속 적용해야 한다.
3. 수련·전수·인가·이탈·재입문에 드는 시간·노동·관계 비용이 모든 유파에서 같은 형식으로 정의되지 않았다.
4. 무공이 기존 카드·생업·관계에 어떻게 연결되는지 승인된 매핑이 부족하다.
5. `개방`은 일반 동사·가치관 축과 무공 갈래명으로 함께 쓰이므로 문맥별 표기가 필요하다.
6. 현재 위키의 군사·장비 문서는 실제 무장 접근과 숙련을 분리한다. 전투 생업이나 장비 보유만으로 유파 가입을 자동 부여할 수 없다.

## 자연스러운 한국어 표현 점검

최신 `Martial-Paths.md`는 정식명뿐 아니라 별칭·분류·기법·본문의 조어를 함께 정리해야 한다. “장부와 사제 호칭에는 한자어 정식명을 쓴다”는 규칙은 디렉터의 최신 무협 장르감 요구와 충돌하지 않는다. 문제는 한자어 여부가 아니라 뜻과 종류가 전달되는지다. 상세 편집안은 [전수검사 표](martial-name-audit-and-revision.md)에 있다.

| 현재 표현 | 검토 의견 | 우선 대체안 |
|---|---|---|
| `기질적 기술` | 뜻이 한 번에 잡히지 않고 심리학 용어처럼 들린다 | `신준의 경로 판별` |
| `손결` | 프로젝트 내부 분류어지만 첫 독자에게는 의미가 닫혀 있다 | `수련 분야` |

## 권장 발전 방향

아래는 조사 당시의 후속 설계 제안이며 이번 명칭 개정으로 구현·채택된 내용이 아니다. 특히 3절의 상호부조 제안은 현행 원천의 개방 무공·안국총림·환승계 구분을 대체하지 않는다. 현재 편집에는 [세계관 편집 지침](../../../WORLD_BUILDING_GUIDE.md)의 경계를 우선 적용한다.

### 1. P0 — 전승을 사회적 관계 레이어로 먼저 잠근다

새 국가·병과·전투 수치를 추가하지 않고 `전승(tradition)`을 인물 관계와 생업에 붙는 별도 서사 레이어로 정의한다. 최소 필드는 다음과 같다.

| 필드 | 의미 | 기존 계약과의 연결 |
|---|---|---|
| `tradition_id` | 유파 또는 전승망의 안정 ID | 국가 ID·병과 ID와 분리 |
| `domain` | 이동·신호·수리·호송처럼 사회적 기능 | 7개 생업의 전술 기여를 재사용 |
| `mentor_relation` | 스승·제자 관계와 입문 상태 | `Cast-Relations`의 의미 있는 관계 |
| `access_condition` | 신뢰, 실습, 증언, 비용, 장소 조건 | 인물의 야망·관계·직위 |
| `license_state` | 미인가·수련 중·인가·정지·이탈 | 정통성·평판과 분리된 상태 |
| `obligation` | 무상 호송, 교대 노동, 정보 반환 등 | 시간·물자·관계 비용 |
| `provenance` | 사실·창작·파생·미확인 | `Cast-Profile-Contract`의 출처 구분 |

이 단계의 완료 기준은 이름을 정하는 것이 아니라, 한 인물이 누구에게 무엇을 배우고 무엇을 갚으며 떠날 때 무엇을 잃는지 문서로 추적할 수 있는 것이다.

### 2. P1 — 이슈 #102의 한 유파만 파일럿으로 플레이테스트한다

네 항목을 한 번에 정본화하지 말고 `환승 길잡이` 또는 `문 수리반` 하나만 고른다. 두 항목은 기존 생업·장소·전투 계약과 접점이 분명하다.

- **환승 길잡이**: 탐사원·전령·물류상의 이동 기록, 우회, 호송 신뢰를 검증한다.
- **문 수리반**: 정비사·순찰대의 시설 복구, 교대, 부품 비용을 검증한다.

파일럿은 세 갈래를 반드시 제공한다.

1. 비전투: 수리·호송·정보 교환으로 목표를 달성한다.
2. 전투: 기존 진형·방향·후퇴 명령과 기존 카드 타이밍으로 같은 물리 목표를 달성한다.
3. 거부·이탈: 유파 도움 없이 우회하지만 시간·부상·관계·물자 중 일부를 더 부담한다.

무공 이름을 새 공격 카드나 피해 보정으로 바로 번역하지 않는다. 플레이테스트에서 실제 선택이 생긴 뒤, 필요할 때만 기존 인물 카드 또는 거점 카드 후보로 올린다.

### 3. P1 — ‘개방’은 절도 세력이 아니라 상호부조·정보망으로 명확히 한다

기존 상호부조 제안처럼 구성원을 노점상·전령·의무원·정비 교대자·숙소 관리자·기록관 등으로 열어 둔다. 소매치기는 선택 가능한 위험 행동이고 정체성이나 필수 생업이 아니다.

정보망의 규칙은 다음 세 가지면 충분하다.

- 확인되지 않은 정보에는 소문 표식을 붙인다.
- 위급한 사람의 위치를 동의 없이 팔지 않는다.
- 한 역이 닫혀도 두 번째 회랑을 남긴다.

이렇게 하면 `개방` 가치관, 이주민 회랑, 전령 생업, 통행·의료·교역 정통성을 재사용하면서 새 국가 슬롯을 만들지 않는다.

### 4. P2 — 전투 연결은 기존 RTFC 계약 안에서 검증한다

유파의 전투 효과가 필요해도 새 전투 명령을 먼저 만들지 않는다.

| 전승 기능 | 우선 연결할 기존 표면 | 검증 질문 |
|---|---|---|
| 이동·호송 | Move, SetFacing, 후퇴, 통행 카드 | 좁은 지형에서 동료를 살리고 퇴로를 남기는가? |
| 신호·청음 | 지휘 반경, 카드 타이밍, 전투 전 정보 | 신호를 아는 사람과 모르는 사람의 정보 차이가 선택을 만드는가? |
| 차단·수리 | 장치 상호작용, 엄폐·시설, 방어 카드 | 부품·교대·시간 비용이 실제로 남는가? |
| 상호부조 | 보급·통행권·의료·귀환 후 정산 | 전투 승패를 조작하지 않고 후속 관계를 바꾸는가? |

현재 RTFC는 분대 명령과 집계 사상자 검증이 보류·미완료 상태이므로, 이 검증이 끝나기 전에는 무공 카드를 정본화하지 않는다.

### 5. P3 — 전승이 안정되면 런타임 데이터로 옮긴다

런타임 구현은 다음 순서를 권장한다.

1. Wiki 정본에 전승 계약과 출처를 등록한다.
2. 캐스트 관계 원장에 스승·제자·동료·원한의 변화만 기록한다.
3. 캠페인·웹 POC에서 비용과 분기 결과를 재현한다.
4. 플레이테스트 결과가 반복해서 같은 선택을 요구할 때만 `TraditionState`와 카드 후보를 설계한다.
5. 카드 소유권·재충전·결정론 해시·정산 exactly-once를 기존 RTFC 검증에 포함한다.

## 정본화 게이트

- 유파 이름과 기술명이 실제 단체·작품·상표를 복제하지 않는지 독립 한국어 자료로 확인한다.
- 각 유파에 `source_kind`를 붙이고, 기존 사실·창작·파생·미확인을 섞지 않는다.
- 16국, 이주민 회랑, 7개 생업, 복수의 정통성, 기존 RTFC를 대체하지 않는다.
- 각 전승마다 비전투·전투·거부/이탈 세 경로와 관측 가능한 비용을 기록한다.
- 무장 보유·전투 역할·징집 이력과 유파 가입을 자동으로 묶지 않는다.
- 수치 보정, 새 국가 슬롯, 새 병과, 자동 승리 카드를 추가하기 전에 별도 오너 승인과 플레이테스트 증거를 요구한다.
- “게임에 구현됐다”는 표현은 실제 런타임·웹 POC·플레이테스트 증거가 있을 때만 사용한다.

## 추천 결론

무공을 발전시키는 첫 작업은 **총림의 개방 전수와 타구봉법을 배우고 쓰고 떠나는 대가를 사건으로 보여 주는 것**이다. 실제 전수가 확인된 인물 카드에 연결하고, 이름만으로 피해나 자동 성공을 추가하지 않는다. 신종목은 최신 지시대로 **총검술 사용자**로 정정하되, 특정 유파 가입·군 경력·무장 지급은 별도 근거가 필요하다. 2차 개정안의 S05·T28·T40·T58 보류를 일괄 치환에서 제외하고, 이름 편집과 전투 규칙 승인을 분리한다.
