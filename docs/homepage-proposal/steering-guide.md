# 홈페이지 스티어링 가이드 (초안)

`sss.linalab.io` 루트 소개 페이지와 이후 추가하는 소개용 페이지의 판정 규칙이다. 세계관 집필 기준은 [`WORLD_BUILDING_GUIDE.md`](../../WORLD_BUILDING_GUIDE.md)가 우선하며, 이 문서는 소개 페이지에만 필요한 규칙을 더한다. 상태: **제안 초안**(소유자 승인 전).

## 1. 구조 규칙

| 규칙 | 판정 |
|---|---|
| S1. 섹션 순서는 소개 → 쇼케이스 → 플레이·기술 증거 → 기획 문서 → 개발 상태 → 외부 링크다 | 순서를 바꾸면 사유를 proposal에 적는다 |
| S2. 각 섹션은 제목(h2) 하나, 한 줄 요약, 본문 카드·표·링크 목록으로 이루어진다 | 한 섹션에 h2가 둘 이상이면 실패 |
| S3. 홈페이지는 요약하고 위키·GDD 원문으로 연결한다. 세부 설정(세력 성향, 수도역, 인물 이력)을 옮겨 쓰지 않는다 | 세부 설정 문단이 있으면 실패, 링크로 대체 |
| S4. `/wiki/`, `/wiki/seoul-showcase/`, 기존 딥링크와 리다이렉트는 보존한다. 홈페이지 링크는 공개 절대 URL을 쓴다 | 위키 경로를 새 경로로 바꾸는 링크는 실패 |
| S5. 모든 사실 카드는 출처 링크를 갖는다 | 출처 없는 사실 카드는 실패 |
| S6. 1440px·390px에서 가로 스크롤과 요소 겹침이 없다. 표만 자체 가로 스크롤을 허용한다 | `scrollWidth > innerWidth` 또는 겹침 1건이면 실패 |
| S7. 색·글꼴·간격은 [`DESIGN.md`](../../DESIGN.md) §2–§4 토큰을 쓴다. 새 색은 그 표에 역할을 추가한 뒤 쓴다 | 표에 없는 색 하드코딩은 실패. 초안 단계의 추가 색은 proposal §5에 역할을 기록한 경우만 허용 |

## 2. 문구 표식

모든 문장은 아래 셋 중 하나에 속해야 한다. 어디에도 속하지 않는 문장은 쓰지 않는다.

| 표식 | 쓰는 경우 | 필수 동반 정보 |
|---|---|---|
| **게시 문서** | 공개 위키 게시 문서의 문장을 그대로 또는 문장 단위로 인용 | 문서 제목과 링크 |
| **REPORTED** | 관측·집계로 얻은 수치(문서 수, 인물 수, 역 수 등) | 관측일, 출처(API 경로 또는 문서명) |
| **제안** | 승인되지 않은 어조·슬로건·설명 문구 | "승인 전" 표기 |

프로젝트 사실(저장소 구성, 공개 경로, HTTP 상태)은 저장소 문서나 관측 결과로 확인된 범위에서 표식 없이 쓸 수 있다. 근거는 proposal의 섹션별 표에 남긴다.

## 3. 문구 판정 규칙

- C1. **확정 설정은 게시 문서에서만 인용한다.** 내부 감사·증거 기록(`.omo/`), 과거 editorial 기록, 쇼케이스 대본은 확정 설정의 근거가 아니다. 쇼케이스 문장은 "쇼케이스에서는"처럼 출처를 밝힐 때만 쓴다.
- C2. **검증되지 않은 수치는 확정 문구로 쓰지 않는다.** 예: 334개 역, 51 요새, 1,022 캐릭터. 쓰려면 REPORTED 표식, 관측일, 출처를 함께 붙인다. 출처끼리 수치가 다르면(예: 인물 1,022 기록 대 공개 health 511) 공개 표면 값을 쓰고 차이를 proposal에 적는다.
- C3. **어조 문구는 제안으로 표기한다.** "절망적이지 않은 쇠퇴" 같은 어조·슬로건은 승인 전까지 제안 배지를 붙이고 히어로 제목으로 쓰지 않는다.
- C4. **상태를 혼동하지 않는다.** 게시, 승인, 배포, 게임 구현은 서로 다른 상태다. "완성", "출시", "플레이 가능"은 공개 빌드가 확인될 때만 쓴다.
- C5. **서울 유일 세계.** 서울 밖 현재 지리·세력·사건을 소개 문구에 쓰지 않는다(`WORLD_BUILDING_GUIDE.md` §6).
- C6. **비공개 경계.** soul·역사 모티브·비공개 editorial 내용, 내부 경로, 호스트 이름, 자격증명은 쓰지 않는다.
- C7. **폐기 설정 금지.** 무공·유파 등 폐기된 체계 용어를 소개 문구에 쓰지 않는다.

## 4. 어조

- 문장은 평서형 한다체로 쓰고, 한 문장에 한 사실을 담는다. 위키 산문 규칙(`lore/editorial/Writing-Rules.md`)과 같다.
- 과장 형용사("압도적", "최고의", "혁신적")와 독자 지시형 광고 문장을 쓰지 않는다. 버튼 문구만 짧은 명령형("쇼케이스 보기")을 허용한다.
- 분위기는 인용한 게시 문장이 만든다. 소개 문구가 새 분위기 설정을 덧붙이지 않는다.

## 5. 제출 전 점검표

1. 모든 사실 카드에 출처 링크가 있는가 (S5)
2. 모든 수치에 REPORTED·관측일·출처가 있는가 (C2)
3. 제안 문구에 제안 배지가 있는가 (C3)
4. 위키·쇼케이스 링크가 공개 URL 그대로인가 (S4)
5. 1440px·390px 캡처에서 가로 스크롤·겹침이 없는가 (S6)
6. 로컬 경로·호스트 이름·비밀 값이 없는가 (C6)
