# 위키 인물 SQLite: 사용자 여정, 수락 기준과 남은 작업

> **역사 계획 — 2026-10-31 현행 안내:** 아래 본문은 SQLite 인물 도구를 도입하던 당시의 사용자 여정·미완료 체크리스트·품질 관측을 원문 보존한 기록이다. 현재 운영 정본은 PostgreSQL `wiki`이며 비공개 편집 자료는 `wiki_private` 경계에 있다. 이관 완료된 추적 `data/canonical/wiki-cast.sqlite`는 제거했다. 외부 SQLite는 외부 경로를 명시한 이관·대사에만 사용하며 저작·런타임 입력으로 복원하지 않는다. 당시의 JSON 원천·독립 SQLite 빌드·`test:cast-sqlite*`·CI 설명은 현행 실행 절차나 현재 잔여 과제 목록이 아니다. 특히 431건·11건은 아래 후보의 과거 관측값이지 현재 PG 품질 수치가 아니다. 보존 원천·봉인 revision의 바이트와 승인 기록을 새 상태에 맞춰 고치지 않는다.
>
> 현행 절차는 [루트 README](../README.md), [도구 안내](../scripts/cast-sqlite/README.md)를 따르며, 명시적 이관 대사 코드는 [reconcile.mjs](../scripts/postgres-migration/reconcile.mjs)를 참고한다. 정확한 SHA/run 기준의 운영 전환 관측은 [배포 기록](../deploy/README.md#운영-전환-관측-2026-10-30)에 있으며, 과거 계획의 모든 인수 조건·원천 품질·개별 설정 승인이 완료됐음을 뜻하지 않는다. 세계관 편집은 [현재 지침](../WORLD_BUILDING_GUIDE.md)의 한국어 공개·서울 유일 세계·무협 제거 계약을 따른다.

## 당시 계획 원문

이 문서는 **위키 저장소의 공개 가능 인물 원천을 독립적인 SQLite 파일로 조회·검증**하기 위한 PR 계획이다. 실행 코드의 범위는 `scripts/cast-sqlite/`, 명령 진입점은 `package.json`, 사용 절차는 저장소 `README.md`다. 생성된 DB와 검증 영수증은 로컬 산출물이며 PR에 포함하지 않는다. 위키 밖 저장소, 정본 JSON, 사이트 화면과 생성 카탈로그의 개정은 이 PR의 범위가 아니다. 병합은 저장소 소유자만 한다.

이 문서의 **이상 상태는 목표**이며 달성 판정이 아니다. 인원·행·원천 파일 수, 해시와 품질 이슈 수는 최종 원천 및 PR head에서 다시 계산한다. 아래의 431건과 11건은 이전 후보 빌드에서 관측한 *미해결 항목의 기준값*으로, 새 원천에서 자동으로 같은 수가 나온다고 가정하지 않는다. 구조 검증 성공은 자료의 사실성이나 소유자 승인을 뜻하지 않는다.

## 데이터와 상태의 경계

1. 현재 인물 분모는 최종 원천 registry에서 계산한다. 안정 ID, 공개 route, 프로필 발생, 관계 방향과 빈 근거, 값의 원래 순서를 각각 보존한다. 발급되지 않은 값은 `NULL`로 남긴다. 공개 순번에서 안정 ID를 추측하지 않는다.
2. 생일·cohort·가계 node/edge·역할 결정·가구 관계는 별도 구조와 외래키로 연결한다. 가족 node가 인물 registry에 없다고 새 인물로 생성하지 않는다. 비한국계 혈통의 원천 전용 key를 한국식 clan 행으로 만들어 채우지 않는다.
3. 현재 역량·숙련·특성·효과·신체 상태는 공개 허용 필드만 적재한다. 역사 GURPS 지역·부대·방랑·장단점과 그 효과는 별도 역사 영역으로 둔다. 옛 수치를 현행 8역량으로 환산하지 않는다.
4. 개인 보유·직위·주군·궁정·조직·사건 연결은 관계의 방향과 적용 시기를 보존한다. 서울 밖 또는 근거가 미확정인 과거 보유를 기본 `current` 결과에 넣지 않는다. 원천의 `confirmed` 표기가 새 서울 권리 승인으로 자동 확장되지 않는다.
5. 공개 draft index의 이름·관계 수·주 표기와 역사 자료는 조회 가능 여부와 상태를 함께 보존한다. 초안, 제안, 검토용, 과거 대체 자료를 승인된 현재 사실로 합치지 않는다.
6. 비공개 편집 원천은 **경로·원문·인명·값을 공개 DB, 명령 출력, 영수증, 이 문서에 싣지 않는다.** 필요한 범위에서는 허용된 공개 투영과 값이 없는 해시·바이트 길이·제외 이유만 검증한다. 해시만 있는 계보와 원문을 복구할 수 있는 공개 원천 계보는 서로 다른 보증이다.

사람과 연결된 공개·역사 JSON의 각 leaf pattern은 `source path → JSON field → 정규화 table.column → person/SQL 조회 → 상태·행수·테스트`로 대응시킨다. 정규화 대상인데 원문 보존 테이블에만 들어간 필드는 완료로 세지 않는다. 새 source 또는 leaf가 생겼는데 매핑과 명시적 제외 이유가 없으면 빌드/검증이 실패해야 한다. 정책 문서와 실행 스크립트는 바이트·해시 provenance 대상으로 관리하되 사람별 JSON leaf 수에 섞지 않는다.

## 실행 계획과 인수 조건

- [ ] **P1. 최종 원천 고정.** 위키 PR head, 원천 Git revision, 입력 집합의 해시와 실제 분모를 새로 기록한다. 다른 저장소의 과거 빌드 수치로 통과시키지 않는다.
- [ ] **P2. 독립 빌드.** `npm run cast:build -- --output <새 파일>`을 위키 checkout만으로 실행한다. 기본 source root는 스크립트 위치에서 결정한다. 기존 출력 덮어쓰기, 원천 내부 출력, 미완성 파일 게시를 거부한다.
- [ ] **P3. 전수 정규화.** 인물·프로필·가치·관계·가계·가구·혈통·현재 문맥·현재 엔진·역사 GURPS·공개 index·역사 권리의 원천 행과 DB 행을 원래 순서·상태·포인터까지 비교한다. 범위 밖 편집 자료와 사람 권리를 생성하지 않는 검토용 자료는 이유를 coverage matrix에 남긴다.
- [ ] **P4. 출처 폐쇄와 비공개 검사.** 공개 원천의 raw bytes/hash 및 typed pointer, 참조 대상의 hash·pointer 상태, 공개 허용 투영의 해시를 각각 검사한다. 비공개 원문·상태·개별 값이 DB/영수증/CLI/추적 해시 입력에 들어가지 않았는지 확인한다.
- [ ] **P5. 독립 검증과 질의.** `cast:verify`의 full 검증에서는 실제 원천과 renderer·검사기를 다시 대조한다. source root 없는 offline 검증은 한계를 명시한다. `cast:query`와 읽기 전용 복사본으로 ID/route, current/history, 미확정·출처 조회를 실제 실행한다.
- [ ] **P6. 재현성과 전달.** 같은 runtime·원천으로 두 번 만든 DB 해시를 대조한다. 최종 코드·문서 commit 뒤 새 DB 및 full receipt를 만들고 테스트·README 절차·CI를 그 commit SHA에서 다시 실행한다. DB, 영수증, private 원천은 Git/public 배포물에 넣지 않는다. PR review 후 소유자가 병합한다.

## 현재 남은 품질·승인 제약

이전 후보 빌드에서 **역사 GURPS 독립 importer 이슈 431건**, **대상 JSON Pointer의 위치를 찾지 못한 참조 11건**이 관측됐다. 이 둘은 DB 파일의 무결성 오류와 별개다. 현행 GURPS 스키마에 대한 공식 검사가 지원되지 않았다면 상태는 `not_checked`이며 0건 통과로 표시하지 않는다. 따라서 깨끗한 원천을 요구하는 `--require-clean`이 실패하는 것은 예상되는 정직한 결과다. 최종 head에서는 두 수와 검사 지원 상태를 다시 측정한다.

431건의 복구는 각 역사 값의 실제 근거·형식·인용을 원천 편집자가 확인하고 별도 정본 변경으로 처리해야 한다. 근거가 없으면 미확인으로 남긴다. 공식 검사기가 현행 스키마를 지원하고 동일 원천에서 실행된 로그가 있어야 역사 품질을 `checked`로 바꿀 수 있다. SQLite 도구가 이슈를 삭제하거나 기준을 느슨하게 해 0으로 만들면 수락하지 않는다.

11건의 복구는 각 참조와 대상 문서의 실제 위치를 확인해 정본의 pointer를 수정하거나 미해결로 유지하는 일이다. unresolved가 0인 새 원천에 대한 full 검증 전에는 모든 출처 위치가 확인됐다고 말할 수 없다. 읽기 전용 오프라인 검증은 참조 대상 원문에 대한 재검사를 대신하지 않는다.

**소유자 승인도 미확인이다.** 행의 존재, `issued`·`confirmed`·draft 같은 원천 상태, 깨끗한 빌드나 PR 승인은 특정 인물의 새 역량·서울 권리·서술에 대한 소유자 승인이 아니다. 대상·범위·버전과 연결되는 실제 승인 기록이 생기기 전까지 해당 조회와 영수증은 `unconfirmed` 또는 `unreviewed`로 남긴다. 이 PR은 승인 기록을 만들어 내거나 대신하지 않는다.

완료를 주장하려면 최종 PR head에서 입력 분모·coverage matrix·전수 행 비교·privacy 검사·결정성·독립 QA·실제 README 실행·원천 품질과 승인 상태를 각각 확인한 증거가 있어야 한다. 남은 원천 이슈와 승인 제약은 PR 설명에도 그대로 공개한다.
