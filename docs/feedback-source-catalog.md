# Private feedback source catalog

The authenticated PostgreSQL release stage (`npm run generate`, also invoked by `npm run build`) writes two ignored service inputs. It requires the public and generation-private connections described in [README](../README.md); do not invoke the catalog worker directly against live output:

- `src/generated-private/feedback-selectable-views.ko.json`
- `src/generated-private/feedback-selectable-views.en.json`

They are private deployment artifacts, not public Vite assets and not canon. Each
record binds a canonical document/person ID, public route, locale, canonical
source-envelope SHA-256 revision, stable block/leaf identity, renderer-visible
text, and ordered JSON-pointer source spans. KO and EN remain separate internal
producer outputs because the feedback service owns one locale/route per canonical
document ID. This is not an English public catalog or a simultaneous English
authoring requirement: the public wiki and document API support Korean only.

Article leaves come from the same authored envelope values rendered by the wiki:
formatting and link syntax are excluded, visible labels/code/authored newlines are
kept, tables use explicit row/column leaves, and duplicate text keeps distinct
stable leaf IDs. Person records use the canonical primary source envelope and the
exact person heading segment; person revision is never computed from a browser or
generated projection.

Current envelopes are assembled from PostgreSQL typed records, not restored
`lore/*.json` authoring files. Logical source paths and JSON pointers identify
document/provenance namespaces. Historical `source_file` bytes and sealed
revisions remain immutable; a generated selectable revision is not approval,
a right to alter archived bytes, or authority to edit canon from feedback.

Configure `FEEDBACK_SELECTABLE_VIEW_PATH` to one generated locale catalog. Do not
serve these files from `public/`, commit generated bytes, or edit them by hand.

`report:feedback-catalog` remains registered, but its report script still reads
the removed `scripts/test-feedback-source-catalog.mjs` as a provenance input.
It is not a working current report path even when both private catalogs exist;
correcting that implementation is outside this documentation-only refresh.
Do not recreate a test file or claim a successful report from this note.

Publication transforms are authoritative for article inclusion: generated blocks
are matched back to authored leaves after frontmatter/title/private projection
lines are removed. A source value absent from the generated reader AST is absent
from the catalog. Computed pages without resolvable authored pointers are excluded:
`DOC:Glossary` is not cataloged because its reader page is an in-memory projection
of the dictionary with logical source ID `lore/glossary.json`, and `/world/`
remains an unsupported computed index. Supporting Glossary later requires
dictionary-field pointers and its canonical revision, not projection
`/content/*` pointers or a recreated source file.

## Mapping v2

Private catalogs use `selectable-text-catalog.v2` and ordered `sourceSegments`.
Literal segments retain equal source/visible lengths. Entity segments carry the
complete canonical encoded token plus its single decoded visible code point. A
selection that touches an entity submits the full token source interval atomically.
The shared service/U2 handoff is owned by the parent service candidate's
`TOOL/feedback-service/ENTITY-MAPPING-V2.md`; the WIKI producer does not define a
second clipping algorithm.
