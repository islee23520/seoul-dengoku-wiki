# 에이전트 기반 아트 파이프라인 — 설계 원리와 프로젝트 이식 부트스트랩

> **이 문서의 정체**: 한 게임 프로젝트에서 약 3개월간 실제 운영하며 정제한 에이전트 기반 아트 생성 공정을
> 일반화하고, **다른 프로젝트가 같은 공정을 스스로 구축하게 하는 실행 루프**로 바꾼 것이다.
> Part 1~2 는 "무엇을/왜", Part 3 는 **에이전트가 한 회전씩 돌며 실행하는 페이즈 머신**, Part 4~5 는 원장·템플릿.
>
> **읽는 주체가 에이전트라면**: Part 0 의 루프 규약을 먼저 읽고, Part 3 의 `PHASE-0` 부터 시작한다.
> 한 회전 = 한 페이즈. 게이트를 통과하기 전에 다음 페이즈로 넘어가지 않는다.
>
> **이식 시 해석 규칙**: Part 1의 제품명·도구명·경로는 원 프로젝트의 **참고 구현**이다.
> 대상 프로젝트에서는 생성 백엔드 어댑터, 리깅 연결부, 엔진 반입 도구를 새로 구현하거나 교체해야 한다.

### 문서 표기

- `[원리]`: 도구와 무관하게 그대로 이식할 규율
- `[참고 구현]`: 원 프로젝트에서 사용한 구현 사례
- `[신규 구현]`: 대상 프로젝트에서 새로 만들어야 하는 구성요소
- `[선택 연동]`: 선택한 벤더·엔진에 따라 교체 가능한 연결부
- `[사람 게이트]`: 자동 통과할 수 없는 사용자 판정 지점

## Part 0. 루프 규약 (에이전트 실행 계약)

### 0.1 회전 단위

```
LOOP:
  1. state 파일 읽기 → 현재 페이즈 P 확인
  2. P 의 [착수 조건] 검사 — 미충족이면 선행 페이즈로 되돌아간다
  3. P 의 [작업] 수행
  4. P 의 [종료 게이트] 를 명령으로 실행 → 예/아니오
     - 예   → 원장에 1줄 적립 → state 를 P+1 로 → LOOP
     - 아니오 → [실패 시] 지시 수행 → 같은 페이즈 재시도 (연속 3회 실패 = 사람 호출, 자동 우회 금지)
  5. 사람 게이트가 걸린 페이즈면 사용자 판정 없이는 절대 통과 처리하지 않는다
```

### 0.2 state 파일 (재개 가능하게)

`pipeline-bootstrap/state.json` — 루프가 죽어도 이 파일만 있으면 이어간다.

```json
{
  "phase": 3,
  "project": "<프로젝트명>",
  "engine": "unity|godot|unreal|web",
  "decided": { "style_anchor": "assets/_style/anchor.png", "asset_types": ["prop","character"] },
  "gates_passed": ["P0","P1","P2"],
  "ledger": ["2026-08-22 P2 — config SSOT 뼈대. 하드코딩 grep 0건"],
  "human_pending": null
}
```

### 0.3 비타협 3줄

1. **게이트 우회 금지.** 게이트 미통과·환경 장애 시 즉석 우회 경로를 발명하지 말고 **멈추고 보고**한다.
   (실사고: 게이트를 우회한 아이콘 파이프라인이 그림자 잔존 + 피사체 침식으로 최종 7장을 오염시켰다.)
2. **사람 판정 자리에 모델 판정을 놓지 않는다.** 계측·VLM 은 *후보를 줄이는 체*지 채택/기각이 아니다.
3. **매 회전 끝에 원장 1줄.** "나중에 정리" 금지 — 원장이 곧 파이프라인의 자산이다 (Part 4 참조).

### 1.2 이식 프로젝트에서 새로 구축할 구성요소

아래 항목은 원칙만 가져오는 것이 아니라, 대상 프로젝트의 환경에 맞춰 실제로 구현해야 한다.

| 구성요소 | 구분 | 최소 완료 조건 |
|---|---|---|
| 이미지·3D 생성 백엔드 어댑터와 인증 로더 | `[신규 구현]` | 단건 호출, 오류 분류, task ID 기록 |
| config SSOT·prompt builder·공용 negation | `[신규 구현]` | 하드코딩 검사 통과, 타입 1종 생성 가능 |
| 검증기·품질 재시도 루프·비용 상한 | `[신규 구현]` | best 보존, 예외 분기, budget cap 동작 |
| manifest·batch runner·report JSON | `[신규 구현]` | dry-run API 호출 0회, 실행 결과 재현 가능 |
| 스타일 앵커·비교 보드·사람 승인 절차 | `[신규 구현] [사람 게이트]` | 서로 다른 타입 2종의 톤 정합을 사용자 승인 |
| 리깅 연결부와 인간형 리깅 플러그인 | `[신규 구현]` | 대상 캐릭터 1종 리깅 후 변형 검증 통과 |
| 엔진 임포터·좌표/크기 검증·런타임 등록 검사 | `[신규 구현]` | 실제 실행에서 에셋 1회 등장 |
| 드리프트 원장·미채택 기록·운영 스킬 문서 | `[신규 구현]` | 새 세션이 문서만으로 에셋 1개 완주 |

> 인간형 리깅 플러그인은 원 프로젝트의 내부 구현을 전제로 하지 않는다. 이식 프로젝트에서 새로 만들거나,
> 검증된 DCC/엔진 연동으로 대체해야 한다.

### 1.3 스킬 지도 — 누가 무엇을 소유하나

| 스킬 | 소유 범위 | 소유하지 않는 것 (라우팅) |
|---|---|---|
| `art-concept` | 2D 전부 — 컨셉 7종·UI 아이콘·텍스처·로컬편집·A-pose·키아트·씬목업 | "무엇을 만드나"(GDD) · 3D 변환(art-3d) · 레이아웃(art-mockup) |
| `art-3d` | 컨셉 → GLB + 리텍스처 | 리깅·애니(정본 문서로 라우팅) · 엔진 반입 |
| `art-fx` | 파티클 — 검색·재가공·시트생성·조립·캡처검증 | 스타일 판정(vfx-principles 6원칙) · 기계 가드레일(vfx-style 룰) |
| `art-import` | 외부 아트(PSD 등) → 스프라이트 + manifest | UI 빌드 컨벤션(Presentation 레이어) |
| `art-mockup` | 화면 목업 도구를 자동 조작해 시안 생성 | 배치 판단 어휘(ui-design) · 실화면 검증(ui-loop) |
| `vfx-principles` | VFX 설계 프레임워크 6원칙 + 저작 공정 | 폴더·네이밍 기계 규칙 |

**패턴**: 스킬은 *의사결정 + 실행 레시피*다. 도메인 지식·CLI 상세·정본 절차는 각자 딴 곳에 두고 **가리킨다**.
소비처가 정본을 재서술하면 그게 드리프트의 근원이다.

## Part 2. 이식 가능한 설계 원리 16

> 이미지·3D 생성 서비스와 대상 엔진은 갈아끼울 수 있다. **아래 16개 원리가 진짜 이식 대상**이다.

### P1. 스타일 DNA 3층

| 층 | 무엇 | 구현 |
|---|---|---|
| **L1** | 프로젝트 공통 스타일 바이블 (한 문단) | `_STYLE_BIBLE_BASE` 상수 — 모든 프롬프트에 무조건 들어간다 |
| **L2** | asset type 별 **재질 번역** | `_material_{type}()` 함수 — 필요하면 sub_material 로 분화 |
| **L3** | **시각 앵커 이미지** 1장 | 재질 DNA 를 담은 구(sphere) PNG. 전 카테고리 생성에 레퍼런스로 주입 |

**철칙**: L2 는 L1 어휘를 그 카테고리 재질 맥락으로 **번역**하는 것이지 딴 도메인 어휘를 끌어오는 게 아니다.
`"inventory item"`, `"real-world material"` 같은 도메인 점프 한 단어가 전체 톤을 무너뜨린다.

**L3 앵커의 위험**: 앵커를 재생성하면 이후 모든 에셋의 재질 DNA 가 새 앵커 기준으로 드리프트한다.
→ 앵커 재생성은 **아트 디렉터 승인 + 전체 재생성 계획**이 있을 때만. CLI 에 고비용 경고를 박아둔다.

### P2. SSOT 3계층 분리

| 계층 | 무엇을 답하나 | 참고 구현 |
|---|---|---|
| **설계 SSOT** | 무엇을 만드나 (엔티티·정체성·실루엣) | `docs/gdd/*.md` |
| **파이프라인 SSOT** | 어떻게 만드나 (매직넘버·모델버전·임계·경로) | `scripts/art/config.py` |
| **구현 SSOT** | 런타임이 쓰는 수치 | `Resources/Data/*.json` |

- 생성 전 **설계 SSOT 를 읽고** `description`·`category`·`theme` 를 **도출**한다. 기억·즉석 창작 금지.
- **슬러그 가드**: 엔티티(캐릭터·몬스터·음식…)는 설계 SSOT 에 등록된 슬러그만 생성. 미등록이면 **생성 중단 → 기획 확정 먼저**.
  단 **예외를 명시**한다 — prop·environment 는 SSOT 가 per-item 을 열거하지 않으므로 승인된 manifest + theme 가 슬러그 소스다.
- 이중 SSOT 금지: 파이프라인 config 의 테마 팔레트는 *캐시*이고 디자인 권위는 설계 SSOT 에 있다고 못박는다.

### P3. 생성 → 검증 → 피드백 → 재시도 루프 (엔진의 심장)

```python
retry_with_feedback(generate_fn, validate_fn,
                    max_retries=10, temps=[...], budget_cap=N)
```
구성 요소 (전부 필요하다):
- **temperature schedule** — 시도마다 온도를 올린다
- **error classification → PATTERN_STRATEGIES** — 실패 *유형별*로 온도 전략을 갈아끼운다 (fast-track 임계 포함)
- **budget cap** — 무한 과금 방지, 상한 도달 시 *최선 결과* 반환
- **best score 보존** — 통과 못 해도 최고점을 들고 나온다
- **예외 분기**: rate-limit = 지수 백오프 재시도 / 인증 실패 = 즉시 중단 / 콘텐츠 필터 = 즉시 중단(프롬프트 수정 필요)
- **네트워크 재시도는 SDK 몫, 이 루프는 콘텐츠 품질 전담** — 두 재시도를 섞지 않는다

### P4. 게이트 이원화 — 기계 게이트 + 사람 눈 게이트

| 축 | 누가 판정 | 실증 |
|---|---|---|
| 수치·기하 (비율·배경 순도·폴리수·정렬·격자선) | **기계** | bbox 슬라이스가 플립북 블리딩을 기계적으로 걸러냄 |
| 미세 형태 (반대쪽 다리가 살짝 보이나) | **사람** | VLM 은 far-claw peek 을 전부 "clean" 판정 → 3D 가 비틀림 |
| 개수·구조 (다리 몇 개인가) | **사람** | VLM 카운팅 신뢰 불가 |
| 모션 만족감·리듬 | **사람** (실속도 GIF) | 정지 캡처·텍스트로는 판정 불가 |
| 채택/기각 | **항상 사람** | 계측은 후보를 줄이는 체 |

→ 각 게이트에 **"이건 기계", "이건 사람"** 을 문서에 못박는다. 애매하면 사람.

### P5. 드리프트 교정표 (증상 → 원인 → 수정)

파이프라인의 최대 자산. **사고 1건 = 표 1줄**. 예:

| 증상 | 원인 | 수정 |
|---|---|---|
| 배경에 회색 스튜디오 패널이 합성됨 | `figurine` 어휘가 "제품 촬영" 연상 → backdrop drift | 공용 negation 상수 사용 (`NO studio backdrop, NO gray panel...`) |
| 앵커 구가 출력에 같이 그려짐 | 다중 레퍼런스 합성 버그 | `"NO reference spheres, NO material sample balls"` 명시 |
| 예시를 나열했더니 그것들까지 그려짐 | examples 가 "생성 목록"으로 해석됨 | examples 제거 + 명시 negation |

**핵심 요령**: 프롬프트에서 *긍정 지시*보다 **negation 상수**가 강하다. 공용 금지어 블록을 만들고
일회성 스크립트가 그걸 우회하지 못하게 한다.

### P6. 레퍼런스 슬롯 계약

여러 레퍼런스를 한 번에 넣을 때 **각 슬롯의 소유권을 프롬프트가 명시**한다.
> IMAGE 2 = identity 만 소유 / composition-ref = **카메라만** 소유

이 분리가 깨지면 comp-ref 의 인물·팔레트가 새어 들어온다. 그리고 **슬롯 번호는 실제 첨부 리스트에서 파생**시킨다
(하드코딩 `IMAGE 5` 는 슬롯이 하나 빠지는 순간 전부 어긋난다 — 실사고).

### P7. 체인 파생 (독립 생성 금지)

한 원본에서 N개의 변종(진화 단계·수확 단계·파괴 단계)을 만들 때:
- ❌ 각각 독립 t2i → 형상이 따로 논다
- ✅ **기준형 1장 확정 → 나머지는 직전 산출물을 다음 입력(`--src`/`--design-reference`)으로 체인**
- 프롬프트 골격: ① 이번 델타 한 문장 ② **보존 명시** (`"...stay COMPLETELY IDENTICAL"`) ③ negation (`"NO new parts, NO floating pieces"`)

### P8. 능력 있는 도구에 비계를 쌓지 않는다

세대가 바뀐 모델은 "마스크 밖 보존 + 문맥 채움"을 네이티브로 한다.
과거 약한 모델용 SAM+블렌드 비계는 *마스크 바깥을 원본 픽셀로 재합성*하므로 soft-edge 객체(벽·물·그림자)를
**구조적으로 못 지운다** — 비계가 능력을 막는다.
→ **기본 경로 = 직접 편집**, pixel-lock 이 정말 필요한 전문가 케이스에만 마스크 경로.
정기적으로 "이 비계, 아직 필요한가?"를 되묻는다.

### P9. 모델 선택은 카테고리 분기 (단일 기본값 금지)

| 대상 | 모델 | 왜 |
|---|---|---|
| 리깅 대상(캐릭터·몬스터) | low-poly 최적화 모델, face auto | 정연한 토폴로지 → 리깅·쉐입키 보존 |
| 정적 오브젝트(프롭·음식) | 고품질 모델 + **face_limit 5000** | 표면 디테일 보존, 폴리 폭발 방지 |
| 얇은 물체(칼날·평판) | **low-poly 금지** | 면이 적어 normal 이 뒤집힘 — 후처리로 못 고침 |
| 표면 음각·부조 | 고품질 + face limit | low-poly 는 음각을 뭉갠다 (실루엣은 정상이라 놓치기 쉬움) |

→ `model_for(category)` 같은 **분기 함수 하나**가 SSOT. 파라미터 미지원 모델은 요청 body 에서 **자동 필터**
(예: 특정 모델에 `geometry_quality` 를 보내면 400).

### P10. 좌표·크기 계약을 문서가 아니라 코드가 강제

- **생성 방향 고정** — 항상 `orientation=default`(+X canonical) 로 명시 전달. 래퍼 기본값을 믿지 말 것
  (우리 스크립트를 우회해 SDK 래퍼를 직접 부르면 기본값이 달라 정렬이 깨진다).
- **멀티뷰 슬롯 순서 = 의미** — API 가 `files[]` **인덱스 위치**로 방향을 판정한다(파일명 무시).
  → 파일명 키워드 기반 **순서 검증기**를 넣어 불일치면 abort, 명령줄은 도구가 **출력해주고 복붙**하게 한다.
- **Transform identity** — 엔진 반입 시 position 0 / rotation 0 / scale 1. 좌표계·단위·정면은 mesh 에 baked.
- **real-world scale** — 실측 크기로 authored. "전부 1 로 정규화 후 데이터로 곱"은 콜라이더·물리·소켓을 다 어긋내므로 금지.
- **회전 보정은 단 한 곳에서 무분기로** — 임포터가 -90° 를 건다면 write-back 도 같은 규약(+X)으로.
  Z+ 정렬본이 섞이면 **-90° 가 중복 적용**된다.

### P11. manifest 기반 배치 + 리포트

```json
[{"type":"prop","theme":"theme-a","name":"asset-slug",
  "description":"...","sub_material":"wood","size":"4K",
  "output_path":"RawAssets/Props/theme-a/asset-slug/concept/01_concept.png"}]
```
- 필수 필드 누락 시 **조용한 폴백이 최악** (theme 누락 → theme-a 폴더에 theme-b 팔레트 저장). 폴백을 경고로 만들거나 필수화한다.
- `--dry-run`(잡 목록만) · `--limit N`(리허설) · `--only` · `--concurrency` · `--overwrite`
- **리포트 JSON 필수** — 서버측 task_id 등 *재현에 필요한 식별자*를 잃으면 체인이 끊긴다.
- 이터레이션 manifest 는 `_archive/{theme}/` 에 보존 (튜닝 이력이 곧 근거).

### P12. 비교면 루프 (감각 검수의 공통 뼈대)

1. **검수 면 먼저** — 본편 플레이에 기대지 않는다. 전용 벤치/랩/청취 페이지를 깔고 시작.
   현존 면을 먼저 조망하고, 없으면 짓고, **답답하면 그 자리에서 고친다**(참는 게 최대 낭비).
2. **축 1개** — 한 회전에 흔드는 변인은 하나.
3. **보드로 펼치기** — 2칸 이상 나란히 (전/후 · A/B · 기준선).
4. **보드 위에서 사람 합의** — 채팅 스크롤만의 판정은 증발한다.
5. **합의 1줄 박제** — 즉시.
+ **충실도 선언**: 면에 올리기 전에 *이번에 피드백 받지 않는 축*을 미리 못박는다. 없으면 판정이 산란한다.

### P13. 싼 단계부터 잠근다 (블록인)

이펙트는 **무채색 + 기본 텍스처로 타이밍만 먼저** 조립해 통과시키고, 그 다음 시트·팔레트를 입힌다.
그리고 `diff` 로 **타이밍 필드가 안 움직였음을 증명**한다.
→ 일반화: *가장 싸고 되돌리기 쉬운 축을 먼저 확정하고, 이후 단계가 그것을 못 건드리게 기계로 증명*.

### P14. 미채택 기록을 남긴다

벤더 기능표에 있다고 실제 파이프라인에 있는 게 아니다. 시도했다가 버린 경로는 **왜·언제·무엇으로 대체했는지**와 함께 박제한다.
(참고 사례: 자동 리깅/리타겟 프리셋 — 1회 시도 후 폐기, 대체 도구로 교체, 출하 0건. 스크립트는 참고용으로만 남기고 문서에 ⚠ 표기.)
안 그러면 **다음 세션이 기능표를 보고 같은 함정에 다시 들어간다** (실제로 오기가 이슈·계획 문서까지 전파됐다).

### P15. 스킬 = 라우터, 정본 = 한 곳

- 스킬 본문은 **의사결정 흐름 + 실행 레시피**. 도메인 원칙·정본 절차는 가리키기만.
- 2개 이상 스킬이 같은 규율을 말해야 하면 `shared/` 에 정본을 두고 각자 인용 (제3 SSOT 금지).
- 스킬 description 에 **트리거 발화**를 실제 사용자 말투로 넣는다 ("3d 뽑아", "batch 돌려", "drift 났어").

### P16. 실행 환경 규율

- **전용 venv 고정** (시스템 python 금지). 깨졌을 때의 복구 명령을 문서 맨 앞에 둔다.
- **인증 조회 우선순위**를 명시 (자격증명 파일 → 환경변수 → 프록시 토큰).
- 콘솔 인코딩·경로 규약(출력은 RawAssets 하위만, 절대경로 금지) 같은 **조용한 실패원**을 앞머리에 박는다.
- 서브모듈/외부 패키지의 로컬 수정은 **re-sync 시 날아간다** — 날아가면 무엇이 전부 실패하는지 적어둔다.

## Part 3. 부트스트랩 루프 — 페이즈 머신

> 각 페이즈: **[착수 조건] → [작업] → [종료 게이트: 예/아니오로 답하는 명령] → [실패 시]**
> 게이트가 `사람`이면 사용자 판정 없이 통과 처리 금지.

---

### PHASE-0 · 정찰 (Recon)

**착수 조건**: 없음 (진입점)

**작업**
1. 프로젝트가 무엇을 만드는지, 엔진·플랫폼·화면비를 확인한다.
2. **설계 SSOT 후보**를 찾는다 (GDD·기획 문서·데이터 테이블). 없으면 "없음"을 명시적으로 기록한다.
3. 만들어야 할 **asset type 목록**과 대략의 물량을 뽑는다 (캐릭터 N · 프롭 N · UI N …).
4. 이미 있는 아트 자산·폴더 관행·네이밍을 관측한다 (**추측 금지 — 까서 역설계**).
5. 사용 가능한 생성 백엔드를 확인한다 (이미지 API·3D API·인증 경로).

**종료 게이트**
```
state.json 에 engine / asset_types[] / design_ssot(경로 또는 "none") / backends[] 4항목이 전부 채워졌나?
```

**실패 시**: 미확정 항목을 **사용자에게 물어본다**. 추측으로 채우고 넘어가지 않는다.

---

### PHASE-1 · 스타일 DNA 확정 (L1 + L3)

**착수 조건**: P0 통과

**작업**
1. **L1 스타일 바이블 한 문단**을 쓴다 — 재질·라이팅·톤·레퍼런스 계보. 이후 모든 프롬프트에 무조건 들어갈 상수.
2. **L3 시각 앵커** 1장을 생성한다 — 재질 DNA 만 담은 단순 형상(구 등). 색·형태가 아니라 *표면 성질*이 주인공.
3. 앵커를 `{raw}/_style/` 에 고정하고, **재생성 = 전역 드리프트**임을 코드 주석·CLI 경고로 박는다.
4. (선택) 포즈 앵커·세계관 앵커 등 2차 앵커를 정한다. 앵커별 **주입 전략**을 표로 정한다
   (예: 캐릭터 = 앵커 + 세계관 레퍼런스 2장 labeled / 그 외 = 앵커 1장 raw).

**종료 게이트**
```
앵커 PNG 로 서로 다른 카테고리 2종을 1장씩 생성했을 때, 두 장이 같은 재질 가족으로 읽히나? → 사람 판정
```

**실패 시**: L1 문단의 어휘를 조정한다. **앵커를 다시 뽑기 전에 L1 을 먼저 의심**한다.

---

### PHASE-2 · 계약 뼈대 (폴더 + config SSOT)

**착수 조건**: P1 통과

**작업**
1. **폴더 계약**을 확정한다 — `{원본}/{Category}/{name}/{stage}/` + `_exp/` + `_archive/` + 엔진 반입 경계.
   금지 사항(카테고리 바로 아래 파일 배치, 문서 혼입, 대소문자 변형 폴더)을 함께 적는다.
2. **config 모듈 하나**를 만든다. 들어갈 것:
   - 경로 상수 (앵커·가이드·출력 루트·리포트 디렉토리)
   - 모델/버전 (역할별: 생성용 / 검증용 / fallback)
   - 카테고리별 사이즈·모델 분기 함수
   - 검증 임계·재시도 스케줄·budget cap
   - 테마/팔레트 등 프로젝트 어휘 사전
3. 규칙을 명문화: **매직 넘버·URL·사이즈는 전부 config**. 스크립트에 리터럴 금지.

**종료 게이트**
```
grep -nE '"(1K|2K|4K)"|[0-9]{4,}' <스크립트 디렉토리>/*.py | grep -v config.py   →  0건인가?
```

**실패 시**: 발견된 리터럴을 config 키로 승격한다.

---

### PHASE-3 · 첫 생성기 + 검증 + 재시도 루프

**착수 조건**: P2 통과

**작업**
1. **물량이 가장 많은 타입 1종**을 고른다 (보통 prop). 다른 타입은 아직 만들지 않는다.
2. `prompt_builder` 골격: `L1 바이블 + L2 재질번역(그 타입) + 공용 negation 블록 + 사용자 description`.
3. **negation 공용 상수**를 먼저 만든다 (배경·스타일·합성 금지어). 일회성 스크립트가 우회 못 하게.
4. **검증 함수 1개**를 만든다 — 그 타입에서 실패가 가장 잦은 축 하나만 (예: 배경 순도, 비율).
   가능한 한 **CV 로 기계 측정**(알파/명도 임계·bbox), 불가하면 VLM + **JSON schema 강제**.
5. **재시도 루프**(P3)를 붙인다: 온도 스케줄 · 에러 분류 · budget cap · best 보존 · 예외 3분기.
6. CLI 한 개로 통합한다: `--type --name --description --output [--size]`.

**종료 게이트**
```
같은 명령을 3회 실행 → 3장 모두 검증 통과 + 저장 경로 정확 + stdout 에 (점수, 시도수) 로그가 찍히나?
```

**실패 시**: 검증이 계속 떨어지면 **프롬프트를 고치기 전에 검증 임계가 타당한지** 대조군으로 검정한다
(정답을 아는 쌍을 같은 절차에 태워 통과하는지 — 지표가 무능한 경우가 흔하다).

### PHASE-4 · 게이트 선언

**착수 조건**: P3 통과

**작업**
1. 이 파이프라인의 **게이트 목록**을 표로 만든다. 각 행: 게이트 이름 / 판정 주체(기계·사람) / 판정 명령 / 통과 기준.
2. **사람 게이트 지점을 명시적으로 못박는다** — 어디서 반드시 멈춰 사용자에게 보이는가.
3. **우회 금지 조항**을 문서에 넣는다: 게이트 미통과·환경 장애 시 즉석 대체 경로 발명 금지, 멈추고 보고.
4. 모델을 판정자로 쓸 거면 **블라인드 규약**을 같이 정한다:
   파일명 중립화(`blind_000.png`) · 보기 순서 셔플 · **2지선다**(우연 50% 고정, 3회 전승 = 12.5%).

**종료 게이트**
```
게이트 표의 모든 행에 "판정 명령" 칸이 채워져 있고, 사람 게이트가 1개 이상 존재하나?
```

**실패 시**: 판정 명령을 못 쓰는 게이트는 게이트가 아니다 — 기계 측정으로 바꾸거나 사람 게이트로 강등한다.

### PHASE-5 · 배치 + 리포트

**착수 조건**: P4 통과

**작업**
1. manifest 스키마를 정한다 (Part 5 템플릿). **필수 필드 누락 시 조용한 폴백을 만들지 않는다.**
2. 배치 러너: `--manifest --output-dir --report` + `--dry-run --limit --only --concurrency --overwrite`.
3. 리포트 JSON 에 **재현 정보 전부** 기록: 사용한 파라미터 · 항목별 ok/skip/fail · 서버측 task id.
4. manifest 이터레이션은 `manifests/_archive/{그룹}/` 에 보존.

**종료 게이트**
```
--dry-run 이 API 호출 0회로 잡 목록만 출력하고, --limit 2 실행 후 리포트 JSON 에 항목별 결과가 남나?
```

**실패 시**: dry-run 이 실제 호출을 하면 **가장 비싼 버그**다. 최우선 수정.

### PHASE-6 · 타입 확장 (L2 증식)

**착수 조건**: P5 통과

**작업** — 새 타입 1종당 아래 5단계를 그대로 반복 (한 회전 = 한 타입):
1. `_material_{type}()` 추가 — L1 어휘를 그 재질 맥락으로 **번역**. 필요하면 sub-type dispatcher 로 분화.
2. 가족 소속 선언 어휘를 1개 이상 포함 + 끝에 negation 4~5개.
3. `build_{type}()` + 생성 함수 + CLI dispatcher 확장.
4. **파일럿 4장** 생성.
5. **기존 타입 2장과 한 화면에 나란히 놓고 톤 정합을 눈으로 확인** → 통과해야 확산.

**종료 게이트**
```
파일럿 4장 + 기존 2장 비교 보드에서 "같은 세계의 물건"으로 읽히나? → 사람 판정
```

**실패 시**: Part 4 드리프트 원장에서 유사 증상을 찾는다. 없으면 새 증상을 **원장에 먼저 등록**하고 수정한다.

### PHASE-7 · 다음 스테이지 연결 (3D / 엔진 반입)

**착수 조건**: P6 을 최소 2타입 통과

**작업**
1. **경계를 먼저 선언한다** — 어느 도구가 어디까지 하나. (예: "메시+텍스처까지가 3D 벤더 관할, 리깅·애니는 별도 도구 관할")
2. 카테고리별 모델 분기(P9)를 config 함수로 만든다. 얇은 물체·표면 음각 같은 **예외를 표로**.
3. **좌표·크기 계약**(P10)을 정한다: 생성 방향 고정 · 슬롯 순서 검증기 · transform identity · 크기 SSOT.
4. 후보 비교 레시피를 만든다: `_exp/` 에 2후보 생성 → 다각도 렌더 → 비교 그리드 1장 → **사용자 픽 후에만 승격**.
5. 엔진 반입 체크리스트: 런타임 에셋 등록 · 머티리얼 정합 · 재임포트가 손튜닝을 리셋하는 지점 경고.

**종료 게이트**
```
컨셉 1장 → 다음 스테이지 산출물 1개가 끝까지 통과하고, 엔진에서 1회 실제로 등장하나?
(캡처·프리뷰 통과 ≠ 실행 통과 — 등록 누락은 캡처가 완벽해도 런타임에서 아무것도 안 뜬다)
```

**실패 시**: 방향이 틀어졌으면 **입력 충실도**를 먼저 의심한다 (컨셉의 정면성·기준물 일관성이 방향 정합의 근원).

### PHASE-8 · 원장 + 스킬 문서화

**착수 조건**: P7 통과

**작업**
1. **드리프트 교정표**를 파일로 만든다 (증상 / 원인 / 수정). 지금까지 겪은 것 전부 등재.
2. **미채택 기록** 섹션을 만든다 (P14) — 시도·폐기·대체·근거·날짜.
3. **스킬 문서(SKILL.md)** 를 쓴다. 구성:

**종료 게이트**
```
그 스킬 문서만 읽은 새 세션(컨텍스트 0)이 대화 없이 에셋 1개를 끝까지 만들 수 있나? → 실제로 시켜본다
```

## Part 4. 실패 원장 — 우리가 실제로 밟은 지뢰

> 이식하는 프로젝트는 **같은 형태**의 사고를 겪는다. 증상 어휘를 빌려가라.

| # | 사고 | 근본 원인 | 일반화된 교훈 |
|---|---|---|---|
| 1 | 게이트를 우회한 아이콘 공정이 최종 7장 오염 (그림자 잔존 + 피사체 침식) | 게이트 미통과 시 즉석 대체 경로 발명 | **우회 금지 — 멈추고 보고** |
| 2 | 앵커 구가 결과물에 같이 그려짐 | 다중 레퍼런스 합성 | 레퍼런스는 **명시 negation** 과 세트 |
| 3 | 레퍼런스를 첨부했는데 다른 물건이 나옴 | 텍스트가 레퍼런스와 다른 걸 지시 → **텍스트가 이긴다** | 생성 전 실제 레퍼런스를 **열어 보고** 묘사를 거기서 받아쓴다 |
| 4 | 목업이 임의 톤으로 빠져 1차 전량 폐기 | 화면 톤 카테고리 규정 부재 | 생성 전 **카테고리 판정**을 강제, 임의 추측 금지 |
| 5 | "크게" 라고 해도 텍스트가 계속 작게 나옴 | 상대어 지시 | **절대값 표**를 프롬프트에 박는다 (하한 포함) |
| 6 | 4×2 시트를 시켰는데 4×4 로 나옴 | 생성물 격자 = 지시 ≠ 실물 | **실물을 세고** 소비측을 실물에 맞춘다 (재롤보다 싸다) |
| 7 | 시트 셀 경계 격자선이 인게임 사각 잔상으로 | 육안·중앙 bbox 검사는 *경계*를 못 본다 | **경계 밴드 밝기**를 기계로 잰다. 후처리 전 원본에서 검출 |
| 8 | 3D 가 좌우 비대칭·비틀림 | 측면 입력에 반대쪽 부위가 살짝 보임 | **입력 충실도가 출력 정합의 근원**. 미세 결함은 사람 눈 |
| 9 | 단계 세트가 단계마다 방향이 다름 | 저폴리 모델이 특징 없는 기준물의 정면을 매번 다르게 추정 | 세트는 **모델·설정 통일 + 체인 파생** |
| 10 | 재임포트가 손튜닝 파라미터를 조용히 리셋 | 임포터가 머티리얼을 기본값으로 재생성 | 재임포트 후 **diff 확인**을 체크리스트에 |
| 11 | 캡처는 완벽한데 게임에선 아무것도 안 뜸 | 캡처는 프리팹 직접 인스턴스 → 등록 체계를 안 탐 | **격리 검증 통과 ≠ 실행 통과.** 등록 + 1회 실제 스폰이 게이트 |
| 12 | 폐기된 도구 경로가 문서·이슈로 전파 | 미채택 기록 부재 | **미채택도 정본에 박제** |
| 13 | 대소문자만 다른 폴더가 유령 추적 | git 은 구분, 디스크는 안 함 | 폴더 규칙에 **명시 금지** |
| 14 | 부정적 측정 하나로 "생성이 나쁘다" 결론낼 뻔 | 지표 자체를 검정 안 함 | **대조군으로 지표를 먼저 의심** |
| 15 | 11지선다 A/B 에서 답이 3개 보기에 쏠림 | 모델 사전 선호 | **2지선다 + 셔플 + 파일명 중립화** |
| 16 | 백그라운드 검증 에이전트 보고가 세션 말미에 몰림 | 완료 통지가 push 전용 | 결과가 다음 행동을 게이트하면 **동기 실행**, 아니면 **파일 드롭 계약** |

### 5.2 프롬프트 조립 골격

```
[L1 스타일 바이블]           ← 프로젝트 공통, 무조건
[L2 재질 번역 (그 타입)]      ← 도메인 점프 금지
[사용자 description]         ← 설계 SSOT 에서 도출
[테마 footer: palette + tone_bias]   ← 색 어휘는 여기 위임, 본문은 theme-neutral
[공용 negation 블록]         ← 배경·스타일·합성 금지
[타입별 negation 4~5개]      ← NOT photorealistic, NOT 2D illustration, ...
+ [레퍼런스 슬롯 역할 문장]   ← "IMAGE 1 = 재질만, IMAGE 2 = identity만, ..."
```

### 5.5 게이트 표 골격

| 게이트 | 판정 주체 | 판정 명령 | 통과 기준 | 실패 시 |
|---|---|---|---|---|
| 배경 순도 | 기계 | `python -m ...validate --background <png>` | 순백 비율 ≥ X% | 재생성 (우회 금지) |
| 톤 가족 정합 | **사람** | 비교 보드 발행 → 사용자 확인 | 사용자 채택 | L1/L2 어휘 조정 |
| 실행 등장 | 기계+사람 | 실제 실행 후 콘솔 무경고 + 1회 등장 | 경고 0 | 등록 누락 점검 |

## 부록 A. 이 공정을 처음 보는 사람에게 하는 30초 요약

1. **디자인 SSOT 에서 "무엇"을 읽고**, 파이프라인이 "어떻게"를 담당한다. 둘을 섞지 않는다.
2. 스타일은 **바이블(글) + 재질번역(타입별) + 앵커(이미지)** 3층으로 강제한다.
3. 생성은 항상 **생성→검증→피드백→재시도** 루프다. 온도·예산·에러분류가 붙어 있다.
4. 게이트는 **기계와 사람으로 갈라져 있고**, 사람 자리에 모델을 앉히지 않는다.
5. 사고는 전부 **증상→원인→수정 한 줄**로 원장에 쌓인다. 그 원장이 파이프라인의 실제 가치다.
6. 도구는 **자기 관할 경계까지만** 쓰고, 그 밖은 정본 문서로 라우팅한다. 미채택도 기록한다.
7. 감각 판정은 **전용 비교면 위에서, 축 하나만 흔들어, 사람이** 닫는다.
