## 2. GURPS 원전 대조 대기

일반적으로 알려진 4판 유도는 `Basic Speed=(DX+HT)/4`, 수정 전 `Basic Move=floor(Basic Speed)`이며 개인 전술 이동과 관련된다. 그러나 이번 조회에서는 Lite 원문을 읽지 못했으므로 이 문장을 **이번 조사에서 검증한 Lite 사실로 인증하지 않는다**. CP 지출·특성에 따른 Basic Speed/Move 조정값은 개별 승인 캐릭터 입력에서 받아야 한다. 신종목 ST11·DX13·HT12라면 수정 전 후보6이지만 실제 확정 Move·짐·원정 예산으로 승격하지 않는다.

공식 PDF 다운로드 추정 경로 `sjgames.com/gurps/lite/4e/gurpslite.pdf` 등은 HTML 404였고 판매 페이지에는 즉시 원문 링크가 없었다. 검색 결과나 Basic Set 색인을 Lite 페이지로 둔갑시키지 않는다. 승인 전 확보할 항목:

- Lite 영어 4판 원문 파일, 표지/개정 월, 파일 SHA256, 인쇄 페이지와 PDF 페이지 대응.
- Basic Speed/Move의 정밀도·내림, Basic Lift의 lb 단위·반올림, 짐 등급 경계·최소 Move 규정.
- HP/FP 저하 시 이동 감소·중첩·반올림, 행군 피로 소모/회복의 원문 규정과 페이지.

아래 예제는 위 미확보 항목을 해결했다고 주장하지 않고 **가상 시험 분대의 Move 입력**을 사용한다. 공식 캐릭터 시트의 짐 계수는 직접 검증했지만, 계수를 캠페인 고정소수점으로 적용하는 방법은 신규 설계다.

## 3. 신규 설계 v0.1 — 승인 대상 전체

단위: 1 전략 턴 = 세계시간 1칸. 시간/일/km 환산은 하지 않는다. 이동점 `MP`는 추상 비용이며 저장 단위 `u`에서 `1000u=1MP`. 한 개인 Move 단위당 턴 예산 `1000u`. 도로 한 간선의 비용과 실제 길이의 관계는 이 버전에서 추상화한다. 간선 하나가 지나치게 긴 지도는 분할하거나 비용 override를 명시해야 한다.

### 개인·분대·태세

```
Q = 1000
encPermille = [1000,800,600,400,200]
healthPermille = 1000(정상), 750(보행 가능 부상), 0(자력 보행 불가)
fatiguePermille = 1000(정상), 750(피로), 500(탈진), 0(이동 불가)
personalU = floor(basicMove * Q * encPermille * healthPermille * fatiguePermille / Q^3)
squadBaseU = min(personalU of 모든 실제 보행 구성원)
turnBudgetU = floor(squadBaseU * stancePermille / Q)
remainingU = turnBudgetU - sum(accepted edgeCostU)
```

`basicMove`는 승인 캐릭터 계약에서 받는 비음수 정수다. 누락값에 기본5 등을 자동 대입하지 않는다. 지휘관·배속 영웅·병졸 모두 병목 계산에 포함한다. 병졸20 제한 외 새 분대 규모 상한을 만들지 않는다. 전술 Move의 내림을 중간에 재현하는 공식이 아니라, 승인 Basic Move에서 캠페인용 소수 보행능력을 보존하는 신규 공식이다. HP/FP 상태→health/fatigue 상태 매핑도 승인 데이터 입력으로 받아야 하며 임의 임계값을 숨기지 않는다.

짐 무게는 장비·무기·방어구·소모품·배정 공용짐을 개인별로 합한다. 승인 BL 값과 같은 단위로 비교한다. 정확히 경계값이면 낮은 짐 등급, 10BL 초과는 `OVER_CAPACITY`로 이동 명령 거부. 평균짐으로 가장 무거운 보행자를 감추지 않는다. 들것/탈것/운반 환자는 별도 승인 운송 계약이 없으면 지원하지 않으며 보행 불가를 자동 제외하지 않는다. 부상·피로계수는 원전 숫자가 아니다. 회복·피로 누적은 별도 데이터 계약까지 미지원 상태를 표시한다.

| 태세 | 계수 | 동작 |
|---|---:|---|
| 통상 행군 | 1000 | 이동·공격·요격·증원 허용 여부 각각 검증 |
| 강행군 | 1500 | 공격·요격 개시 거부; 피격 준비도 불이익은 전투 계약으로 전달, 크기는 미확정 |
| 매복 | 500 | 감소한 이동력; 탐지·요격은 승인된 결정론 정보/지형 규칙 필요 |
| 주둔 | 이동 종료 | 거점 도달 후 별도 태세 명령. active 상태 이동불가, 출발은 별도 통상/강행군 변경 필요 |
| 야영 | 이동 종료 | 현재 노드에서 별도 태세 명령, 공격 개시 불가 |

태세 변경으로 예산을 재충전하지 않는다. 이번 턴 첫 이동 전 이동 태세를 잠그며 이동 이후에는 종료 태세만 허용하는 제안이다. 종료 태세를 다시 풀어도 그 턴 이동은 재개되지 않는다. 강행군→통상 전환으로 같은 턴 공격 제한을 지우지 않도록 `usedForcedMarchThisTurn`을 기록한다. 태세 명령은 이동 명령과 다른 ID를 가지며 명시적 의존성으로 순서를 정의한다.

### 간선 비용

| 간선 유형 | 기본 비용 u | 조건 |
|---|---:|---|
| 지상 도로 | 750 | 같은 층, 승인 지도 도로 태그 |
| 지상 보통 | 1000 | 같은 층 |
| 지상 험지 | 1500 | 같은 층 |
| 지하 노선 | 1000 | 같은 지하층, 보행 가능 노선 |
| 환승/출입 | 1250 | 명시된 연결 노드 쌍만; 수평 구간과 다른 간선 |

`edgeCostU=ceil(baseCostU * terrainPermille /1000)+surchargeU`; 이 표의 기본 지형은 이미 반영돼 있으므로 기본 `terrainPermille=1000`, `surchargeU=0`. 추가 보정은 승인 데이터에서만 받는다. 통행권 없는 간선·봉쇄·잘못된 층은 무한 비용 대신 불법 상태다. ZOC 진입은 별도 숫자 비용을 붙이지 않고 정상 간선 비용을 낸 뒤 이동 종료한다. 같은 노드명이어도 층이 다르면 같은 위치가 아니다.

### 도달 범위·예약·전체 거부

현재 명령의 **모든 간선**에 대해 인접성→층→통행권→봉쇄→태세→ZOC→총비용 순으로 검증한다. 같은 실패가 여럿이면 이 순서, 경로 인덱스 순서로 최초 이유를 반환한다. 실패 시 위치·예산·구성은 원상태다. ZOC를 통과한 뒤 나오는 경로는 전체 거부하며 ZOC 노드가 끝점인 경로만 유효하다. 시작점이 적 ZOC면 다음 행동은 후퇴·공격·허가된 우회 중 하나이고 보통 MOVE로 우회하지 못한다.

도달 범위는 비음수 비용 Dijkstra로 계산하되 ZOC 노드는 결과에 포함하고 확장하지 않는다. 예산 이하라는 조건만으로 불법 간선을 통과시키지 않는다. 동일 비용 경로는 안정적인 ASCII edgeId 배열의 사전식 순서를 택한다.

여러 턴 예약은 목적지·의도 경로의 **비구속 계획**이며 단일 당일 이동명령이 아니다. UI는 현재 알려진 지도에서 턴별 유효 끝점을 제시하고 각 턴의 prefix를 별도 명령으로 확정한다. 현재 명령이 예산초과/봉쇄이면 prefix 자동실행 금지. 예약은 다음 턴 지형·권한·적 위치·짐 변화에 따라 다시 검증한다. 한 간선 비용이 새 턴 전체 예산보다 커도 부분 간선 진척을 저장하지 않는다. 우회/태세/수송 변경 필요를 알린다.

## 4. 수작업 계산 표

두 분대는 실제 인물 카드가 아닌 가상 검증 자료다. 정상 상태에서는 health=fatigue=1000. BL은 아래 예제 ST 값에서 나눗셈이 정수로 끝나 원전 반올림 문제를 피한다.

| 분대/구성 | ST | DX/HT 참고 | 가상 승인 Basic Move | BL | 짐 | 등급/계수 | personalU |
|---|---:|---|---:|---:|---:|---|---:|
| A 지휘관1 | 10 | 12/12 | 6 |20|15|0/1000|6000|
| A 병졸8, 각자 |10|10/10|5|20|30|1/800|4000|
| B 지휘관1 |15|12/12|6|45|40|0/1000|6000|
| B 병졸12, 각자 |10|10/10|5|20|50|2/600|3000|

A 통상=min(6000,4000)=4000u, 강행군=6000u, 매복=2000u.
B 통상=min(6000,3000)=3000u, 강행군=4500u, 매복=1500u.
추가 부상 예: B 병졸 한 명 보행부상750이면 5×1000×600×750×1000/1000³=2250u, B 전체2250u. 그 병졸이 피로750까지 겹치면1687u로 내림. 이75% 값·중첩은 신규 설계다.

시험 지도: S0→S1 도로750, S1→S2 도로750, S2→U0 출입1250, U0→U1 지하1000, U1→U2 지하1000. U1을 ZOC로 쓰는 사례는 별도 입력으로 표시한다.

| A 통상, 출입 간선 봉쇄 | S0→…→U1 |S2→U0 blocked|전체 거부, S0·4000 유지|
| A 불법 층변경 | S2→U1 직접 |승인 출입 간선 없음|LAYER_MISMATCH, 전체 거부|
| 예산 정확히 일치 | A 통상, 보통 간선4개 |1000×4=4000|도착·잔여0|
| 1u 부족 | 예산3999, 같은 경로 |4000>3999|전체 거부|

여러 턴 B 예약 예: 첫 턴 S0→U0(2750,250소멸), 다음 턴 U0→U1→U2(2000,1000잔여). 매 턴 시작 상태가 같다는 가정의 예측이며 잔여250을 다음 턴에 누적하지 않는다.

## 5. 동시 해결·정렬·재생 해시 제안

단순히 제출순으로 각 분대 이동을 끝내는 방식은 GDD 위반이다. 모든 명령을 같은 턴 시작 snapshot에서 사전검증한 뒤 해결한다. 다음은 승인용 최소 계약이다.

1. 행위자 권한·전투 잠금·규칙 버전·명령 ID 중복을 검증한다. 같은 commandId/같은 내용 재전송은 기존 영수증 반환, 다른 내용은 거부한다.
2. 분대별 명시 의존성 DAG를 만든다. 순환/중복 최종 명령은 거부한다. 독립 명령 저장 순서는 `(turn, phaseOrdinal, squadId, commandId)`로 고정하되 이 순서를 게임 승자 우선권으로 쓰지 않는다.
3. 유효 경로들의 동일 노드 도착과 반대 방향 동일 간선 통과를 같은 충돌 집합으로 묶는다. 예시 시간좌표는 `progress=cumulativeCostU/budgetU`의 유리수이며 float 변환 없이 교차곱으로 비교한다. 간선 점유구간이 겹치는 반대 이동도 검출한다. 이것은 신규 시간모델이며 비용을 현실 초로 해석하지 않는다.
4. 충돌에서 남은 이동력·태세·지형·통제권·정찰/매복/정보를 승인 conflictRuleVersion에 넘긴다. 무조건 squadId가 빠른 쪽이 이기는 방식은 금지한다. 이 보고서는 전투/매복 수치 규칙을 새로 확정하지 않는다. 해당 규칙이 없으면 `CONFLICT_RULE_UNAPPROVED`로 해당 충돌 명령들을 원상태에서 거부하는 연구 fixture만 허용한다. 제품 구현 준비완료가 아니다.
5. 전투 컨텍스트 생성과 결과 원장 적용은 별도 계약이며 한 번만 적용한다. 무효경로 전체거부와 유효경로 도중 발생한 적 조우를 혼동하지 않는다. 동적 봉쇄가 같은 배치에서 발생할 경우 atomic conflict 처리 정책까지 승인 전 미결이다.

해시 입력에는 ruleVersion·계수 데이터 해시·mapVersion·턴·세계시간·이전 상태 해시·canonical commands·AI 대행 표지·상태 전후·실패코드·명령별 비용/잔여·충돌 context IDs를 넣는다. HTTP 도착시각·호스트 처리순·UI 좌표·번역 문자열은 제외한다. UTF-8, 정수만, 공백 없는 JSON, object key 정렬, 명령/엔티티 배열 안정 ID 정렬, null 명시 여부를 고정하고 SHA-256한다. canonical 명세도 버전 관리한다. hash만으로 올바른 전투 규칙을 증명하지 않는다.

필수 결정론 fixture: 동일 state/commands의 입력 배열을 섞어도 같은 canonical bytes/hash; 같은 명령을 재전송해도 비용중복차감 없음; 비용 또는 태세가1개라도 변하면 hash 변경; 반대방향 간선 이동을 충돌로 검출; host/player/AI 제출순을 바꿔도 결과 동일. 이 문서는 SHA-256 알고리즘 선택·입력 계약을 제시했으며 Core 실행 해시를 만들어냈다고 주장하지 않는다.

## 6. 승인 데이터 validator 계약·검증 현황

승인용 validator 요구사항: ruleVersion/approvalRecordId/owner/승인일/원전 식별자 필수; draft 데이터는 제품 로드 거부; 모든 수치 정수·비음수·명시 상한/checked64 또는 임의정밀도; 나눗셈 floor/ceil 고정; Q=1000; 짐 경계 엄격 증가; 간선비용>0; 층변경 간선은 승인된 연결쌍; 참조 ID 유일/유효; 병졸≤20; 실제 모든 보행자의 이동입력 존재; 과적·이동불가 처리; 태세 공격 제한 보존; conflictRuleVersion 부재시 충돌 구현 PASS 금지. 곱셈 intermediate overflow를 clamp로 숨기지 않는다.

검증: GDD/API·Academy·SJ Games 공식 안내/시트 직접 조회, 두 분대/경로/상태 손계산 완료. 이는 설계 표의 검산이며 제품 lint/typecheck/unit test를 실행한 것으로 보고하지 않는다. 이슈의 '고정소수점·데이터 validator'는 여기서는 검토 가능한 계약만 작성했고 validator 구현/실행은 하지 않았다.

소유자가 검토할 구체값: 1000u/Move/턴, 가장 느린 구성원 기준, 짐 계수 적용 방식, 부상·피로750/500, 강행군1500·매복500, 간선750/1000/1500/1250, 태세 변경 잠금, 잔여 이월 없음, ZOC 회계 잔여 유지, 예약과 당일 명령 분리, 충돌 시간좌표·canonical hash. 승인 기록 없이 모두 draft를 유지한다.

남은 필수 항목: Lite 원문 판본·정확한 페이지 대조, HP/FP 상태 매핑, 지도 간선 규모·길이 정책, 부상자 운송, 준비도 불이익 수치, 매복/정찰 및 동적 충돌 규칙, owner 명시 승인. 따라서 **보고서 작성 완료 / #296 전체 PASS 아님 / #297 제품 구현 착수 불가**다. 로컬 파일 한 개만 추가했으며 원격 댓글·커밋·정본·Unity는 변경하지 않았다.
