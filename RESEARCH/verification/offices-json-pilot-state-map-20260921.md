## 주의: ID 체계가 둘이다

- 정본 ID `S01-S16`은 atlas 순서다(급수계약정 = S01).
- `generate-catalog.mjs`의 `slug`(`s01`-`s16`)는 `Sixteen-States.md` 국명 표의 행 순서다(대한민국정부 = s01, 급수계약정 = s10). atlas ID와 다르다.
- JSON 파일럿은 atlas ID를 키로 삼아야 하며 slug나 산문 제목을 키로 쓰면 안 된다.

## 현 소비자: `WEB/wiki/scripts/generate-catalog.mjs`

- 118-124행: `| 국가 | 티어1 |`부터 다음 `## ` 제목 앞까지를 잘라, 6칸 행 정규식 `^\| ([^|]+) \| ... \|$`(m 플래그)로 국가명 -> 5직함 맵을 만든다. 구분선 `|---|...|` 행도 6칸으로 잡히나 국가명 조회에 쓰이지 않는다.
- 423-429행: 인물의 `state_name`으로 행을 찾고 인물 `품계` 문자열의 위치(+1)를 `T1`-`T5`로 쓴다. 못 찾으면 `E_PERSON_TIER_MISSING`을 던진다. `S00`은 `T5` 고정.
- 산문 제목, 다섯 층 표, 옛 조선 관직 치환 표는 읽지 않는다. 따라서 `### 원불교`는 현재 소비 경로에 영향이 없다.
- 지켜야 할 가정: 표 머리글 리터럴, 표 뒤 `## ` 제목, 국가 칸 = 정본 국명, 칸 공백 한 칸, 직함은 `품계` 값과 정확히 일치.
- `stateSlug`는 Sixteen-States 표 행 순서(인덱스+1)다. `rulerByState`는 국명 키 하드코딩(교헌필사정 -> 오해린).

## JSON 설계 권고

- 국가 행은 atlas ID(S01-S16) 키로 `name`과 `tiers[5]`를 저장한다. 묶인 산문 제목은 표현 계층으로만 둔다.
- 산문은 (제목, 단락, 표, 링크 스팬) 순서 블록으로 보존해 위 목록과 대조 가능하게 한다.
- 소비자가 국명 조회를 유지하도록 국가 칸 문자열은 정본 국명을 쓴다.
