# 전략에서 전투로

![전략 상태와 전술 결과의 아이소 왕복](https://github.com/islee23520/seoul-kenshi/blob/main/GAME-REFERENCE/assets/wiki/isometric-battle-roundtrip.svg?raw=true)

전략 세계 상태를 전술 전투에 넘기고, 한 번의 결과만 캠페인에 반영하는 왕복 과정을 운영합니다.

## 세계 상태는 한 곳에서

캠페인의 `WorldState`만 영속 상태를 소유합니다. 전투는 캠페인을 직접 수정하지 않습니다.

## 전투를 시작할 때 넘기는 정보

전투를 시작할 때 다음 정보를 한 묶음으로 확정해 넘깁니다.

- 전투, 캠페인, 위치와 참가자 ID
- 부상, 사기, 장비, 물자와 파티 구성
- 전장 원형, 지형, 위험과 목표
- 합법적인 퇴로와 증원 조건
- 세계 시간, 전투 시드, 규칙과 콘텐츠 버전

전투가 시작된 뒤에는 바깥 세계의 상태를 다시 가져오지 않습니다. 전투 Core는 30Hz 고정 틱으로 진행하고, D1 드라이버만 프레임당 최대 4스텝을 수행합니다. 카드 상태는 `(OwnerUnitId, CardId)`로 분리하며 인물별 재충전은 방패벽 300틱, 격려 600틱, 협공 450틱, 기동 재집결 600틱입니다. 공유 거점 카드는 보급 900틱, 통행 750틱으로 최대 2슬롯을 공유합니다. 이전 ownerless replay는 자동 변환하지 않고 규칙 버전 오류로 거부합니다.

## 전투가 끝난 뒤 돌려주는 결과

전투가 끝나면 승패, 흐른 시간, 인물의 생사, 새 부상, 장비 소모, 전리품, 포로, 파티의 퇴로와 거점 통제 변화를 확정된 결과로 돌려줍니다. 승인된 전술 표시 계약은 0..4 집계 생존수이며, 현재 작업에서 작업 7 구현·검증이 끝나기 전까지 실제 런타임에 구현된 기능으로 간주하지 않습니다. 구현 시 정산은 기존 논리 `UnitId`와 남은 `HP`만 사용하고, 치료로 집계 생존수가 늘거나 리더가 별도 정산 대상이 되지 않도록 합니다. 증원은 기존 분대의 회복이 아니라 별도 분대로 결과에 포함하는 승인 계약이며, 현재 구현 완료를 주장하지 않습니다.

## 결과는 한 번만 반영

`ResultId`는 결과를 구별하는 고유 값입니다. 이미 처리한 결과가 다시 들어오면 앞서 만든 영수증만 돌려줍니다. 같은 전투에 다른 결과가 들어오면 상태를 바꾸지 않고 복구 오류를 냅니다.

정산 순서는 인물 운명, 물자, 파티 위치, 시간, 거점·노선 통제, 관계·평판 사건입니다. 반영 전 검증 단계에서 모든 불변식을 통과한 뒤 한 번에 반영합니다. 전투 reset은 정산 전에 현재 전투 세션만 시작 상태로 되돌리며, 캠페인 상태나 이미 반영한 결과를 되돌리는 수단이 아닙니다.

전쟁 준비, 봉쇄, 철수와 점령 이후의 수치 규칙은 [전쟁과 공성](/rules/Warfare-and-Sieges)에, 거점 단계 전이는 [거점과 영토](/world/Strongholds-and-Territory)에 정의합니다.
