# 같은 선택이 같은 결과가 되나

![저장 뒤에도 칸에 누가 서 있고 어느 쪽을 보며 어디까지 보이는지 그대로 이어지는지](https://github.com/islee23520/seoul-kenshi/blob/main/GAME-REFERENCE/assets/wiki/isometric-grammar.svg?raw=true)

2026-09-07 격자 POC 역사 자료다. 현재 저장 계약의 기준은 불변 전투 컨텍스트, 수락된 부대 명령과 결정론적 체크포인트다.

## 다시 돌려도 같은 세계

같은 시작값과 선택 기록으로 다시 돌리면 같은 세계 상태와 사건 기록의 검사값이 나와야 합니다. 무작위 값은 전투, 조우, 세계 사건처럼 쓰임새별로 나눠, 한 시스템의 처리 순서가 다른 시스템의 결과를 흔들지 않게 합니다.

## 사건 원장

모든 상태 변경은 다음을 기록합니다.

- 원인 ID와 명령
- 세계 시간
- 변경 주체와 대상
- 변경 전후 요약 해시
- 규칙과 콘텐츠 버전

이 원장을 통해 “왜 노선이 봉쇄되었는가”, “왜 물가가 올랐는가”, “왜 인물이 세력을 떠났는가”를 설명할 수 있습니다. 면담·거래·후계 지지처럼 인물에게 한 일은 [후계, 이름 로스터, 세계 원장](../LORE/Heirs-Names-and-World-Ledger.md)의 미시 줄로만 남고, 합이 임계를 넘을 때 여기 세계 사건이 됩니다. 성명을 고르는 난수는 인물 스트림만 씁니다.

## 저장 파일에 담는 것

저장 파일에는 판본이 붙은 세계 상태, 명령·사건의 위치, 콘텐츠 판본과 진행 중인 전투의 확정 체크포인트를 담습니다. 체크포인트에는 불변 전투 컨텍스트, 일시정지·재개 상태, 결정론적 수락 순서가 붙은 명령 기록과 정산 영수증을 포함합니다. 먼저 임시 파일에 쓰고 검사값을 확인한 뒤 원본과 바꿉니다.

지원하지 않는 버전, 잘린 파일, 잘못된 체크섬은 조용히 읽지 않습니다. 명확한 오류를 반환하고 이전 백업을 보존합니다.

## 전투 중 저장하는 때

- 전투 컨텍스트 발행 전
- 전투 상태와 수락된 명령 기록이 함께 확정된 체크포인트
- 결과 정산 완료 뒤

중간 저장을 읽을 때 캠페인을 다시 조회하지 않고 저장된 불변 컨텍스트와 수락된 전투 명령 기록을 복원합니다. 일시정지 중 확인된 교체 명령은 재개 뒤 다음 시뮬레이션 스텝에서 같은 순서로 적용되어야 합니다. 저장은 실시간 전투에 턴이나 새 시간 간격을 만들지 않습니다. 같은 체크포인트와 명령 기록은 같은 결과와 검사값을 내야 합니다.
