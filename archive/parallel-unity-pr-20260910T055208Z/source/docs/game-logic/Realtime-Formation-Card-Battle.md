# 실시간 진형·카드 전투

![한 판의 실시간 진형 카드 전투 위치 방향 시야 규칙](https://github.com/islee23520/seoul-kenshi/blob/main/docs/assets/wiki/isometric-realtime-formation-card-battle.svg?raw=true)

여기서 한 판은 확정된 전투 컨텍스트로 시작해 ResultId 하나로 끝나는 실시간 진형·카드 전투 세션 한 번을 뜻합니다. 한 판 안에서 진형·사기·카드 타이밍이 실시간 전술의 핵심 축이며, 위치·방향·시야는 진형 규칙으로 이어집니다.

> 2026-09-07 소유자 결정([Intent](https://github.com/islee23520/seoul-kenshi/blob/main/Intent.md) 결정 3)으로 전투는 턴제 SRPG에서 **실시간 진형·카드 전투**로 확정되었습니다. 이 문서는 승인된 게임 Core 계약을 정의합니다. 현재 런타임은 실시간 전환 단계에 있으며 인물별 카드 소유권과 판정(작업 5)의 결함 수정(명령 별칭, 증원 카드, 소유자 HUD, 캠페인 필터)이 진행 중입니다. 분대 이동과 공격 명령(작업 6), 집계 사상자 표현(작업 7)은 승인된 설계 계약이며 아직 구현 완료 상태가 아닙니다. 목표 형태의 근거는 [Songs of Silence](Ref-Songs-of-Silence.md)와 [라벨렌 전기](Ref-Ravelen-Chronicles.md) 조사입니다.

## 탐색과 같은 문법

전투에 들어가도 카메라나 공간 규칙은 바뀌지 않습니다. 탐색에 쓰던 고정 직교 아이소메트릭 카메라와 1.5m 4방향 타일 격자 위에서 진형이 배치되고 시간은 30Hz 고정 틱으로 흐릅니다. 런타임에서는 D1 드라이버가 프레임당 최대 4스텝을 진행합니다. 일시정지 중에도 유효한 카드를 낼 수 있습니다. 전투 초기화는 정산 전에 현재 전투만 시작 상태로 되돌리며, 캠페인 진행이나 이미 반영한 정산을 되돌리지 않습니다.

## 플레이어가 하는 일

플레이어는 개별 병사를 직접 조작하지 않고 분대 단위 명령과 카드 타이밍을 다룹니다.

1. **전투 전 진형 편집**: 전열, 후열, 측면에 분대를 배치하고 4방향 정면을 정합니다. 리더의 지휘 반경(3칸) 안에 있는 인물만 카드와 협공 대상이 됩니다.
2. **전투 중 카드 발동**: 인물별 카드 `(OwnerUnitId, CardId)`와 출격 전 선택한 거점 카드(최대 2장)를 각 카드의 재충전 주기에 맞춰 냅니다. 기동 재집결은 600틱이며, 전체 카드의 재충전은 300~900틱입니다. 덱 구축이나 무작위 드로우는 없습니다.
3. **분대 지시와 제어**: actor 기반 분대 이동(Move), 목표 적 지정 공격(Attack), 방향 전환(SetFacing)을 내립니다. 일시정지, 줌, 전투 리셋으로 전황을 통제합니다.
4. **후퇴 및 항복 판단**: 사기가 0이 되어 궤주하기 전에 물러나거나, 적 지휘관의 사기, 체력, 퇴로 조건이 충족될 때 항복을 받아냅니다.

## 승인된 Core 계약

### A. 인물 카드 소유권과 명령 계약
- **카드 상태 분리**: 인물 카드는 `(OwnerUnitId, CardId)` 쌍으로 상태를 관리하며 소유자마다 독립된 재충전 타이머를 가집니다. 재충전 길이는 기존 카드별 값을 유지합니다: 방패벽 300틱, 격려 600틱, 협공 450틱, 기동 재집결 600틱. 공유 거점 카드인 보급과 통행은 각각 900틱과 750틱입니다.
- **명령 주체 명시**: 분대 명령(Move, Attack, SetFacing)은 실행 주체(`actor`)와 목표 위치 또는 대상 `UnitId`를 명확히 지정합니다.
- **거점 카드 공유**: 거점 카드는 최대 2슬롯이며 아군 분대 전체가 공유합니다.
- **순수 판정과 실행 분리**: 미리보기(Preview)는 상태를 변경하지 않는 순수 판정으로 동작합니다. 확정(Submit) 시점에 유효성을 다시 검증하고 한 번만 반영합니다.
- **리플레이 버전 관리**: 규칙 버전을 명확히 구분하며 이전 소유자 없는 리플레이(ownerless replay)는 재생 전 버전 오류를 명시해 거부합니다. 원본 파일 자동 변환이나 삭제는 하지 않습니다.

### B. 집계 생존수와 사상자 계약
- **분대 구성과 뷰**: 초기 편성은 양측 6개 논리 분대(총 12분대)이며 증원은 별도로 추가됩니다. 각 분대는 4명의 병사 뷰와 1명의 중앙 리더로 표현됩니다. 리더는 연출용이며 별도 전투 HP나 정산 ID를 갖지 않습니다.
- **0..4 집계 생존수**: 초기 생존수는 `ceil(4 * 시작Hp / MaxHp)`로 정합니다(Hp가 0이면 0). 이후에는 아래 피해 규칙으로 갱신한 집계 상태를 표시하며, 매번 현재 HP로 다시 계산해 치료를 부활로 바꾸지 않습니다.
- **단조 감소**: 피해를 입을 때 생존 수는 `min(이전 생존수, ceil(4 * 현재Hp / MaxHp))`로 줄어들며 치료를 받아도 쓰러진 병사가 부활하지 않습니다.
- **독립 증원**: 증원 병력은 기존 분대의 인원 회복이 아니라 고유 초기 HP를 가진 별도 분대로 전장에 진입합니다.
- **정산 불변**: 정산과 결과 기록은 기존 논리 `UnitId`와 남은 `HP`를 기준으로 단 1회(exactly-once) `ResultId`와 함께 확정됩니다.

## 전투에서 다루는 것

- 진형(전열, 후열, 측면)과 4방향 정면, 지휘 반경(3칸)
- 6v6 논리 분대(분대당 4병사 뷰와 중앙 리더)
- 사기 게이지, 0에 도달하면 명령이 잠기고 궤주가 시작됩니다
- 인물 카드(관계, 생업, 특기)와 거점 카드(보급, 통행권, 설비)
- 지형 비용과 엄폐, 장치(수문, 문, 신호) 조작
- 예고된 증원 위치와 위협 표시
- 부상, 쓰러짐, 포획, 후퇴, 항복과 사망
- 일시정지, 시점 줌, 전투 시작 상태로의 리셋

## 전장의 기본 형태

| 원형 | 전술 특징 |
|---|---|
| 작은 역사 | 기둥과 상점, 짧은 교전 거리, 좁은 전열 |
| 환승역 | 층 전환, 여러 입구, 측면 노출과 증원 경로 |
| 종착역 | 막힌 끝, 넓은 승강장, 차량 엄폐 |
| 터널 | 한 줄 진형, 긴 시야, 퇴로 위험 |
| 지상 폐허 | 넓은 시야, 환경 노출, 기동 카드 유리 |
| 차량기지 인접 | 대형 설비, 수리 목표, 다중 경로 |
| 한강 횡단 구간 | 제한된 연결, 붕괴와 침수 위험 |

## 같은 상황은 같은 결과로

실시간 환경에서도 결정론 계약은 엄격히 유지됩니다. 전장 생성, 명중, 피해, 사기, 증원과 카드 플레이는 전투 시드와 틱 스탬프가 붙은 명령 기록으로 완벽히 재현되어야 합니다.

- 시뮬레이션은 30Hz 고정 간격으로 진행됩니다.
- D1 드라이버만 `BattleSim.Step`을 호출하며 한 프레임에 최대 4스텝까지 처리합니다.
- UI의 시각 이동(Transform)은 게임 Core의 논리 위치를 따라 표현합니다. 화면에서만 분대를 이동시켜 Core의 이동 판정을 대신하지 않습니다.
- 동일한 입력 기록이 다른 결과를 내면 검증 실패입니다.

## 현재 구현 상태와 계약 경계

- **Core 계약 승인**: A(인물별 카드 소유권 및 명령)와 B(0..4 집계 생존수) 계약이 승인되어 본 문서에 반영되었습니다.
- **작업 5 진행 중 (NEEDS-FIX)**: 인물별 카드 소유권과 순수 판정 공유 로직은 현재 결함 수정 단계입니다 (명령 별칭, 증원 카드 처리, 소유자 HUD 연결, 캠페인 필터링 오차).
- **작업 6 미완료**: 분대 Move/Attack 및 방향 명령은 승인된 계약이며 구현 완료되지 않았습니다.
- **작업 7 미완료**: 집계 생존수 및 사상자 처리는 승인된 계약이며 구현 완료되지 않았습니다.
