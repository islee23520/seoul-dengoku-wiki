# 실시간 부대 지휘 전투 규칙

> 출처: `GDD/rules/Realtime-Formation-Card-Battle.md`, `GDD/rules/Strategy-Battle-Roundtrip.md`, `GDD/rules/Warfare-and-Sieges.md` — 현재 목표와 2026-09-07 카드 전투 POC 기록을 구분한다.

## 개요

한 판은 참가자, 전장, 목표, 보급, 합법 퇴로와 증원 조건이 확정된 닫힌 전투 컨텍스트로 시작해 불변 `ResultId` 하나로 끝난다.
전장의 명령 대상은 이름 있는 영웅 액터와 일반 병사 분대다. 플레이어는 둘을 각각 부대 단위로 선택해 현재 지시를 교체하며, 영웅의 공격 연계나 회피를 직접 조작하지 않는다.
병사 분대는 병사 최대 20명이며 영웅은 별도 전술 액터라 이 20명에 포함되지 않는다.
3D 자유 지휘 카메라와 파티 전투에 한정된 일시정지 명령은 질문 시간 초과 뒤 채택한 권장 설계 기본값이며 소유자가 직접 확정한 결정이 아니다.

## 조항

### RBATTLE-01 한 판의 경계

한 판은 참가자, 전장, 목표, 보급, 합법 퇴로와 증원 조건이 확정된 전투 컨텍스트로 시작한다.
끝은 일반 승리·패배, 명령 철수, 사기 패주, 수락된 항복 가운데 하나를 담은 불변 `ResultId` 하나다.
캠페인은 같은 `ResultId`를 정확히 한 번만 정산한다.

### RBATTLE-02 공간과 카메라

목표 전투 카메라는 3D 자유 지휘 시점이다.
플레이어는 전장을 팬·오빗·줌으로 살피며 특정 각도, 높이, 시야각 수치를 새로 고정하지 않는다.
상단 전장 도식은 위치와 상호작용을 설명하는 문서용 청사진이지 실제 게임 렌더 화면이 아니다.

### RBATTLE-03 시뮬레이션과 일시정지

시뮬레이션은 고정된 규칙 간격으로 진행하되 새 실시간 이동·속도 수치는 이 문서에서 만들지 않는다.
일시정지는 이 파티의 닫힌 전투 세션만 멈추며 공유 캠페인 월드, 세계 시간과 다른 파티의 이동·전투를 멈추지 않는다.
감속과 배속은 두지 않는다.

### RBATTLE-04 명령 단위

명령 단위는 이름 있는 영웅 액터와 일반 병사 분대다.
영웅 액터와 병사 분대를 각각 선택하거나 함께 선택한 뒤 이동, 공격, 방향 전환, 진형 변경, 정지, 철수 가운데 하나를 지시한다.
영웅에게도 부대 명령을 내리되 이동·공격·회피 연계 같은 직접 액션 조작은 하지 않는다.
선택하지 않은 상태에서는 명령을 확정할 수 없다.

### RBATTLE-05 진형과 정면

전투 전이나 허용된 재편 상태에서 진형과 정면을 정한다.
명령 전에 경로, 목표와 도착 진형을 미리 보며, 확정한 새 지시는 선택한 부대의 현재 지시를 교체한다.
여러 지시를 쌓는 큐, 웨이포인트 연쇄와 순서 편집은 두지 않는다.

### RBATTLE-06 참가 부대

캠페인 파티 가운데 실제로 전투에 참가한 이름 있는 영웅은 각각 별도 전술 액터가 되고, 일반 병력은 병사 분대로 편성한다.
병사 분대 하나의 병사 수는 최대 20명이다. 영웅은 병사 분대의 20명에 포함되지 않는다.
군단 전체 상한, 분대 최소 인원, 분대 수, 영웅 수는 정하지 않으며, 증원은 전투 컨텍스트에 확정된 조건으로만 들어온다.

### RBATTLE-07 영웅과 병사 분대

영웅 액터의 생사, 부상, 장비와 신병 결과는 캠페인이 소유하는 인물 ID에 남긴다.
병사 분대와 영웅 액터는 전장에서 서로 다른 명령 대상이며, 영웅을 병사 분대의 인원으로 합치지 않는다.
영웅 분리 규칙을 개별 영웅의 이동·공격·회피 연속 입력이나 초인적 직접 액션으로 바꾸지 않는다.

### RBATTLE-08 전투 사실

전투 결과는 종료 상태, 흐른 시간, 인물의 생사, 새 부상, 장비 소모, 전리품, 파티의 퇴로와 거점 통제 변화를 기록한다.
전투 화면의 표현이 이 캠페인 사실을 대신하지 않는다.

### RBATTLE-09 신병 처리

포획은 전투 종료 상태가 아니라 전투 뒤 인물별 신병 처리에서 생기는 구금 결과다.
항복자, 패주자, 부상자나 생존자를 자동으로 모두 포로로 바꾸지 않는다.
새 포획 확률, 수용 정원이나 수치를 만들지 않는다.

### RBATTLE-10 부대 명령

부대 명령은 선택한 영웅 액터 또는 병사 분대와 이동·공격·방향·진형·정지·철수 가운데 하나를 명시한다.
확인한 새 명령은 해당 영웅 액터나 병사 분대의 현재 지시를 교체한다.
카드 자원, 덱, 무작위 드로우, 영웅 직접 액션 조작과 영웅 능력 자원은 목표 범위가 아니다.

### RBATTLE-11 수락 기록

확정한 지시만 결정론적 수락 순서와 함께 명령 기록에 들어간다.
취소한 미리보기는 기록도 상태도 바꾸지 않고 기존 지시를 유지한다.
같은 부대에 나중에 확정한 지시는 앞선 현재 지시를 교체하며 별도 명령 큐를 만들지 않는다.

### RBATTLE-12 재개 적용

일시정지 중에도 부대를 선택하고 명령을 미리 본 뒤 확인하거나 취소할 수 있다.
일시정지 중 수락된 교체 명령은 재개 뒤 다음 시뮬레이션 스텝에서 결정론적 수락 순서대로 적용한다.

### RBATTLE-13 미리보기와 확정

미리보기와 확정은 같은 불변 전투 컨텍스트로 유효성을 검사한다.
미리보기는 상태를 바꾸지 않으며, 확정 시 다시 검사해 한 번만 반영한다.

### RBATTLE-14 사기

사기는 전투 종료 원인과 손실에 영향을 줄 수 있지만 새 목표의 임계 수치는 이 문서에서 만들지 않는다.
사기가 무너져 지휘 통제를 잃은 이탈은 사기 패주로 기록한다.

### RBATTLE-15 철수·패주·항복

명령 철수는 플레이어가 지시하고 확인하며 철수 중에도 지휘가 유지되는 종료다. `LegalFallback`을 통과한 경로가 있어야 성립한다.
사기 패주는 결속 붕괴로 통제를 잃은 비자발 이탈이며 합법 경로를 고르는 명령 철수와 구분한다.
항복은 한쪽이 제안하고 상대가 받아들여야 성립한다. 퇴로 봉쇄나 `LegalFallback` 실패만으로 항복 선택을 없애지 않는다.

### RBATTLE-16 결정론

전장 생성, 명중, 피해, 사기와 증원은 전투 시드, 불변 컨텍스트와 수락된 명령 기록으로 재현한다.
동일한 컨텍스트와 수락된 명령 기록이 다른 결과를 내면 검증 실패다.

### RBATTLE-17 규칙 버전

전투 컨텍스트와 결과에는 규칙과 콘텐츠 버전을 기록한다.
지원하지 않는 버전은 명확한 오류로 거부하며 원본 기록을 자동 변환하거나 삭제하지 않는다.

### RBATTLE-18 정산

`ResultId`와 전투 사실은 단 한 번 확정한다.
이미 처리한 결과가 다시 들어오면 기존 영수증만 돌려주고, 같은 전투에 충돌하는 결과가 들어오면 세계를 바꾸지 않고 복구 오류를 낸다.
정산은 귀환 명령이 아니며 결과 반영 뒤 원정을 계속할 수 있다.

### RBATTLE-19 리셋 범위

전투 초기화는 정산 전에 현재 닫힌 전투 세션만 시작 상태로 되돌린다.
캠페인 진행과 이미 반영한 결과를 되돌리는 수단으로 쓰지 않는다.

### RBATTLE-20 표현과 코어

UI의 시각 이동은 Core의 논리 상태를 따라 표현한다.
화면에서만 부대를 움직여 Core의 이동 판정이나 수락된 명령을 대신하지 않는다.

### RBATTLE-21 증원

증원은 전투 시작 시 확정된 증원 조건에 따라 별도 전력으로 진입한다.
바깥 캠페인 상태를 전투 도중 다시 조회해 증원을 바꾸지 않는다.

### RBATTLE-22 속도 수치

현재 목표에는 실시간 이동 틱, 공격 쿨다운, 전투 시간 상한이나 카드 재충전 수치를 새로 정하지 않는다.
그 수치들은 아래 2026-09-07 카드 전투 POC 기록에만 보존한다.

## 판정 순서

1. 참가자, 전장, 목표, 보급, 합법 퇴로, 증원 조건, 전투 시드와 규칙·콘텐츠 버전을 불변 컨텍스트로 확정한다.
2. 실제 참가 영웅은 별도 전술 액터로 두고 일반 병력은 병사 최대 20명의 분대로 편성한 뒤 전투 전 진형과 정면을 정한다.
3. 플레이어가 영웅 액터나 병사 분대를 선택한 경우에만 이동·공격·방향·진형·정지·철수 명령을 연다.
4. 경로·목표·도착 진형 미리보기는 상태를 바꾸지 않는다.
5. 확정 때 같은 컨텍스트로 다시 검사하고, 새 지시로 현재 지시를 교체해 수락 순서를 기록한다.
6. 일시정지 중 확정한 지시는 재개 뒤 다음 시뮬레이션 스텝에서 수락 순서대로 적용한다.
7. 전장 생성, 명중, 피해, 사기와 증원을 시드와 수락된 명령 기록으로 진행한다.
8. 종료 원인을 일반 승리·패배, 명령 철수, 사기 패주, 수락된 항복 가운데 하나로 구분한다.
9. 포획 여부는 종료 상태와 분리해 인물별 신병 결과에 기록한다.
10. 전투 사실과 불변 `ResultId`를 한 번 발행하고 캠페인이 정확히 한 번 정산한다.
11. 정산 뒤 원정을 계속하거나 귀환·정착·정복·방랑·교역 가운데 다음 결말을 고른다.

## 금지 사항

- 개별 영웅의 이동·공격·회피 연계나 콤보를 직접 조작하는 일
- 영웅을 병사 분대의 20명에 포함하거나 병사 분대를 20명보다 크게 편성하는 일
- 군단 전체 상한, 분대 최소 인원, 분대 수, 영웅 수를 새로 정하는 일
- 영웅 능력 자원이나 별도 특수 밸런스를 만드는 일
- 카드, 덱, 무작위 드로우, 자원 소비나 재충전을 현재 목표 명령으로 두는 일
- 선택하지 않은 상태에서 명령을 확정하는 일
- 명령 큐, 웨이포인트 연쇄, 순서 편집, 감속·배속을 추가하는 일
- 미리보기나 취소가 상태 또는 수락 기록을 바꾸는 일
- 일시정지로 공유 캠페인 월드나 다른 파티를 멈추는 일
- `LegalFallback` 실패를 질서 있는 명령 철수로 처리하는 일
- 퇴로 봉쇄만으로 항복 선택을 없애는 일
- 명령 철수, 사기 패주, 수락된 항복과 포획을 같은 상태로 처리하는 일
- 항복자·패주자·부상자·생존자를 자동 포획하는 일
- 전투 도중 캠페인 상태를 다시 조회하는 일
- UI 표현으로 Core 판정을 대신하는 일
- 전투 리셋으로 캠페인 진행이나 이미 반영한 결과를 되돌리는 일
- 같은 `ResultId`를 두 번 반영하는 일
- 결과 반영을 강제 귀환으로 처리하는 일
- 동일 입력이 다른 결과를 내는 일
- 새 실시간 이동 공식을 발명하는 일

## 2026-09-07 카드 전투 POC 역사

### POC 공간·드라이버·명령

- 고정 직교 아이소메트릭 카메라와 1.5m 4방향 타일 격자 위에 진형을 놓았다. 이후 화면은 좌우 사이드스크롤 POC로 기록됐다.
- 30Hz 고정 틱, 프레임당 최대 4스텝의 D1 드라이버를 썼다. 일시정지는 해시 입력에서 제외했다.
- POC 표시 예시에서는 초기 편성이 양측 6개 논리 분대, 총 12분대였고 증원은 별도로 붙었다. 각 예시 분대는 병사 뷰 4명과 중앙 리더 1명으로 보였다. 이는 현재 목표의 분대 수나 영웅 포함 규칙이 아니다.
- 리더는 연출용으로 별도 전투 HP와 정산 ID가 없었다.
- 분대 명령 `Move`, `Attack`, `SetFacing`은 실행 주체와 목표 위치 또는 대상 `UnitId`를 지정했다.
- 전열·후열·측면과 4방향 정면을 사용했고 지휘 반경은 3칸이었다. 반경 밖 인물은 카드와 협공 대상이 아니었다.

### POC 카드 소유권·재충전

- 인물 카드 상태는 `(OwnerUnitId, CardId)` 쌍으로 관리했고 소유자마다 재충전 타이머가 독립이었다. 덱 구축과 무작위 드로우는 없었다.
- 거점 카드는 아군 분대가 공유하는 최대 2슬롯이었다.
- 방패벽 300틱, 격려 600틱, 협공 450틱, 기동 재집결 600틱을 소유자별로 유지했다.
- 보급은 900틱, 통행은 750틱이며 효과 지속은 150틱이었다.
- 미리보기는 상태를 바꾸지 않았고 확정 때 다시 검사해 한 번 반영했다.

### POC 집계 생존수·정산 공식

- 집계 생존수 범위는 0부터 4였다.
- 초기 생존수는 `ceil(4 * 시작Hp / MaxHp)`로 열었고 시작 HP가 0이면 0이었다.
- 피해 뒤 생존수는 `min(이전 생존수, ceil(4 * 현재Hp / MaxHp))`로 단조 감소했다.
- 치료를 받아도 쓰러진 병사는 부활하지 않았다.
- 증원은 기존 분대 인원 회복이 아니라 고유 초기 HP를 가진 별도 분대로 들어왔다.
- 정산은 기존 논리 `UnitId`와 남은 `HP`를 기준으로 `ResultId`와 함께 한 번 확정했다.

### POC 사기·항복·시간 상한

- 기본 사기는 60, 경고선은 40, 회복 상한은 80이었다.
- 초당 회복 5, 사망당 손실 5, 지휘관 HP 절반 이하 손실 10을 적용했다.
- 사기 20 이하, 지휘관 HP 50% 이하와 열린 퇴로가 모두 참일 때만 항복이 성립했다.
- 지휘관 타일 점거는 퇴로 차단과 같지 않았고 후퇴 판단은 사기 경고선 40을 넘기기 전에 두었다.
- 칸 이동은 10틱, 공격 쿨다운은 30틱, 한 판 상한은 9000틱이었다.

이 항복 수치 결합은 현재 목표의 항복 조건이 아니다. 현재 목표에서는 `LegalFallback` 실패가 명령 철수만 막으며 항복 선택을 없애지 않는다.

### POC 리플레이·리셋·구현 상태

- 규칙 버전은 `rtfc-owner-cards-v2`였다. 소유자 정보가 없는 이전 리플레이는 규칙 버전 오류로 거부했고 원본을 자동 변환하거나 삭제하지 않았다.
- 전투 초기화는 정산 전에 현재 전투만 시작 상태로 되돌리고 캠페인 진행과 이미 반영한 정산은 건드리지 않았다.
- 카드 소유권과 순수 판정 로직의 원본 62개 사례, 소유자 상대 지휘 반경 수정 1개 사례가 검증됐다. 최초 진형 버튼의 Raycast/EventSystem 문제는 남았다.
- 분대 Move/Attack과 방향 명령은 추가 반례 테스트 전 결과만 있어 최종 검증 상태가 보류됐다.
- 집계 생존수와 사상자 처리는 승인됐지만 구현 완료되지 않았다.
- Foundation raycast depth -1 원인은 해결되지 않았다. 원본 SVG 사용 가능 여부는 캐릭터·타이틀·아이콘·역사 텍스처의 권리와 외형 검토를 대신하지 않는다.
