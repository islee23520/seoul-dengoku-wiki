# 후계, 이름 로스터, 세계 원장

이름 있는 인물이 죽거나 자리를 비우면 빈 직위만 남지 않는다. 후계자·신임 실무자·새로 붙는 친족은 [작명 원칙](../characters/Core-Characters.md)을 지키는 성명으로 생성된다. 성씨와 이름은 문화 로스터에서 고른다. 플레이어의 면담·거래·지지·호송은 인물 단위 기록만 남기고, 그 기록이 임계를 넘을 때 [사건 원장](../../GDD/rules/Save-and-Determinism.md)이 거점·물가·통행·정통성을 바꾼다.

이 문서는 후계 생성의 목표 규칙이다. 현재 총람 422명 가운데 상세 인물 본문이 있는 412명과 총람만 있는 10명을 구분하며, 이미 붙인 이름을 다시 짓지 않는다. `tools/cast/generate_nemotron_roster.py`의 후보 샘플링은 아래 후계·관계·저장 기능의 구현 완료를 뜻하지 않는다.

## 문화 키

작명 문화는 국가 ID가 아니라 권역 키로 읽힌다. 국가가 병합되거나 국호가 바뀌어도 키는 남는다.

| 키 | 권역 | 쓰는 국가(개막) |
|---|---|---|
| `west-sluice` | 서부 수문 | 수문국, 규격맹, 태욱그룹, 여의도출자연합회 |
| `center-record` | 중앙 기록·철도 | 대한민국정부, 환적국, 원불교, 명부교회 |
| `north-refuge` | 북부 피난 | 안국총림, 성하그룹 |
| `east-caravan` | 동부 상단 | 동방사, 신내운수, 흰십자단, 아관사 |
| `southeast-ration` | 동남 배급 | 명동대교구, 정동노동총연맹 |

위 `CultureKey`는 서울 권역별 작명 후보를 묶기 위한 게임 키다. 국적·민족적 배경·언어·본관을 대신하지 않는다. 이직이나 국가 병합으로 기존 이름과 가계 정보를 바꾸지 않는다. 보호자·양자 관계를 새로 설정할 때도 이름 유지·계승 규칙을 별도로 기록하며, 입적 국가만으로 본관을 부여하지 않는다.

## 로스터 칸

성, 남성 이름, 여성 이름은 파일을 나눈다. 권역 키는 문화 키 표를 따른다.

- [surnames.json](../name-pools/surnames.json) — 성. 한 글자
- [given-male.json](../name-pools/given-male.json) — 남성 이름
- [given-female.json](../name-pools/given-female.json) — 여성 이름
- `given-open` — 성별을 가리지 않을 때만. 후계 생성 기본
- [clans-hangnyeol.json](../name-pools/clans-hangnyeol.json) — 본관명과 창작 글자 순서를 붙인 실험용 시드. 실존 문중 항렬표가 아닙니다. 목표 계약과 현재 구현의 차이는 [본관과 항렬](../characters/Hangnyeol-and-Bon-gwan.md)에 둔다.

한국어 이름 후보의 기본 표기는 `성 + 이름`이다. 다른 작명 전통은 해당 문화의 원표기와 읽는 법을 보존한다. 항렬 적용은 가족관계에서 확인한 세수와 글자·위치 규칙을 따르며 연령대로 계산하지 않는다. 현재 생성기의 앞글자 덮어쓰기는 이 목표 계약을 충족하지 못한다. 실존 인물이나 원작 인물을 그대로 옮긴 이름·전기를 새 창작 인물로 등록하지 않는다.

권역당 성 12개·통용 이름 24개·성별 각 8개라는 초기 용량안은 현재 공통 JSON 풀과 일치하지 않는다. 권역별 풀의 크기와 갱신 정책은 구현 전에 별도로 검증한다. 승인된 풀을 소진하면 후보 생성을 거부하고 직위는 공석으로 두는 목표는 유지한다.

## 이름을 고르는 순서

1. 대상의 `CultureKey`를 읽는다.
2. 성씨 풀에서 성을 고른다. 같은 국가에 같은 성씨가 있다는 이유로 배제하지 않는다. 결정 난수는 [같은 선택이 같은 결과가 되나](../../GDD/rules/Save-and-Determinism.md)의 인물 스트림만 사용한다.
3. 남성·여성 이름 풀을 분리해 사용하고, 통용 이름 정책이 필요한 경우 별도로 선택한다. 항렬·자배·통자는 [본관과 항렬](../characters/Hangnyeol-and-Bon-gwan.md)을 따른다. 추가 100명은 [랜덤 추가 로스터](../characters/Random-Cast-Roster.md)의 미검토 후보로 남아 있다.
4. `성+이름`이 전 세계 생존·사망 기록과 같으면 3으로 돌아간다. 8번 실패하면 생성을 거부한다.
5. 새 인물 ID, 성명, 키, 출생 틱을 원장에 쓴다.

위 순서는 목표 동작이다. 현재 샘플 생성기는 24회 재시도와 별도 이름 집합을 사용하므로 8회 제한·전 세계 생사 기록·가계 항렬·저장 연동이 구현됐다고 보고하지 않는다. 기존 캐스트 이름은 유지하고 새 후보의 충돌만 검토한다.

## 후계가 생기는 때

[야망](../characters/Ambitions-and-Relations.md)의 계승 순서는 그대로다. 지정 후계, 대행자, 추대, 친족·양자, 사제·도제, 길드 추천, 거점 통제.

바뀌는 점은 하나다. 순서를 따라갔는데 이름 있는 후보가 없고, 그 직위가 이름 있는 인물을 요구하면, 위 로스터로 후계 후보를 한 명 생성한다. 생성 실패 시 직위는 공석이다. 대행자·관리인만으로 버틸 수 있는 자리는 생성하지 않는다.

생성되는 인물은 다음을 갖는다.

- 성명과 `CultureKey`
- 보호자 또는 추천자와의 관계 한 줄(양자, 도제, 길드, 친족 중 하나)
- 야망·공포는 보호자 직능에서 그대로 가져오지 않고 [인물 카드 계약](../characters/Cast-Profile-Contract.md)에 맞춰 검토한다. 근거가 없는 이력은 미확인, 새로 설정할 내용은 창작 제안으로 남긴다. 생업 한 칸만 채운 후보를 완성 인물로 등록하지 않는다.

플레이어가 후계를 지명하면 로스터를 건너뛰고 그 인물을 쓴다. 지명 대상이 다른 문화 키여도 성명은 바꾸지 않는다.

## 미시 기록

플레이어가 인물에게 하는 일은 국가 수치를 바로 건드리지 않는다. 아래만 기록한다.

| 행위 | 기록 종류 | 대상 |
|---|---|---|
| 면담 | `talk` | 인물 |
| 물자·통행·포로·기록 거래 | `trade` | 인물 또는 직위 |
| 후계 공개 지지·실격 | `heir-stance` | 후보 |
| 조약 호송 | `escort` | 서명자 |
| 소문 반증·폭로 | `rumour` | 인물 또는 직위 |
| 쿠데타 지원·경고 | `plot` | 주도자 |

한 줄에는 원인 ID, 세계 시간, 주체, 대상, 크기, 규칙 판본이 들어간다. 크기는 정수다. 신뢰·정통성 슬라이더를 직접 올리는 명령은 없다.

## 거시로 넘어가는 때

원장을 시간순으로 읽어 합이 임계를 넘으면 세계 사건을 한 번만 발행한다. 같은 원인 ID로 두 번 발행하지 않는다.

| 합산 | 임계를 넘기면 |
|---|---|
| 한 인물에 대한 `talk`+`trade` | 그 인물의 제안 수락 범위가 넓어지거나 좁아진다 |
| 한 직위 계승 쟁점의 `heir-stance` | 지정 후계가 바뀌거나 계승 전쟁이 열린다 |
| 한 거점의 `trade` 거절이 쌓임 | 통행 허가 철회, 물가 인상 |
| 한 국가의 `plot` 성공 | 수장 교체. 후계 생성 규칙을 탄다 |
| 여러 국가에 걸친 `rumour` 확정 | 정통성 하락, 협약 재검토 |

세계 사건은 [세력과 외교](../factions/Factions-and-Diplomacy.md), [경제와 생산](../economy/Economy-and-Production.md), [물류와 기반 시설](../economy/Logistics-and-Infrastructure.md)이 읽는 필드만 바꾼다. 전투 격자나 카드 재충전은 건드리지 않는다. 전투 결과는 [전략에서 전투로](../../GDD/rules/Strategy-Battle-Roundtrip.md)가 한 번만 반영한다.

## 저장

성명 로스터의 남은 칸, 이미 쓴 성명, 미시 기록, 아직 안 터진 임계는 저장 파일의 세계 상태에 들어간다. 인물 스트림 난수는 전투·조우 스트림과 섞지 않는다.

지원하지 않는 저장은 이름을 새로 뽑으며 복구하지 않는다. 오류를 내고 이전 파일을 둔다.
