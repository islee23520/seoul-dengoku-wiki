# UI/UX 실제 브라우저 검증 영수증

검증일: 2026-09-19

표면: `GDD/system-design/total-war-ui/`

도구: Aside Browser CLI `aside-agent repl`
버전 표식: `total-war-ui-20260919-v1`

## RED

- 공개 경로 `/total-war-ui/`는 작성 전에 nginx 404였다. 캡처 `screenshots/baseline-public.png`.
- 첫 템플릿 검토에서 세 결함을 실제 조작으로 재현했다.
  1. 류은비 버튼을 눌러도 임초원 선택 상태가 유지됐다.
  2. 퇴로 봉쇄 상태를 취소해도 전투 화면에 봉쇄가 남았다.
  3. `BTW-SW03-EXAMPLE-01`을 반영한 뒤 전투 종료를 다시 확인하면 같은 ID의 반영 버튼이 되살아났다.
- 로그: `ui-regression-red.log`.
- 추가 RED: 경로, 비전투 대응, 배치 부대 버튼이 포커스만 받고 화면 상태는 바꾸지 않았다. 로그 `ui-extra-red.log`.

## GREEN

- 선택 부대 없음일 때 명령 4개 모두 비활성.
- 이동 미리보기 취소는 현재 지시와 수락 기록 수를 유지.
- 이동 확인은 현재 지시를 교체하고 기록 1개 추가.
- 파티 전투를 정지한 동안 공격 명령을 확정해도 즉시 실행하지 않음. 재개 뒤 다음 단계에서 수락 기록에 순서대로 추가되고 현재 지시 교체.
- 선택 해제 뒤 명령 비활성 복귀.
- 퇴로 봉쇄에서 질서 철수만 비활성이고 항복은 선택 가능.
- 수락된 항복과 신병·구금 사실을 별도 표시.
- 결과 반영 뒤 같은 `ResultId` 반영 버튼과 종료 유형 버튼이 잠김. 전투 화면으로 돌아가 종료 확인을 반복해도 기존 영수증을 재표시하고 세계 변경 없음.
- 원정 계속은 귀환을 강제하지 않고 캠페인 경로 화면으로 돌아감.
- 경로 후보, 인물, 배치 부대, 비전투 대응 버튼이 각각 실제 상태를 갱신.

전체 조작 로그: `ui-functional-green.log`, `ui-extra-green.log`, `ui-regression-green.log`.

## 대표 데스크톱 표면 시각 검토

| 화면 | 검증 프레임 | 내부 폭 | 내부 높이 | 가로 넘침 | 세로 |
|---|---:|---:|---:|---|---|
| 캠페인 | 1440×900 | 1440 | 900 | 없음 | 한 화면 |
| 편성 | 1600×1000 | 1600 | 1000 | 없음 | 한 화면 |

| 전투 | 1440×900 | 1425 | 963 | 없음 | 63px 스크롤 |
| 결과 | 1920×1080 | 1920 | 1080 | 없음 | 한 화면 |

2026-09-19 프로젝트 글로벌 규칙에 따라 멀티 플랫폼 지원 기능은 구현·테스트하지 않는다. 규칙 확정 전에 수집한 390×844 캡처는 최종 증거에서 제거했고 수용 근거로 쓰지 않는다. 모바일·브라우저·운영체제별 대응을 위해 추가 수정하지 않는다.

이미지 직접 검토 결과: 빈 화면, 겹침, 잘린 핵심 라벨, 카드 자원 UI, 영웅 액션 바, 무단 완성 아트가 없다. 탑다운 전장 도식은 실제 3D 렌더가 아님을 화면에 적었다. 초상은 정비율 애니메이션풍 아트의 배치 영역을 설명할 뿐 완성 이미지를 위조하지 않는다.

사용자 추가 결정 뒤 대표 데스크톱 전투 화면을 다시 열었다. 영웅 지휘 인물 `H`는 병졸 분대와 별도 목록·전장 토큰으로 보이고 `병졸 수 제외`라고 적힌다. 경비조·정찰조·구호조는 각각 `병졸 8 / 20`, `5 / 20`, `4 / 20`으로 표시되며 모두 상한 이하다. 캡처 `screenshots/ui-hero-squad-desktop.png`. 이 검증은 프로젝트 규칙에 따라 대표 데스크톱 한 표면만 사용했다.

증거: `screenshots/ui-*.png`, `screenshots/battle-command-green.png`, `screenshots/ui-regression-green.png`.
