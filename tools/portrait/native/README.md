# Seoul avatar generator

Whole-canvas replacement accepts `readableFirst: true` to put the deterministic source-bound readable instruction before the unchanged validated design JSON. The transport uses `CHARACTER_ART_BOUND_JSON_V1` and multipart CRLF line endings; parsing, snapshot checks, and pre-dispatch association reject a modified prefix or JSON. This is an opt-in transport change, not an image-quality or owner-approval claim. Build and 32 tests include a real local HTTP multipart roundtrip.

Serial production batches use `lib/batch-review.mjs` before advancing. A provider output alone is insufficient: the current image SHA, permanent character ID, request ID, actual-image inspection and a passing technical verdict must match an explicit review file. Missing reviews, failed requests and unknown responses hold the batch. This gate does not grant owner approval or retry a request.

## Integrated acceptance gate

`PORTRAIT_ACCEPTANCE_CRITERIA` and `evaluatePortraitAcceptance` are public exports. All production calls to `requireBatchReview` now require a profile and measurement file, including callers that previously supplied only a technical verdict. This is a deliberate stricter advancement contract; historical pass records are not automatically upgraded.

The exact image/request-bound review must use `acceptanceSchema:"portrait-integrated-acceptance.v1"` and a `criteria` map containing Q01 through Q10 plus `authoredIdentity`, `approvedPositionIntervals`, `opaqueInterior`, `naturalSilhouette` and `defringe`. Each row requires `{verdict:"pass",scope:"whole-image",imageSHA,evidenceSHA}`. Missing, unknown, failed, region-bounded or stale-image rows hold advancement. `evidenceSHA` identifies a review artifact; the evaluator validates its digest format but does not load that artifact or prove its content. Semantic rows are reviewer assertions, not automated pixel recognition. Position rows require review against the approved positional reference, not merely agreement with a supplied proportion profile.

The evaluator mechanically checks PNG canvas/RGBA, nonempty foreground, transparent background, core-alpha fraction and source-bound measured proportions. It separately reports strict foreground opacity; natural edge alpha is not deleted or made opaque automatically. Whole-image `opaqueInterior` review must distinguish semantic interior from natural edges. Neither integrated technical PASS nor a matching artifact hash grants owner or release approval.

Run `node bin/portrait-acceptance.mjs image.png review.json profile.json measurement.json` for a JSON verdict and exit code0 only on integrated PASS. Missing or invalid artifacts return exit code1. The CLI takes character/request identity from the review; production batch review independently binds them to its dispatch terminal.

## Shared portrait proportions

The public API exports `createProportionProfileFromArtifacts`, `validateSharedProportionProfiles`, and `verifyProportionArtifacts`. Profiles fix a 1024x1536 canvas and common head width/height, face width/height, pupil midpoint Y, head center X and crown Y. Body types retain separate shoulder-joint-span/head-width and visible-torso-span/head-width ratios. Shoulder landmarks are joint centers, not clothing edges; torso endpoints must describe the same cross-section level. Hidden joints must not be inferred from a jacket silhouette.

`createProportionProfileFromArtifacts({commonReference, bodyReference, bodyType, toleranceBytes})` accepts each reference as `{imageBytes, measurementBytes}`. Measurement JSON supplies `imageSHA`, `actualImageMeasured:true`, `canvas:[1024,1536]`, `bodyType`, and `landmarks` containing two-coordinate pixel arrays for `crown`, `chin`, `headLeft`, `headRight`, `faceTop`, `faceLeft`, `faceRight`, `leftPupil`, `rightPupil`, `leftShoulder`, `rightShoulder`, `torsoLeft`, and `torsoRight`. The helper decodes each PNG, checks actual dimensions and image identity, and computes measurement digests from exact bytes. `toleranceBytes` is JSON with explicit `pixels` and `ratio` tolerances; its digest is likewise computed from bytes. Measurements and tolerances require independently established source authority. A matching hash or `actualImageMeasured` flag does not establish measurement truth or owner approval.

`validateSharedProportionProfiles(profiles)` rejects mixed common head/face standards and conflicting references or ratios within one body type. Profiles use sorted-key hashes so generation JSON canonicalization preserves their identity. The lower-level `createProportionProfile` accepts already bound observations; callers must not use it to turn synthetic coordinates into production authority.

A validated generation model may carry `proportionProfile`; whole-canvas preparation accepts the same input field. Compact transport includes numerical profile instructions and retains the profile in the rendering projection and original receipt. Approved positional intervals and natural silhouette containment remain authoritative. A conflicting profile must be corrected before generation, not treated as permission to widen those intervals.

`requireBatchReview(terminal, reviewPath, {profile, measurementPath})` reads the exact output and measurement artifact, verifies their binding and measured proportions, and holds advancement on a failed verdict even when the artwork technical review passes. Profile-bound calls additionally require `naturalSilhouetteVerdict:"pass"` in the same exact image/request-bound review; missing, failed or unverified silhouette verdicts hold advancement. Zero side-border alpha and uniform placement cannot certify naturally completed sleeves: placement can move a source crop edge inside the canvas without restoring missing material. The third argument must be supplied by a proportion-qualified production runner. Historical callers without it are not proportion-qualified. Actual image inspection, independent artwork review and owner acceptance remain separate gates. No production reference, artwork or private approval evidence ships with this package.

Once an HTTP request is about to be dispatched, its exact `.request.json` is retained even if the provider returns an error or the response cannot be obtained. Reusing that output path is rejected; reconciliation must precede any separately numbered request. Local HTTP-failure tests verify evidence retention and one-call behavior.

Inspect preserved batch artifacts without provider calls:

```sh
node bin/portrait-batch-audit.mjs /absolute/path/to/batch-root
```

The auditor checks exclusive request identity, terminal identity, exact image/receipt hashes and request correlation, then reports RGBA core and edge-contact metrics. `corePolicyPass` counts alpha >=250 among nonzero pixels; it is not the original strict foreground-opacity contract. `nonopaqueForegroundPixels` counts all nonzero alpha below255, and `strictOpaqueForegroundPass` requires a nonempty foreground with that count equal to0. The existing `partialAlphaPixels` metric counts alpha below250, not all nonopaque pixels. These separate numeric rules do not determine which pixels belong to semantic foreground or natural antialiased edges. Missing or unknown responses remain nonretryable. Edge pixels do not certify semantic clipping, and numeric alpha checks do not certify defringe or owner approval.

Export complete original-resolution perimeter comparisons:

```sh
node bin/portrait-perimeter-proof.mjs source.png new-proof-directory
```

Every nonzero-alpha pixel touching transparent space or the canvas border is assigned to exactly one source-coordinate tile. Each selected tile is composited onto light/dark backings without resampling. The source SHA and complete boundary coverage count are retained; this creates inspection evidence, not an automatic defringe verdict. Every tile must actually be viewed before a whole-perimeter visual claim.

Prepare a compact model-facing variant without dispatch:

```sh
node bin/portrait-compact-prepare.mjs /absolute/path/to/design.json
```

This command validates a source-bound whole-canvas position contract and retains the exact original design, source/rendering/text hashes, appearance leaves, upload roles, all inner/outer position intervals, boundary and output constraints. It expresses the rendering data once and excludes audit-only hashes from the readable model text. Preparation reports `providerCalls: 0` and `dispatched: false`. Whole-canvas execution can opt into `compactFirst: true`; the original validated JSON stays in the request receipt, and only its recomputed compact text enters multipart. Changed text/hash binding or a modified provider revised prompt is rejected. Compact and readable-first execution are mutually exclusive. Actual local HTTP wire tests cover this path; no framing improvement is implied.

The CLI request uses file names for `lookBytes`, `modeBytes`, `previewBytes`, `packageBytes`, `ruleBytes`, and `sourceImageBytes`. File names are resolved from the caller's working directory. The API accepts Uint8Array bytes directly. JSON duplicate decoded keys are rejected. Output files must not exist. `previewPortrait` requires complete explicit authored slots, ordered reference SHA descriptors, measured native portrait composition and package version; it returns `character-art-2d.v1`. Caller-owned asset bytes can be verified with `resolveSourceAssets(references, {read})`. Its asynchronous `read(descriptor)` returns the exact external bytes matching each SHA. External filesystem package roots use `portrait-package.json` and relative asset paths; they never fall back to a source repository.

`project`, `validateProjection`, and `generationFacing` expose the 19 owner fields with explicit source status, JSON pointers, document hashes and values. Unknown makeup, scene, lighting, camera and color grading remain null. Purpose maps output format; title maps identity name; aspect ratio and orientation derive native canvas; style maps technique references; fidelity anchors preserve ordered references; subject maps recipient, face and body; gaze maps face description and authored composition; hair maps hair; wardrobe maps outfit and accessories; composition and pose map native composition; quality and negative prompt map output constraints. Only exact annotation span markers are stripped. `generationFacing` returns the same native model, never a newly concatenated prompt. It validates source image, original look, preview, package and rule hashes before accepting the projection.

`modeToken` retains the minimal source-preserving adapter for compatibility. Production `fullbodyTokens` and `partTokens` reject missing authored mode canvas, pose or coverage. Every mode uses the exact same identity/schema/slot snapshot. Fullbody requires complete authored lower garment and footwear, and assembles actual identity, slots, canvas, pose and coverage separately from portrait framing. It does not submit fullbody to the portrait-only image contract.

Mode documents use `avatar-mode-source.v1`, mode `fullbody` or `3Dparts`, characterId, lookId, inputSnapshotSHA, and the four fields canvas, pose, coverage, parts. Each non-null field is `{value,status,source}` with an explicit authored source. Canvas is `{width,height,unit:"px"}`. Coverage value maps each requested part to `{visibility:"visible"|"occluded"|"unknown",geometry:null|{value,status,source}}`. Geometry null exports an explicit unknown constraint, not inferred hidden anatomy. Fullbody coverage requires head, hair, body, upper, lower, footwear and equipment.

For 3Dparts, parts is an authored unique array of those seven allowed labels. Pose value is `{coordinateSystem,unit:"m"|"cm"|"mm",anchors}`; every requested part requires `{parent:null|partLabel,anchor,position:[x,y,z]}` in anchors. Missing anchors, cycles, unknown parts and invalid units fail. Stable part IDs bind character/look/part; content hashes bind part-specific slots, source snapshots, attachment coordinates and visibility. Head routes only face; hair only hair; body only body including independent skin; upper routes upper/neckline/marks; lower and footwear route their named garment; equipment routes accessories and headwear. No skin or hair transfers into clothing. Token output is not mesh generation. No Blender or Tripo execution is exposed.

Portrait `generatePortrait` executes native HTTP transport with explicit connection configuration and actual images, verifies output PNG dimensions and transparency, and records unreviewed candidate receipts. Keys are supplied by an environment variable named in caller configuration; no machine credential discovery is used. Tests exercise only a local loopback provider. No production visual approval is implied.

`modifyPortrait` retains native source/mask/contract snapshot checks and pixel-preservation validation. Missing-fabric contracts truthfully use fabricPresent false and fabricationCase missing-fabric, activating only upper; neckline remains protected. Existing-fabric contracts retain upper and neckline activation. No unsupported source canvas is resized as a workaround. The native portrait contract does not support arbitrary source dimensions, and provider/mask visual proof is still required for real artwork. Token modification (`composeModificationRequest`) is separate from source image modification.

## Complete source replacement

`clothingPolicy` uses schema `avatar-clothing-policy.v1` and five separately sourced fields: `eraBaseline` (`WWII-era`), `tier` (`high`/`other`), `tierLayerPreference` (`thin-light`/`unspecified`), `surfaceExposure` (`frequent`/`underground`/`occasional`), and `winterProtection` (`warm-outer-layer`/`not-required-by-exposure`/`unresolved`). Each field has value/status/source, with strict discriminated provenance: `canonical-document:{kind,documentSHA,jsonPointer,value}` or `owner-event:{kind,eventId,eventSHA,textRange,normalizedValue,operatorPinnedEventRegistrySHA}`. Owner prose does not require invented JSON records or canon edits. Unknown is exactly `{value:null,status:"unknown",source:null}`; absent clothingPolicy becomes five explicit unknowns, not a generation ban. Unknown exposure prevents weather-specific clothing PASS but permits preview and independently authored garment preservation without an invented coat or exposure.

API trust supplies `readClothingSource(documentSHA)` for exact canonical byte/pointer/value checks. Owner prose uses separate operator-owned `clothingEventRegistry:{bytes,sha256}` and `readOwnerEvent(eventId)`. A closed `clothing-owner-event-registry.v1` pins each approved field/eventSHA/textRange/normalizedValue mapping. The actual user event bytes, ID, role and nonempty in-range text are verified; a candidate cannot choose its own registry pin. No thickness number or surface inference from rank/occupation is accepted. The output receipt keeps clothing status UNVERIFIED; all100 acceptance still needs applicable weather proof.

High tier requires thin/light base-layer preference. Frequent surface exposure requires warm outer protection even at high tier; occupation construction and explicit Catholic/Presbyterian identity remain beneath that weather layer. Underground-only exposure does not force a coat. No real military insignia, company logos, or invented country uniform is added. Clothing fields enter the same native readable projection and scope hash, not a second prompt stack. K028 tier/exposure remain unknown until exact canonical findings arrive; no inferred policy is inserted into prepared files. Known source bindings use the operator reader API context.

`tier` also accepts the exact sourced textual rank leaf, without conversion to numeric/high/other. K028's `품계: 주사` is a canonical fact, not an automatically high-tier classification. The thin/light conflict rule applies only when a separately sourced value explicitly says `high`. K028 surface frequency remains UNKNOWN; its office and document-transport activity do not establish underground-only or surface frequency. State-concept proposals are not approved clothing inputs and do not propagate into the roster or prior portraits.

The native composer derives `completeSource.readableProjection` from validated JSON: all 12 exact inner/outer rational intervals, source pixel canvas and axes (`x/1024`, `y/1536`), mannequin pose-only precedence, natural complete shoulder/sleeve side contours, bottom-only connected garment contact, authored upper construction and protected neckline. The projection contains canonical `projectionJSON`, `projectionJSONSHA`, `text`, `textSHA`, `scopeHash`, and `scopeVersion:"complete-source-readable-position.v1"`. It enters the native multipart prompt alongside unchanged machine metrics. Parsing and pre-dispatch recomputation reject text/axis/numeric/version/hash/role/garment divergence; caller prose overrides are rejected. This is generation guidance, not output acceptance. K028 upper changes additionally must equal the existing authored source document's `constructionCues`; other leaves remain protected. External evidence-only projection-spec hashes are not claimed as the native canonical scope hash, whose bytes and schema are explicit in preview.

## Sparse local alpha

`modifyPortrait` and `seoul-avatar modify request.json` accept optional `sparseMask` for `operation:"local-alpha"`, `alpha:0`, with no `region`. Existing rectangle requests remain supported. This is offline native PNG correction: no provider calls or regeneration. The standalone package has no MCP surface.

`sparseMask` is `{version:1,format,path,sha256,pixelListSHA,approvalPath,approvalSHA,ownershipProofPath,ownershipProofSHA}`. Format is `canonical-pixel-list-json` (strictly increasing row-major integer indices, canonical JSON with optional final newline) or `binary-png` (same RGBA canvas; alpha 0 selects, alpha 255 protects; partial alpha rejects). Byte SHAs bind every supplied file; `pixelListSHA` hashes UTF-8 `JSON.stringify(indices)` without a newline. Both formats must select exactly the independently approved pixels, not a subset or bounding rectangle.

The pinned approval document uses `portrait-sparse-alpha-approval.v1`, `version:1`, `approved:true`, `sourceSHA`, `canvas:[width,height]`, `packageVersion`, `inputSnapshotSHA`, `ownershipProofSHA`, `approvedSelectedPixels`, and `pixelListSHA`. Generic ownership proof uses `portrait-local-owner-proof.v1`, `sourceSHA`, `ownerAuthorized:true`, `scope:"selected-background-alpha-only"`, and the same `pixelListSHA`. Operators must independently supply approved pins; rehashing a candidate assertion does not establish semantic ownership. Existing bounded K033 ownership evidence additionally requires immutable component evidence via approval `componentMaskPath`/`componentMaskSHA`, exact 4432-pixel four-connected list and decoded source binding. `packageRoot` supports optional repository-relative `manifestPath` for caller-owned packages.

Source and immutable inputs remain unchanged. Both output and receipt must be distinct new paths. Collisions and aliases abort without deleting existing files. Receipt records mask/approval/ownership hashes, canvas, selected count, output SHA and decoded proof of zero RGB differences globally, zero unselected RGBA differences and zero selected nonzero alpha. The result remains unreviewed; placement and whole-portrait acceptance are independent.

Trust is selected outside the candidate request. API calls are `prepareCompleteReplacement(input, trust)` and `completeSourceReplacement(input, trust)`, with operator-owned `trust:{registryBytes,registrySHA,readEvidence}`. CLI adds `--trust-registry operator-registry.json OPERATOR_APPROVED_SHA256` separately from request JSON. Candidate registry fields are rejected. The operator must select the digest independently; accepting a digest supplied by the candidate would defeat this boundary. The registry follows the external-pin/immutable-reader pattern: hashes prove bytes, while approval scope comes from the operator's pinned entry, not an `authored` label, source string, URL, or recomputed candidate hash.

`complete-source-trusted-registry.v1` binds recipient/look, policy/rule/authority/owner-decision/raw-reference SHAs, reference version, exact criterion scopes, and closed approved document contents. The separately operator-selected `private-k028-input-trust-registry.v1` format is also accepted: its six artifact pins, raw owner-event hashes, source SHA and criterion scopes are verified against exact bytes and the closed `operator-owner-input-authority.v2` schema. No private transcript or registry is embedded in the npm package. Input approval conveys no output or publication acceptance and requires no future image proof before HTTP.

Replacement composition must use `position-reference.v2`, explicit referenceVersion/referenceSHA/ruleSHA, `unit:"px"`, all 12 exact rational latest16 position metrics, matching guide bindings, and `wholeFramePassAuthority:false`. Old semantic-frame numeric bands and reference mismatches reject before dispatch. Source v2 position authority, exact16 rows, metric authority/status, source manifest/observation hashes and raw adapter equality are checked; cut FAIL and background UNVERIFIED remain separate candidate criteria. No one-pixel margin is inferred.

With position-v2, the legacy `framing-only` transport role must explicitly declare exactly `allowedProperties:["pose"]`. It supplies coordinated orientation/body pose only, not numeric head size, crown/eye/chin placement or framing authority. The provisional mannequin remains provisional; its PNG and diagnostic metadata are not requalified. Composition requires `referencePrecedence` equal to: `Latest approved position-reference.v2 exact rational metrics exclusively own numeric head size, crown, eye, chin and framing positions. The mannequin reference supplies coordinated orientation and body pose only; its image and diagnostic metadata supply no numeric positions or framing authority.` The same precedence is transmitted in the complete-source instruction. Missing scope, duplicated pose properties, or `["pose","frame"]` rejects before provider dispatch.

Offline semantic contact proof additionally requires an externally pinned `semanticEvidence` registry entry binding the exact imageSHA, policySHA, assessorEvidenceSHA, and `bottom-garment-contact` scope. Rehashing a self-authored garment seed cannot grant authority. Closed schemas reject extra fields. Byte integrity and approved assessor identity/scope still do not mechanically prove assessor truth; the component check measures connectivity only, and natural garment semantics require independent observation.

`prepareCompleteReplacement(input, trust)` validates without provider calls. `completeSourceReplacement(input, trust)` generates a distinct COMPLETE whole-canvas unreviewed candidate through the native generation stack. It does not use a mask, resize/stretch the subject, or copy any original pixels. The raw provider PNG remains in `<output>.native` even when padding validation fails. This operation is separate from protected local/masked editing, including the historical `modifyPortrait` operation named `new-source`.

Supply exact `lookBytes` and `originalLookBytes` (CLI: file paths), `sourcePath`, `sourceSHA`, unique `activatedSlots` such as `["appearance.outfit.upper"]`, `packageRoot`, optional relative `manifestPath`, `catalogPath` for templates, `composition`, and ordered `references` containing technique then framing descriptors in the same shape as `previewPortrait`. `expected` must exactly contain `sourceSHA`, `inputSnapshotSHA`, `originalLookSHA`, `packageVersion`, and `packageSHA` (SHA of the exact manifest bytes). All unactivated authored leaves, identity and face mode must match the original. Template selection uses the catalog and uploads the selected package-bound face bytes with `face-base-only`; UNIQUE stays UNIQUE and uses its authored face slots. Style and framing upload only their verified package bytes with separate roles; donor hair/clothing cannot supply authored appearance.

`identityReferencePolicy` is mandatory and must be `authored-only`: the current owner contract excludes previous portraits as generation inputs. Source bytes are read for lineage validation only and are never uploaded. The selected system template and explicit authored slots provide identity inputs, without proving exact visual identity. A prior recipient image would require an explicit named owner exception and a contract revision; a supported native reference role or source SHA is not permission. The existing selector validates template eligibility and reference bytes; it does not replace the immutable look's explicit face leaves. `canonicalRoot`, `lineageEligibilityPath` and `lineageEligibilitySha256` expose the selector's existing non-East-Asian lineage contract.

Boundary preflight requires exact `boundaryPolicyBytes`/`boundaryPolicySHA`, `ruleBytes`/`ruleSHA`, and `authorityBytes`/`authoritySHA` (CLI byte fields are file paths). Missing or stale documents reject before HTTP. Free-standing `padding` is rejected. The caller's sourced authority document must contain an `authored` or `source-approved` entry with `scope: "complete-source-boundary"`, a nonempty `source`, and the exact policy unit/canvas/referenceVersion/positionBounds/boundary/bottomContact set. This verifies supplied source bindings; it does not certify who authored external documents or invent owner approval.

The policy schema is `portrait-complete-source-boundary.v1`: `unit:"px"`, `canvas:{width,height}`, `referenceVersion`, nonempty `provenance`, `authority:{documentSHA,pointer}`, `positionBounds:{ruleSHA,pointer,scope:"position-v2"}`, `boundary:{mode,padding,evidenceRequired:true}`, and `bottomContact:{required:true,row:height-1,subject:"connected-torso-garment"}`. The position pointer resolves in exact schemaVersion 2 rule bytes with matching referenceVersion; it supplies position scope, never fabricated margins from crown/eye bounds. `authored-numeric-bands` requires explicitly sourced `padding:{left,right,top,bottom}` safe finite nonnegative integers, side sum below width and top below height. Required bottom garment contact rejects any positive bottom band. `observable-no-cut` requires `padding:null`; no numeric boundary PASS is inferred, and semantic evidence remains required. The package canvas descriptor alone cannot authorize either policy.

The output scanner judges alpha-zero only in authorized top/side bands. Bottom contact remains `UNVERIFIED` and blocked without candidate-bound semantic garment evidence. For offline review, `validateReplacementPadding(pngBytes, policy, {bytes,sha256}, policySHA)` accepts exact observation bytes containing `imageSHA`, `policySHA`, `subject:"connected-torso-garment"`, sourced `status:"authored"|"source-approved"`, nonempty `source`, and an integer `seed:[x,y]` identifying the observed garment above the bottom. A four-neighbor visible-alpha traversal from that semantic seed measures whether the component reaches the required bottom row. A floating component or disconnected bottom dot fails. This is only a component-contact check under the supplied semantic identification, not proof from alpha alone that the component is clothing. Natural uncut contour, internal cutoffs, background residue, subject stretching and identity remain independent checks; the overall boundary remains blocked pending them. Generation never supplies its own semantic observation or grants contact PASS.

Outputs and all sidecars must be new paths. `output` is the candidate PNG path; `connectionConfig` is explicit caller configuration. `<output>.replacement.json` records immutable look/package/source/policy/rule/authority bindings and unreviewed status. Raw whole-canvas PNGs remain available on output failure. No whole-rule PASS, publication, owner/review write, or automatic retry follows generation. Production publication requires genuine 100-PASS evidence from the independent gate.
